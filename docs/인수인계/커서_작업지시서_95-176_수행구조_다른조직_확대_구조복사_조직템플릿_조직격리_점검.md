# 커서 작업지시서 95-176 — 수행 구조를 다른 조직 사업에도 쓰게 하기 (구조 복사 화면 · 조직 템플릿 · 조직 격리 점검)

작성일: 2026-11-12
선행: 95-175 A·B·C 운영 반영 완료(v95-175). 테스트 필수(렌더된 HTML·실제 클릭 검증). `git add .` 금지, 운영·개발 데이터는 코드로 고치지 않는다. 전체 게이트 실패가 8건에서 늘면 known_failures에 넣지 말고 원인 커밋을 찾는다. 푸시·배포·운영 DB 접근 금지(배포는 사용자가 직접). 보고는 커밋 diff 기준. 시드·예시 데이터 금지(템플릿 포함).

## 1. 배경
수행 구조(단계 › 하부 업무 › 작업 계획)는 이미 사업마다 따로 만드는 구조라 모든 조직의 사업에 쓸 수 있다. 다만 지금은 사업마다 단계부터 직접 입력해야 하고, 「다른 사업에서 구조 복사」는 `POST /projects/:id/structure/copy`(`StructureCopy`)만 있고 **화면이 없다**. 사업이 많은 조직(미디어사업팀 등)이 쓰려면 **복사 화면 + 조직 템플릿**이 필요하다. 또 구현 코드 확인에서 `StructureCopy`가 원본 사업의 **조직·열람 권한을 확인하지 않는 점**이 보여(`h.repo.Get(src)`로 존재만 확인) 먼저 막아야 한다.

## 2. 0단계 (코드 수정 금지, 보고 후 확인 대기)
1. `StructureCopy` / `CopyStructure`의 현재 동작 확인: 원본 사업 접근 검사, 복사 범위(단계·하부 업무·가중치·`track_mode`만인지, 계획·사이트·날짜·상태가 따라가는지), 같은 이름 건너뜀, 반복 쿼리(`listPackages`가 단계 루프 안에서 매번 호출됨).
2. 사업 상세 「수행 구조」 구역(`project/_phases.html`)의 현재 빈 상태·입력 폼 위치, 기본 단계 제안(95-120P 코드 그룹)과의 관계.
3. 하부 업무 `track_mode='phase'`(「수량만」)가 화면에서 어떻게 보이고 어떻게 진행률에 반영되는지, **사이트가 없는 사업**에서 작업 계획 화면이 어떻게 보이는지.
4. 사업 후보 목록 규칙(95-87/95-113/95-144B: 자기 조직·유관 부서·타 조직 보기)과 `canDesignProjectWork`/`canManagePlans`/`CanRegisterWorkOnProject` 재확인.
5. 조직(org) 격리 현황: 새 쿼리·핸들러가 모두 org 조건을 쓰는지(92 정적 점검 대상).
6. 마이그레이션 번호(111 사용 중 → 이번은 112 예상)와 템플릿 저장에 재사용할 기존 패턴.

## 3. A. 구조 복사 화면 + 접근 검사 (긴급 보안 정리 포함)

### 3-1. 서버
- `StructureCopy`에서 **원본 사업을 현재 사용자가 볼 수 있는지** 검사한다(95-113 사업 후보 규칙: 같은 조직 + 유관 부서만. 기본안: **같은 조직 사업만**). 권한 없음·타 조직·존재하지 않음은 **같은 문구의 404/거절**(존재 여부를 알려 주지 않는다).
- 원본에 구조가 없으면 「복사할 구조가 없습니다」(오류 화면 아님).
- 복사 범위: **단계·하부 업무(이름, `track_mode`, `weight`, 순서)만**. 작업 계획·사이트·날짜·상태·완료·연결 작업은 복사하지 않고, 복사된 단계·하부 업무는 모두 「예정」으로 시작한다. 같은 이름 건너뜀은 유지하되 **건너뛴 개수와 추가된 개수**를 응답에 담는다.
- 구현은 한 트랜잭션: 중간 실패 시 일부만 복사되지 않는다. 반복 쿼리(`listPackages`)는 루프 밖으로 뺀다. 단계 순서는 원본 `seq` 순으로 복사한다(현재 정렬이 복사 뒤에 있어 의미가 없다).
- 감사 로그(`audit`)에 원본 사업과 추가 건수를 남긴다.

### 3-2. 화면 (수행 구조 구역)
- 구조가 없을 때(「설정 안 함」)와 있을 때 모두 구역 안에 **「다른 사업에서 구조 복사」** 입력을 둔다(권한: `canDesignProjectWork`만 보임).
- 원본 사업 선택: 사업명·번호로 검색(95-113 피커 재사용), **구조가 있는 사업만** 후보, 후보에 「단계 N · 하부 업무 M」 표기.
- **복사 전 미리보기**: 추가될 단계·하부 업무 목록과 「같은 이름이라 건너뜀」 표시를 보여 주고 확인해야 저장한다(95-120P 「저장 전 미리보기」와 같은 흐름·스타일).
- 결과 안내: 「단계 N개, 하부 업무 M개를 복사했습니다. 작업 계획과 사이트는 복사되지 않습니다.」
- 좁은 화면(390px)에서 가로 스크롤 없음.

### 3-3. 테스트
- 같은 조직 사업 복사 성공(단계·하부 업무·가중치·`track_mode`·순서), 계획·사이트·상태·날짜 미복사, 같은 이름 건너뜀 개수, 원본 구조 없음, 자기 자신 선택, 한 트랜잭션 롤백(중간 실패 주입).
- **조직 격리**: 타 조직 사업 ID를 직접 넣어도 복사 불가(404, 존재 노출 없음). 일반 직원·읽기 전용·C-Level·옵저버는 버튼이 없고 POST도 거절.
- 쿼리 수 상한(단계 20·하부 업무 100 복사에서 상수 개).
- 실제 브라우저: 구조가 없는 사업 → 복사 입력 → 미리보기 → 저장 → 트리가 생김(임시 DB), 390/820/1440.

## 4. B. 조직 구조 템플릿 (저장·적용)

### 4-1. 데이터 (마이그레이션 112, `.down.sql`, 기존 행 불변, TEXT 키 관례)
```sql
CREATE TABLE structure_templates (
  template_id TEXT PRIMARY KEY,
  org_id      TEXT NOT NULL,          -- 조직 전용
  name        TEXT NOT NULL,          -- 예: 구축 표준 (조직이 직접 이름 지음)
  project_kind TEXT NOT NULL DEFAULT '',  -- 선택: 구축|개발|공사|유지보수|기타 (제안 정렬용)
  note        TEXT NOT NULL DEFAULT '',
  is_active   INTEGER NOT NULL DEFAULT 1,
  created_by  TEXT NOT NULL DEFAULT '',
  created_at  TEXT NOT NULL, updated_at TEXT NOT NULL,
  UNIQUE(org_id, name)
);
CREATE TABLE structure_template_phases (
  tphase_id TEXT PRIMARY KEY, template_id TEXT NOT NULL, seq INTEGER NOT NULL DEFAULT 0, name TEXT NOT NULL
);
CREATE TABLE structure_template_packages (
  tpackage_id TEXT PRIMARY KEY, tphase_id TEXT NOT NULL, seq INTEGER NOT NULL DEFAULT 0,
  name TEXT NOT NULL, track_mode TEXT NOT NULL DEFAULT 'site', weight REAL NOT NULL DEFAULT 1
);
```
- **계획·사이트·날짜·상태·실적은 템플릿에 저장하지 않는다.** 시드 템플릿 없음(조직이 직접 만든다).

### 4-2. 기능
- **저장**: 구조가 있는 사업의 「수행 구조」 구역에서 「이 구조를 템플릿으로 저장」(이름 필수, 사업 유형 선택). 같은 이름이 있으면 거절(덮어쓰기 아님). 권한: 그 조직의 조직관리자·비전관리자.
- **적용**: 구조가 **비어 있는** 사업에서 「템플릿 적용」(목록: 그 조직 템플릿, 사업 유형이 같은 것을 위로). **미리보기 → 저장**(3-2와 같은 흐름). 이미 구조가 있는 사업에는 「구조 복사」와 같은 규칙(같은 이름 건너뜀)으로 **추가 적용**만 허용한다. 권한: `canDesignProjectWork`.
- **관리**: 조직관리자가 템플릿 이름·단계·하부 업무를 보고 이름 수정·비활성화할 수 있는 간단한 목록(사업 상세 외 별도 화면은 만들지 않아도 된다 — 구조 구역 안 「템플릿 관리」 접힘 영역으로 충분하다. 규모가 크면 보고서에 남기고 분리). 삭제 금지, 비활성만(이미 적용된 사업은 영향 없음).
- 기본 단계 제안(95-120P 코드 그룹)과의 우선순위: **템플릿이 있으면 템플릿을 먼저 보여 주고**, 없으면 지금처럼 기본 제안을 보여 준다.
- 템플릿은 **조직 단위**다. 다른 조직의 템플릿은 보이지 않고 적용할 수 없다(비전관리자는 열람·관리 가능). 전사 공용 템플릿은 이번 범위 밖(질문 1).

### 4-3. 테스트
- 저장→적용 왕복(단계·하부 업무·`track_mode`·`weight`·순서 일치), 계획·사이트가 템플릿에 들어가지 않음, 이름 중복 거부, 비활성화 후 목록 제외·기존 적용 사업 불변, 이미 구조가 있는 사업에 추가 적용(같은 이름 건너뜀).
- **조직 격리**: 타 조직 템플릿 ID 직접 적용 → 404. 일반 직원은 저장·관리 불가, 적용은 `canDesignProjectWork`만.
- 마이그레이션 up/down(빈·기존 DB), 기존 사업 화면 불변(구조 없는 사업 회귀).
- 브라우저: 사업 A 구조 → 템플릿 저장 → 다른 사업 B에서 템플릿 적용(미리보기→저장) → 트리 확인, 390/820/1440.

## 5. C. 사이트가 없는 사업(수량만 하부 업무) 확인과 안내
- 0단계 3번 결과를 근거로: 사이트가 없는 사업에서 작업 계획을 만들려 할 때 「이 사업에는 사이트가 없습니다. 사이트·진행에서 사이트를 먼저 등록하거나, 하부 업무를 「수량만」으로 만드세요」 같은 **안내 문구**를 보여 준다(오류 화면 아님, 입력을 막지는 않는다).
- 「수량만」 하부 업무의 진행률 반영 방식이 이미 있으면 그 **동작을 보고서에 정확히 적고**, 화면에 설명 한 줄(무엇을 기준으로 진행률이 계산되는지)을 둔다. 없거나 불완전하면 **구현하지 말고** 보고서에 부족한 점과 제안만 적는다(별도 지시서로 분리).

## 6. D. 다른 조직 사업 회귀 점검 (임시 DB, 코드 변경 없이 시험만 추가)
- 미디어사업팀·SI사업팀 두 조직의 사업으로 다음을 시험한다: 구조 만들기, 작업 계획, 작업 등록의 수행 단계 패널, 진행 보고 문장, 주간 업무 보고서·업무 회의 문장, 사업 통합(95-168), 대시보드 열.
- **조직 격리 행렬**: 한 조직 사용자가 다른 조직 사업·계획·템플릿에 접근하는 모든 경로(GET/POST)가 404/403인지, 문장·집계 API가 다른 조직 숫자를 섞지 않는지.
- 사업 유형별 기본 단계(구축·개발·공사), 유지보수의 「사용 안 함」, 기타·미분류의 「설정 안 함」이 조직과 무관하게 같은지.
- 새로 발견한 문제는 이번 지시서에서 고치지 말고 **보고서에 목록으로**(안전한 한두 줄 수정은 고치고 별도 커밋).

## 7. 하지 않는 것
