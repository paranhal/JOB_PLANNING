### A-3. 작업 계획 CRUD
- 하부 업무 줄의 「+ 작업 계획」 → 창(시안 참고): 계획 이름(필수, 100자, 하부 업무 안 중복 금지), **사이트 검색 선택**(단일·다중), 진행 기준(사이트/수량)·수량 단위, 착수 예정일(선택), **완료 예정일**(선택, `plan_start ≤ plan_end`), 완료 후 계획(선택, 300자).
- **결정(질문 7)**: 시·군 필터만으로 고르지 않는다. **검색 선택이 기본**이고 시도/시군구는 보조 필터다. 권역·차수 같은 묶음도 검색 선택으로 만든다.
- **수량(질문 2)**: 선택한 사이트 행마다 수량 칸(`target_qty`), 「선택한 사이트에 같은 수량 적용」 버튼. `progress_basis='qty'`는 제외 아닌 모든 사이트의 수량이 입력된 계획에서만 저장(미입력 N곳 오류 문구). 인정 규칙은 설계서 §3-3a(완료=목표 전체, 진행·보류=`done_qty`, 예정=0). 완료 처리 시 `done_qty`를 `target_qty`로 맞춘다.
- **후보 = 그 사업의 사업 사이트 풀**(`project_sites`, 제외 상태 제외, 사업 조직 기준). 규격은 95-165 `target_picker` + 95-169 검색(1글자 부분 일치·초성·시도/시군구 필터·결과 전체 선택·선택 유지·Enter 제출 방지, 100건 단위). 800곳에서 느리지 않게 서버 검색.
- 사이트를 담으면 **같은 트랜잭션**에서 ① 해당 단위 업무 범위(`phase_sites`)에 없으면 추가 ② 하부 업무 `package_sites`(없으면 생성, `plan_id` 지정). 이미 다른 계획에 속한 사이트는 선택 불가(칩 「○○ 계획」)이고 「이 계획으로 옮기기」로만 가져온다(**완료 사이트는 이동 불가**, 이력 보존).
- 수정: 이름·예정일·완료 후 계획, 사이트 추가·제외(제외는 `excluded` + 사유 필수, 완료 사이트 제외는 확인창 「완료 이력은 보존되며 진행률 분모·분자에서 빠집니다」), 순서(↑↓).
- 삭제: 실적(완료·진행 사이트)·연결 작업이 있으면 **삭제 금지, 비활성만**. 없으면 삭제하고 사이트는 「계획 미배정」으로 돌아간다.
- **완료 확정/보류/되돌리기**: `status` 변경은 **버튼으로만**(자동 변경 금지). 완료 확정은 모든 사이트가 완료(또는 제외)일 때만 활성, 되돌리기 허용(감사 로그).
- 모든 변경은 `data_change_logs`(누가·언제·무엇·사유).

### A-4. 작업 등록 「수행 단계」 패널 (95-120 §3-E 개편)
95-120의 「단위 업무 → 하부 업무 콤보」를 **트리 선택 패널**로 바꾼다(시안 ② 참고).
- 사업(95-113 피커)을 고르면 **구조가 있는 사업에서만** 패널이 나타난다. 구조 없는 사업·사업 없음은 **현재 폼과 100% 같다**(회귀).
- 한 줄 = `단위 업무 › 하부 업무 › 계획`, 줄마다 표시 상태 칩(진행 중/예정), 진행률(`4/50 (8%)`), 완료 예정일, 이어서 할 사이트 수. 완료된 계획은 기본 숨김(「완료된 계획 보기」), 보류 계획은 선택 불가 칩, 마지막 줄 「단계 없이 등록(미분류로 집계)」. `track_mode='phase'` 하부 업무는 선택만 가능(사이트 패널 없음).
- **선택은 선택 사항**이며 비워도 저장된다. 사업을 바꾸면 선택 초기화. 선택하면 `work_tasks.package_id`·`plan_id` 저장.
- 계획을 고르면 **작업명을 「계획명 하부업무명」으로 자동 제안**한다(예: 홍천 지역 환경조사). 사용자가 직접 고친 뒤에는 덮어쓰지 않는다.
- 사이트 패널(오늘 처리할 사이트)은 **B 단계**에서 연결한다(A에서는 계획 선택·작업명·저장까지).
- 사업 상세 「이 사업으로 업무 등록」(95-174)으로 들어오면 그 사업이 선택되고 이 패널이 바로 열려야 한다.
- 95-157 콤보 닫힘 규칙, 95-132B(모달 390px 가로 넘침 없음) 회귀 주의. 업무 수정 화면에서는 연결 변경 가능, 조치 화면은 읽기 전용 표시.

### A-5. 표시 상태·진행률 함수 (서버 한 곳, 신규 식 금지)
`repository`에 `EffectiveStatus(level)`와 `StructureProgress(projectID)`를 둔다(핸들러에 계산 로직 금지).
- 표시 상태: 저장 `done`→완료, `hold`→보류, 실적(연결 작업 또는 사이트 이벤트·체크) 있으면 진행 중, 없으면 예정, 모든 사이트 완료인데 `auto`이면 **완료 후보**. 단위 업무는 95-120P 저장 상태를 쓰되 저장이 예정이고 하위 실적이 있으면 진행 중으로 표시.
- 진행률: 계획 = 완료 ÷ (사이트 − 제외) **+ 수량 달성률(인정 수량 ÷ (대상 수량 − 제외 수량))을 같이 반환**(표시는 항상 둘 다, 기준은 `progress_basis`), 하부 업무·단위 업무·사업은 항상 사이트 기준, 하부 업무 = 계획 미배정 포함 전체 사이트 기준, 단위 업무·사업 = `weight` 가중평균(`track_mode='phase'`·`none` 제외, 「반영 N/M」). 분모 0 → `—`. **95-119 달성률과 같은 값**이 나오는 합계 일치 테스트.
- 현재 단계 = 순서상 첫 완료 아닌 단위 업무(그 안의 진행 중 하부 업무·계획이 「현재 위치」).
- 쿼리는 사업 ID·계획 ID **일괄 GROUP BY**(N+1 금지, 쿼리 수 상한 테스트).

### A-6. 템플릿·사업 통합(95-168)·권한
- 95-120 §3-C 템플릿은 **단위 업무·하부 업무만** 복사한다(작업 계획·사이트는 복사하지 않음 — 사업마다 다름). 「다른 사업에서 구조 복사」도 같다.
- **사업 통합(95-168)**: 계획 이름 같으면 1개로 합치고(사이트는 중복 제거, `plan_id` 갱신), 다르면 이어 붙임. `work_tasks.plan_id` 갱신, 되돌리기 스냅샷에 `package_plans` 포함(95-120 §3-F 확장).
