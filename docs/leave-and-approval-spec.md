## 1. 양식 분석 — 「근태허가원」 (HWPX 구조 확인 완료)

> 개인 정보 값(성명·연락처 등)은 옮기지 않고 **구조만** 기록한다. 업로드된 양식에는 **샘플 작성자의 실제 정보가 들어 있으므로** 템플릿 제작 시 반드시 제거해야 한다(§6.3).

### 1.1 문서 구조
- 파일은 HWPX, 본문은 **표 1개(8행 × 12열)** 로 구성. 용지 설정은 A4 크기에 가로 방향 지정이고, 화면에서는 **A4 위쪽 절반에 A5(210×148) 양식이 놓이고 아래에 절취선**이 있는 모양이다.
- 양식 번호 `QEP-430-04(Rev.0)`, 회사명 (주)비젼아이티와 로고 이미지(1개), 규격 `A5(210x148)`가 맨 아랫줄에 고정.

| 행 | 내용 |
|----|------|
| 0~2행 | **왼쪽 큰 칸**: 제목 「근태허가원」 + 문서번호 + 작성일 + 작성자. **오른쪽 결재란**(세로 「결재」 글자 + 작성/검토/승인 3열). 결재란 1행=서명 칸(높이 큼), 2행=결재일 칸(`월/일` 형식) |
| 3행 | **구분**: 한 줄 텍스트 `☑연차 ☐반차 ☐월차 ☐휴가 ☐조퇴 ☐외출 ☐결근 ☐기타(      )` |
| 4행 | **기간**: 세 줄 — ① 시간 지정 ② 일 단위 ③ 대체근무 (각 줄 앞에 ☐/☑) |
| 5행 | **사유** (가운데 정렬 한 줄) |
| 6행 | **행선지 · 연락처 · 업무대행자** (제목칸 + 값칸 3쌍) |
| 7행 | 양식번호 · (주)비젼아이티(로고) · 규격 |

### 1.2 시스템 동작에 미치는 결론
- **결재란은 3칸(작성/검토/승인)** 이고, 검토 칸에는 **이미 사선이 그려져 있다.** 검토 단계가 없다는 운영과 양식이 일치한다.
- 구분은 **체크박스 문자(☑/☐)** 로 표현된다 → 각 체크 문자를 자리표시자로 바꾸는 방식이 가장 단순하다.
- **반차에는 오전/오후 구분이 양식에 없고** 기간 ①줄의 **시각 범위**(`시 ~ 시 (N시간)`)로 표현된다. 앱에서는 오전/오후를 선택하게 하고 출력 시 시각으로 환산한다. **1일 = 8시간이므로 반차 = 4시간**, 시각 기본값은 오전 09:00~13:00 / 오후 14:00~18:00이며 관리 설정에서 바꿀 수 있다(Q-01).
- 일 단위 줄은 `YYYY년 MM월 DD일 ~ MM월 DD일 (N 일간)` 형태이므로 종료일은 연도 없이 `월 일`만 표기한다.
- **업무대행자는 필수가 아니다.** 비워서 제출할 수 있고 출력 양식의 해당 칸은 공백이다.

## 2. 화면 흐름과 결재선

### 2.1 신청 화면 (모바일 우선, 한 화면에 끝나게)

```
[휴가 신청]
 1 구분 선택            (칩: 연차 · 반차 · 월차 · 휴가 · 조퇴 · 외출 · 결근 · 기타)
 2 기간                 구분에 맞는 입력만 표시
     연차/월차/휴가/결근 → 날짜 범위 선택 → "N일간" 자동 계산
     반차               → 날짜 + 오전/오후 → 시각·시간 자동 표기
     조퇴/외출          → 날짜 + 시작~종료 시각 → "N시간" 자동 계산
     대체근무(토글)     → 날짜 + 기근무/근무예정
 3 사유 · 행선지 · 연락처(프로필 기본값) · 업무대행자(선택)
   [팀장 본인이고 정책 C가 켜져 있으면] 대리 결재자(필수)  ← 휴가 기간 동안 팀원 신청을 대신 승인할 사람
 4 잔여 연차 미리보기   "신청 후 잔여 12.5일" (부족하면 차단)
 5 결재선 미리보기      일반 직원: 작성(나) → 승인(팀장 OOO)
                        팀장 본인: 작성(나) → 승인(나) · "팀장 본인 신청은 자동 승인됩니다" 안내
 [제출]
```
- 작성자·작성일·문서번호는 제출 시 서버가 생성한다.
- 일수·시간 계산은 **서버 함수 하나**만 사용하고 화면 미리보기도 같은 API를 호출한다(주말·공휴일 제외, §7.2).
- 같은 사용자의 활성 신청과 날짜가 **겹치면 제출 불가**.
- 취소: 상신 전 삭제 / 상신 후 **회수** / 승인 후 **취소 결재**(또는 관리자 처리) → 잔여 복원 + `staff_leaves` 되돌림 + (정책 C로 만들어진) 대리 결재 지정 종료.
- 결재자(팀장) 화면 모바일: 문서 요약 → 결재선 → 신청자 **잔여 연차 · 같은 기간 팀 휴가 현황** → 의견 → 하단 고정 `승인 / 반려`. 대리인이 볼 때는 `OOO 팀장 대리` 라벨.

### 2.2 결재선 생성 규칙

| 기안자 | 결재선 |
|--------|--------|
| 일반 직원 | 1 작성(기안자, 상신 시 자동 처리) → 2 **승인(소속 조직 팀장)** |
| **팀장 본인** | 1 작성(본인) → 2 **승인(본인)** — **자기 결재** (§2.3) |
| 소속 조직에 팀장이 지정돼 있지 않음 | **상신 불가**, 「팀장이 지정되지 않았습니다. 관리자에게 문의하세요」 표시 (관리자는 `is_org_head` 지정 필요) |

- **견적서도 같은 규칙**이다(마지막 = 팀장, **팀장이 작성자이면 자기 결재**, 금액 예외 없음).
- 검토 단계는 만들지 않는다. 결재 엔진은 단계가 늘어도 동작하도록 설계하되 **현재 템플릿에는 2단계만** 둔다.

### 2.3 자기 결재(팀장 본인 신청) 처리 방식 — 휴가·견적 공통

- 팀장이 상신하면 **같은 처리에서 즉시 승인**한다(승인 버튼을 한 번 더 누르게 하지 않는다). 상태는 곧바로 `approved`, 이벤트는 `submit` 다음 `self_approve`(행위자=본인) 순으로 남긴다.
- 자기 결재여도 **연차 잔여 검증, 날짜 겹침 검증, 잔여 소진, `staff_leaves` 반영은 모두 동일하게** 수행한다. 하나라도 실패하면 **전체 롤백**.
- 출력 양식의 **작성란과 승인란에 본인 서명이 모두** 들어가고 결재일은 같은 날짜다. 검토란은 사선 그대로.
- 감사 장치: ① `self_approve` 이벤트로 이력 보존 ② 관리자 화면에 **자기 결재 목록** 필터 ③ 관리 > 결재 설정에서 **관리자 알림 여부를 체크박스로 선택**.
- 팀장이 신청한 휴가를 **취소**할 때도 같은 규칙(본인이 취소 결재 처리).
- 허용 여부는 관리 > 결재 설정의 체크박스(`휴가 신청은 팀장 본인이 승인한다`, `견적서는 팀장 본인이 승인한다`)로 문서 종류별 제어한다(`approval_policies`). 끄면 팀장 본인 신청은 차단되고 별도 승인자 지정 규칙이 필요하다.
- **일반 직원은 자기 자신을 승인자로 둘 수 없다.** 예외는 오직 「승인자 규칙이 `org_head`로 해석된 결과가 기안자 본인」인 경우다.

### 2.4 팀장이 자리에 없을 때 — 대리 결재 (체크박스 선택형)

방식은 **관리 > 결재 설정**에서 체크박스로 고른다(복수 선택). 정책 정의, 승인자 결정 규칙, 테스트는 **`ia-and-approval-plan.md` §2.5**에 있다. 휴가 쪽 연동은 다음과 같다.
- **정책 C**(팀장이 휴가를 신청할 때 대리 결재자를 함께 지정)가 켜져 있으면, 팀장 본인의 휴가 신청서에만 「대리 결재자」 입력란이 나타나고 **필수**다. 대리 결재자는 신청서의 「업무대행자」와 **별개 항목**이다(업무대행자는 선택, 대리 결재자는 정책 C일 때 필수).
- 팀장 휴가가 최종 승인되면 **휴가 기간(시작일~종료일, 달력 기준)** 의 대리 결재 지정이 자동 생성(`source='leave'`)되고, 휴가를 취소·반려·회수하면 만들어지지 않거나 즉시 종료된다.
- 대리인이 처리한 팀원 휴가는 이력에 `acted_by`=대리인, `act_mode='delegate'`로 남고 출력물 승인란은 **실제 처리자 서명 + 「(대결)」 표기**를 가정한다(Q-04).
- 대리인이 **자기 자신의 휴가**를 신청한 경우에는 대리인이 그 문서를 승인할 수 없다(자기 결재 예외는 팀장 본인뿐). 팀장 복귀 또는 정책 D(관리자 비상 승인)로 처리된다.

## 3. 구분(유형) 정책 — 확정안

모든 유형이 **연차에서 차감**된다. 결근·기타만 차감하지 않는다. **1일 = 8시간(480분)**.

| type_key | 라벨 | 입력 방식 | 차감 | 기존 `staff_leaves` 반영 |
|----------|------|-----------|------|--------------------------|
| `annual` | 연차 | 일 | 1일/영업일 | 반영 (`annual`) |
| `half` | 반차 | 시간(오전/오후 선택) | 4시간(240분) | 반영 (`half_am`/`half_pm`) |
| `monthly` | 월차 | 일 | 1일/영업일 | 반영 (`annual`로 저장, 표시 라벨은 월차) |
| `vacation` | 휴가 | 일 | 1일/영업일 | 반영 (`annual`) |
| `early_leave` | 조퇴 | 시간 | 해당 시간(분) | 기록만(1차) |
| `outing` | 외출 | 시간 | 해당 시간(분) | 기록만(1차) |
| `absence` | 결근 | 일 | 차감 없음 | 반영 |
| `other` | 기타(직접입력) | 일/시간 | 차감 없음 | 기록만 |
| 대체근무 | 기간 방식 ③ | 일 | 차감 없음 | 기록만 |

- 유형 설정은 `leave_types` 테이블에 두어 **코드 수정 없이 관리자가 조정**한다.
- **월차는 별도 잔액이 아니다.** 1년 미만 직원의 월 발생분과 15일 연차는 **하나의 원장 풀**이고, 월차/연차/휴가는 신청 라벨만 다르다(FIFO로 만료 임박분부터 차감).
- 조퇴·외출 차감은 **분 단위**로 정확히 계산해 저장하고 화면에는 일(소수) 또는 시간으로 표시한다(Q-07). 시간 차감이 근로자에게 불리하게 작용할 수 있는 영역이라 **회사 규정·노무 확인**을 권한다(법률 자문 아님).
- `staff_leaves`는 `annual / half_am / half_pm` 3종 · 일 단위만 지원하므로 1차는 일·반일 건만 반영하고, 시간 단위(조퇴·외출)는 일정 제외 없이 기록·표시만 한다. 시간 단위 일정 제외는 업무 배치 로직 변경이 필요한 **별도 과제**.
- 승인 시 신청서의 **영업일마다** `staff_leaves` 행 생성(`leave_request_days`와 연결, `source_request_id` 기록). 관리자 직접 입력은 유지하되 출처로 구분.

## 4. 연차 잔여일 — 원장(Ledger) 방식, **입사일 기준**

### 4.1 법정 기준 (참고, 확정 전 노무·취업규칙 확인 필수)
저는 법률 자문을 하지 않으며, 회사 **취업규칙이 법정 기준 이상**일 수 있다. 아래는 일반적으로 안내되는 근로기준법 제60조 기준이다.
- 1년 미만: 1개월 개근할 때마다 1일, **최대 11일**
- 1년 이상(1년간 **80% 이상 출근**): **15일**
- 계속근로 3년 이상: 최초 1년 초과 근속 **매 2년마다 1일 가산**, 총 한도 **25일**
- 사용 기한: 발생일로부터 1년(미사용 소멸, 회사 이월 규정이 있으면 별도)
- 반차·시간 단위 사용은 법에 세부 규정이 없어 **회사 규정**으로 정함
- 1년 미만 때 발생해 쓴 월 연차를 1년차 15일에서 **차감하지 않는 것**이 현행 해석으로 알려져 있다(확인 필요). 원장은 부여를 독립으로 관리하므로 별도 차감 로직을 두지 않는다.

출처(2차 자료): [flex 연차 유급휴가 개념 정리](https://intercom.help/flex-team-guide/ko/articles/10288450-%EC%97%B0%EC%B0%A8-%EC%9C%A0%EA%B8%89-%ED%9C%B4%EA%B0%80-%EA%B0%9C%EB%85%90-%EC%A0%95%EB%A6%AC). 법령 원문은 국가법령정보센터에서 확인할 것.

### 4.2 계산 규칙 (순수 함수로 구현 → 테스트 용이)

```
발생 일정(입사일 H, 기준일 T):
  1년 미만: H에서 매 1개월 경과일마다 1일(최대 11회)   ← 월 1일씩 생기는 직원
            각 발생분 만료 = H + 1년 (회사 규정에 따라 조정 가능하게 정책 상수로 분리)
  완료 근속연수 y ≥ 1: 매 입사 기념일에 부여
      일수 = min(25, 15 + floor((y - 1) / 2))
      만료 = 부여일 + 1년
  출근율 80% 미만: 1차는 자동 판정하지 않고, 관리자가 해당 부여를 수동 조정(사유 필수)
저장 단위: 분(minute). 1일 = work_minutes_per_day = 480분(8시간). 화면은 일(0.5 단위) 또는 시간으로 환산
```

| 완료 근속연수 y | 부여 일수 |
|:-:|:-:|
| 1 | 15 |
| 2 | 15 |
| 3 | 16 |
| 4 | 16 |
| 5 | 17 |
| 21 | 25 |
| 23 | 25 (한도) |

경계 케이스: 월말 입사(1/31 입사 → 2월 말 경과일), 윤년(2/29 입사), 정확히 1년 되는 날, 퇴사·휴직, 입사일 미등록(→ 잔여 `—`).

### 4.3 차감·잔여 규칙
- **FIFO(만료 임박분부터) 차감.**
- 사용 가능 = (유효 부여분 잔여 합) − (**결재 진행 중 신청의 예약분**). 동시에 여러 건 올려 초과 신청하는 것을 막는다. (자기 결재는 상신 즉시 승인되므로 예약 없이 바로 소진.)
- 승인 시 소진 기록, 반려·회수 시 예약 해제, **승인 후 취소 시 복원 기록**(음수 소진).
- 잔액 부족 시 기본 **차단**, 관리자 예외 허용 옵션(`allow_negative`, Q-06).
- 모든 부여·소진·복원·만료·조정은 **append-only 원장**. 잔여는 합계로 **계산**(직접 저장 안 함). 수동 조정은 사유 필수 + 이력.
- 화면 지표 원칙: 계산 불가(입사일 없음 등)는 `0일`이 아니라 `—`.

### 4.4 「나의 휴가」 화면에 보일 것
발생 / 사용 / 예약(결재 중) / **잔여**, 만료 예정일별 잔여, 올해 사용 내역, 신청 상태. 월 발생 직원은 **다음 발생일**도 표시.

### 4.5 팀장 · 관리자 화면
팀장: 팀원 잔여·휴가 현황(캘린더). 관리자: 전사 잔여 현황, 수동 조정(사유 필수), 입사일 누락자 목록, **자기 결재 목록**.

### 4.6 기초 잔액 이관 (현황 파일 도착 후 실행 — **지금은 설계만**)
- 이미 근무 중인 직원은 입사일 기준으로 **과거 부여 내역을 처음부터 재계산하면 실제와 어긋난다.** 그래서 `시스템 도입일(ledger_start_date)`을 정하고, **도입일 이전 사용분은 계산하지 않는다.**
- 이관 데이터(사용자가 별도 제공, Q-14): 직원별 **현재 잔여 연차, 부여분별 만료일(알 수 있으면)**. 부여분이 구분되지 않으면 직원당 1건으로 이관하고 만료일은 규칙으로 추정(관리자 확인).
- 이관 방식: 엑셀 업로드 → **미리보기(dry-run)** → 확정 시 `leave_grants`에 `source='opening'`으로 적재(멱등 `grant_key='OPEN:<user_id>:<seq>'`).
- 자동 발생은 `ledger_start_date` **이후 도래하는 발생일**부터만 생성.
- 이관 후 **총량 검증 리포트**(엑셀 합계 = 원장 합계)를 반드시 출력.

## 5. 직원 엑셀 일괄 등록 (입사일·팀장·연락처)

기본은 **사용자 관리 화면에서 개별 입력**, 최초 1회는 **엑셀 일괄 등록**. 기존에 `cmd/asimport`, `cmd/mntimport` 같은 가져오기 패턴과 `excelize` 의존성이 있으므로 같은 방식으로 만든다.

- 화면: `관리 > 사용자/권한 > 직원 정보 엑셀 등록` (관리자 전용): 양식 다운로드 → 업로드 → **미리보기(오류·경고 표시)** → 확정.
- 엑셀 열(안): `아이디(또는 사번)`, `성명`, `소속(조직)`, `입사일`, `팀장 여부`, `연락처`.
- 매칭 키는 **아이디**(성명은 대조용). 성명 불일치·미등록 아이디는 오류로 표시하고 건너뜀.
- 입사일: `YYYY-MM-DD`, `YYYY.MM.DD`, 엑셀 날짜 서식 모두 허용 후 정규화. **미래 날짜·1970년 이전·형식 오류는 경고/오류.**
- **팀장 여부 검증**: **한 조직에 팀장은 1명**이다(D-14). 2명 이상으로 표시되면 오류, 한 명도 없으면 경고(팀장이 없으면 그 조직 직원은 상신 불가).
- 같은 파일을 두 번 올려도 결과가 같아야 한다(**멱등 upsert**). 실행 이력은 감사 로그에 남김.
- 전체 성공 또는 전체 롤백(부분 반영 금지)을 기본으로 하되, 미리보기 단계에서 오류 행 제외 옵션 제공.
- 사용자 관리 화면에서 개별 수정한 값이 이후 엑셀 재업로드로 **조용히 덮어써지지 않게** 변경 대상은 미리보기에서 `기존값 → 새값`으로 표시.

- 템플릿 생성 시 위 두 파일은 **삭제 또는 빈 내용으로 교체**하고, 생성 결과의 미리보기도 비워 둔다.

## 8. DB 스키마 초안 (Cursor 구현용)

마이그레이션은 현재 최신(055) 다음 번호부터, 기존 규칙(`NNN_name.sql` + `.down.sql`, `InitDB`의 `repository.applyX`로 동일 실행, SQLite라 제약은 트리거)을 따른다. **결재 엔진 테이블(`approval_*`, 정책·대리 결재 포함)은 `ia-and-approval-plan.md` §2.3**(056).

```sql
-- 057 직원 프로필 (users 변경 없이 별도 테이블)
CREATE TABLE employee_profiles (
  user_id      TEXT PRIMARY KEY,
  org_id       TEXT NOT NULL,
  hire_date    TEXT,                          -- YYYY-MM-DD. 연차 산정 기준. NULL이면 잔여 '—'
  is_org_head  INTEGER NOT NULL DEFAULT 0,    -- 팀장(부서장). 승인 단계 자동 지정
  phone        TEXT,
  updated_at   DATETIME DEFAULT CURRENT_TIMESTAMP
);
-- 제약(트리거): 조직당 활성 팀장 최대 1명 (D-14)

-- 058 휴가 정책/유형
CREATE TABLE leave_policies (
  org_id               TEXT PRIMARY KEY,
  work_minutes_per_day INTEGER NOT NULL DEFAULT 480,          -- 1일 = 8시간 (D-18)
  allow_negative       INTEGER NOT NULL DEFAULT 0,
  doc_prefix           TEXT NOT NULL DEFAULT 'VI',
  ledger_start_date    TEXT,                                  -- 시스템 도입일(기초 잔액 이관 기준)
  half_am_start        TEXT NOT NULL DEFAULT '09:00', half_am_end TEXT NOT NULL DEFAULT '13:00',  -- 관리 설정에서 변경 가능 (Q-01)
  half_pm_start        TEXT NOT NULL DEFAULT '14:00', half_pm_end TEXT NOT NULL DEFAULT '18:00',
  updated_at           DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE leave_types (
  type_key             TEXT PRIMARY KEY,
  label                TEXT NOT NULL,
  unit                 TEXT NOT NULL,       -- day | time
  deducts_balance      INTEGER NOT NULL,
  reflect_staff_leaves INTEGER NOT NULL,
  is_active            INTEGER NOT NULL DEFAULT 1,
  sort_order           INTEGER NOT NULL DEFAULT 0
);

-- 059 휴가 신청서
CREATE TABLE leave_requests (
  leave_req_id        TEXT PRIMARY KEY,
  org_id              TEXT NOT NULL,
  user_id             TEXT NOT NULL,                      -- 신청자(작성자)
  doc_no              TEXT NOT NULL UNIQUE,               -- VI-근태-260807-001
  type_key            TEXT NOT NULL REFERENCES leave_types(type_key),
  type_note           TEXT,                               -- 기타(직접입력)
  period_mode         TEXT NOT NULL,                      -- days | hours | swap
  start_date          TEXT NOT NULL,
  end_date            TEXT NOT NULL,
  start_time          TEXT,
  end_time            TEXT,
  half_part           TEXT,                               -- am | pm (반차 입력 보조)
  work_minutes        INTEGER NOT NULL,                   -- 서버 계산(차감 후보 분)
  swap_date           TEXT,
  swap_state          TEXT,                               -- worked | scheduled
  reason              TEXT NOT NULL,
  destination         TEXT,
  contact_phone       TEXT,
  deputy_user_id      TEXT,                               -- 업무대행자 (선택, NULL 허용)  D-21
  approver_deputy_user_id TEXT,                           -- 대리 결재자 (팀장 본인 신청 + 정책 C 일 때 필수)
  approval_request_id TEXT,
  status              TEXT NOT NULL DEFAULT 'draft',      -- draft|pending|approved|rejected|withdrawn|cancelled (결재 상태와 같은 트랜잭션에서 동기화)
  created_at          DATETIME DEFAULT CURRENT_TIMESTAMP
);
CREATE INDEX idx_lreq_user ON leave_requests(user_id, start_date);
CREATE TABLE leave_request_days (                          -- 영업일 단위 전개
  leave_req_id TEXT NOT NULL REFERENCES leave_requests(leave_req_id),
  leave_date   TEXT NOT NULL,
  minutes      INTEGER NOT NULL,
  PRIMARY KEY (leave_req_id, leave_date)
);
CREATE TABLE doc_sequences (                               -- 문서번호 채번
  scope TEXT NOT NULL, seq_date TEXT NOT NULL, last_no INTEGER NOT NULL,
  PRIMARY KEY (scope, seq_date)
);

-- 060 연차 원장 (append-only)
CREATE TABLE leave_grants (
  grant_id   TEXT PRIMARY KEY,
  user_id    TEXT NOT NULL,
  grant_key  TEXT NOT NULL,        -- 'M:2026-09'(월 발생) | 'Y:2027'(연 발생) | 'OPEN:<user>:<seq>'(기초 이관) | 'ADJ:<uuid>'(수동)
  minutes    INTEGER NOT NULL,
  granted_on TEXT NOT NULL,
  expires_on TEXT NOT NULL,
  source     TEXT NOT NULL,        -- auto_monthly | auto_yearly | opening | manual
  note       TEXT,
  created_by TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE (user_id, grant_key)      -- 발생 배치를 여러 번 돌려도 중복 없음(멱등)
);
CREATE TABLE leave_consumptions (
  cons_id      TEXT PRIMARY KEY,
  user_id      TEXT NOT NULL,
  grant_id     TEXT NOT NULL REFERENCES leave_grants(grant_id),
  leave_req_id TEXT,
  minutes      INTEGER NOT NULL,   -- 사용=양수, 복원=음수
  kind         TEXT NOT NULL,      -- use | restore | expire
  created_at   DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 061 staff_leaves 연결
ALTER TABLE staff_leaves ADD COLUMN source_request_id TEXT;   -- 결재 경유 건 구분·취소 시 되돌림용
```

필수 제약(트리거·서비스 모두):
1. `leave_grants`, `leave_consumptions`, `approval_events` **UPDATE/DELETE 금지**
2. 한 부여분의 `SUM(consumptions) ≤ minutes`
3. 같은 사용자의 활성(`pending`/`approved`) 신청 **날짜 겹침 금지**
4. `status ≠ 'draft'` 이후 신청 내용(기간·유형·사유) 변경 금지(결재 스냅샷과 일치)
5. 승인 단계의 승인자는 기안자 본인일 수 없다(예외 = 팀장 본인 자기 결재, `ia-and-approval-plan.md` §2.3 제약 5)
6. `half`/`early_leave`/`outing`은 시작<종료 필수, `half`는 `half_part` 필수
7. 팀장이 지정되지 않은 조직의 직원은 상신 불가(서비스에서 명확한 오류)
8. 팀장 본인 신청이고 정책 C가 켜져 있으면 `approver_deputy_user_id` 필수(같은 조직 활성 직원, 본인 아님)

## 9. 필수 테스트 (Cursor 구현 시, Go 테스트)

**계산/원장**
- 부여 일수 표(§4.2) 전부 + 월말·윤년·정확히 1년 경계, **1년 미만 월 발생(최대 11회) 경계**
- 발생 배치 **멱등성**(두 번 실행해도 `grant_key` 중복 없음)
- FIFO 차감, 부분 소진, 복원, 만료 처리, 월 발생분+연 발생분 혼재 시 차감 순서
- 예약분 반영: 잔여 3일에 2일+2일 신청 시 두 번째 **차단**
- **동시성**: 같은 사용자의 동시 제출 2건이 초과 예약되지 않음
- 입사일 NULL → 잔여 `—`
- **1일=480분 기준** 시간 단위 차감 정확성(조퇴 3시간=180분), **반차 = 240분**, 반차 시각 환산
- `ledger_start_date` 이전 발생일은 자동 부여하지 않음

**일수/채번**
- 주말·공휴일 제외 영업일 수, 휴일이 시작/끝인 경우, 연말·연초 걸침
- 문서번호 일별 순번 · **동시 제출 중복 없음** · 날짜 바뀜 리셋

**직원 엑셀 일괄 등록**
- 날짜 형식 3종 정규화, 미래 날짜/형식 오류 처리, 미등록 아이디·성명 불일치
- 같은 파일 재업로드 **멱등**, 일부 오류 시 롤백, 변경 대상 `기존값 → 새값` 미리보기 정확성
- **조직별 팀장 0명 경고 / 2명 이상 오류**
- 권한(관리자 외 접근 불가), 감사 로그 기록

**기초 잔액 이관**
- dry-run은 DB를 바꾸지 않음, 확정 시 `OPEN:` 부여 적재, **엑셀 합계 = 원장 합계** 검증, 재실행 멱등

**결재선·자기 결재 (휴가)**
- 일반 직원: 결재선 = 작성(본인) → 승인(소속 팀장), **검토 단계 없음 = 검토란 공백**
- **팀장 본인 신청: 결재선 = 작성(본인) → 승인(본인), 상신 즉시 `approved`, 이벤트 순서 `submit → self_approve`**
- 자기 결재에도 **잔여 부족·날짜 겹침은 차단**되고, 실패 시 상태·원장·`staff_leaves` 모두 롤백
- **일반 직원이 자기 자신을 승인자로 지정/승인하는 시도는 차단**
- 결재 설정에서 휴가 자기 결재 체크를 끄면 팀장 본인 신청이 차단됨
- 팀장이 지정되지 않은 조직 직원의 상신 차단과 안내 문구
- 팀장 신청 휴가의 **취소**도 자기 결재로 처리되고 잔여·`staff_leaves`가 복원됨
- 관리자 화면 **자기 결재 목록**에 해당 건만 나타남, 관리자 알림 체크 on/off에 따른 알림 적재
- 승인 → `staff_leaves` 행 생성(영업일마다)·`source_request_id` 연결, 반려/회수 → 생성 안 됨
- 승인 후 취소 → `staff_leaves` 삭제 + 잔여 복원 (**원자적**, 실패 시 전체 롤백)
- 시점 보기·옵저버·타인 접근 시 신청/승인 불가, 본인 문서만 열람(팀장은 팀원)
- 겹침 신청 차단
- **업무대행자 없이 제출 가능**, 출력 양식 해당 칸 공백

**대리 결재 연동 (정책 C 등)**
- 정책 C 켬: 팀장 본인 휴가 신청에서 대리 결재자 **필수**(미입력 시 상신 불가), 일반 직원 신청에는 입력란 없음
- 정책 C 끔: 대리 결재자 입력란 없음
- 팀장 휴가 최종 승인 시 **휴가 기간(달력 기준)** 의 대리 결재 지정 생성, 휴가 취소·반려·회수 시 생성 안 됨/종료
- 대리인이 팀원 휴가를 승인하면 `acted_by`·`act_mode='delegate'` 기록, 출력 `{{승인표기}}`=`(대결)`
- 대리인이 **자기 휴가를 대결 승인할 수 없음**
- (정책 조합·경계·겹침·권한 테스트는 `ia-and-approval-plan.md` §2.5.5)

**견적 결재**
- 견적 `draft` 상신 → 승인 전에는 `sent`(제출) 전환 불가, 승인 후 가능
- 상신 후 품목·금액 수정 불가(스냅샷), 반려 후 재상신 시 리비전 증가
- 결재선 마지막 = 팀장, **팀장이 작성한 견적은 자기 결재**(금액과 무관), 결재 설정에서 견적 자기 결재를 끄면 차단

**출력**
- 자리표시자 치환 골든 테스트: 문서번호·구분 체크·기간 3방식·결재란·서명 삽입
- **자기 결재 건은 작성·승인란 둘 다 본인 서명**, 검토란은 항상 공백, 대결 건 `(대결)` 표기
- **남은 `{{` 없음, 미리보기 파일에 샘플 개인정보 없음**(§6.3)

**기타**
- 마이그레이션 up/down 왕복, `InitDB` 재실행 멱등
- 390px 폭 휴가 신청 → 결재 시나리오(수동 검수 + 개발기 Playwright)
- 역할 매트릭스: 전 역할이 `self.leave`, `self.approval`을 가지는지, `approval.admin`만 결재 설정 변경 가능
