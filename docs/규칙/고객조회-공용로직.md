# 고객 조회 공용 로직 (95-22)

## Scope

| Scope | 대상 | 화면 |
|---|---|---|
| `site` | 활성 `party_kind=customer` | AS·정기점검·일일업무·작업 사이트·자산·연락처·점검 사이트 |
| `party` | customer + partner + vendor + own | 발주처·계약상대·제조사·공급사·견적 수신처 |

`own` 을 `party` 에 포함한 근거: 기존 `ListAll()` 이 party_kind 를 가리지 않았고, 품목 제조사/공급사 검색(`/customers/search`)이 같은 집합을 썼다.

가등록(`is_provisional`)은 AS 접수 `ListForReceipt` 와 같이 활성 customer 이면 포함한다.

## 규칙

- 조직 조건 없음. 하위 기관 포함. 건수 상한은 호출자 `Limit` 만.
- 표시 이름: `기관명`, 동명 또는 상위기관이 있으면 `기관명 (상위기관 · 지역)`.
- 검색 필드: 기관명·공식명·기관코드·고객ID·상위기관명·시도·시군구·주소. LIKE 이스케이프.

## 허용 목록 (선택 목록이 아닌 조회)

| 위치 | 사유 |

## 새 화면에서 고객을 고르려면

1. `{{template "customer_combo" dict "Name" "customer_id" "Scope" "site"}}`
2. 서버는 `/lookup/customers` 또는 `repo.Lookup(CustomerQuery{...})`
3. 폼 필드명 `customer_id` 와 기존 검증은 유지
