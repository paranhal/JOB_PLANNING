# 95-198 구현 보고(활동 분류 입력칸) — 업무 등록·수정 화면의 활동 분류 입력칸

> 같은 번호의 긴급 건(정적 JS 버전 쿼리)은 `95-198_구현보고.md` 에 있다.

작성: 2026-11-15. 푸시·배포·VERSION 변경 없음. 95-197(주간업무보고서 활동 분류)의 후속으로, 업무를 만들거나 고칠 때 활동 분류를 바로 지정하게 했다.

## 1. 변경
- **입력칸**: 「활동 분류」 선택(— 없음 — + 7종)을 공용 조각 `_partials/activity_kind_field.html` 로 만들어 두 화면에 넣었다.
  - 업무 등록(`+ 일일 업무 등록` → 행정 / 지원업무, `_modals.html`의 `wb_form_admin_sales`): 사업명 아래. 「행정업무」일 때만 보인다(지원업무는 사업 필수, 영업활동은 해당 없음).
  - 업무 수정(`task_show.html` 수정 모드): 사업명 아래에 현재 값이 선택된 채로 보인다.
  - 상세 화면 머리에 「활동 <분류>」 표시.
  - 옛 등록 화면(`admin_work/form.html`, `/admin-work` 등록)에도 같은 칸과 저장을 넣었다.
- **저장**(`handler/workboard_activity_kind.go`):
  - 등록은 `persistNewTask`(업무 관리 등록·나누기 포함)와 `AdminWorkHandler.Create`, 수정은 `UpdateTask` 저장 뒤에 `SetTaskActivity` 로 반영한다.
  - 알 수 없는 분류 값은 저장 전에 400으로 거절한다.
  - 사업이 있으면 사업이 우선이고 활동 분류는 비운다(사업과 활동은 함께 갖지 않는다). 일반(행정) 업무만 대상이다.
  - 칸을 보내지 않는 화면에서 사업을 연결하면 남아 있던 활동 분류를 비운다.
  - 「업무별 나누기」로 여러 건이 만들어질 때는 모두에 같은 분류를 적용한다.
- 새 DB 컬럼·스키마 변경 없음(95-197의 `work_tasks.activity_kind` 사용).

## 3. 시험
- HTTP `TestHTTP95_198_*`(4): 등록 화면에 칸·7종 / 등록 저장·미입력·잘못된 값 400(업무 미생성) / 수정 화면 선택 표시·상세 표시·변경·해제 / 사업이 있으면 활동 분류 안 남음.
- 실제 브라우저 `Test95_198_BrowserActivityField`(임시 DB, 390/1440): 「+ 일일 업무 등록」→「행정 / 지원업무」를 눌러 활동을 고르고 저장 → DB에 분류 저장(390 고객서비스·1440 경영지원), 수정 화면에서 현재 값 확인 후 역량강화로 변경 → 상세에 표시. 가로 넘침 없음. 스크린샷 `docs/리뷰/screenshots/95-198/`.
- 전체 게이트(수정 전): 통과 2809 / 실패 14(기존 7 · 신규 7). 신규 7은 모두 등록 화면 템플릿을 직접 읽는 시험이 새 조각 파일을 목록에 갖고 있지 않아서 생긴 것(`no such template "activity_kind_field"`)이다. 시험 목록에 조각을 추가해 7건 모두 통과를 확인했고, 전체 게이트는 다시 돌리지 않았다.

## 4. 한계·남은 것
1. 지원업무·영업활동·AS·정기점검·수행 업무에는 활동 분류 칸이 없다.
2. 사업을 고르면 활동 분류가 적용되지 않는 규칙은 서버에서 처리한다(화면에서 서로 해제하지는 않는다).
3. 등록 화면 스크린샷은 모달 위쪽이라 칸 자체는 스크롤해야 보인다.
