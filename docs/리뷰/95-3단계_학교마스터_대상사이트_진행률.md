## 스키마 075

- `customers.org_code` + 부분 UNIQUE `(org_id, parent_customer_id, org_code)`
- `project_sites` 상태 CHECK: `planned` · `in_progress` · `installed` · `inspected` · `excluded` (옛 `active`→진행, `done`→검수완료)
- `installed_at` / `inspected_at` / `excluded_reason` / `status_changed_at` / `by`
- 부분 UNIQUE `(project_id, customer_id)`
- `project_site_events`(append-only), `site_import_batches`
- 트리거: 고객이 있으면 사이트 org = 고객 org = 사업 org

## 화면

- 고객현황: 기본 목록은 하위 기관 **접기**(상위만). 「하위 N」으로 펼침(`?category=`). 「하위 기관 일괄 등록」
- 학교 엑셀: 시트 `기관`. 미리보기 → 적용. 상위 없으면 체크 시에만 생성. 빈 상위 = 충청남도교육청
- 사이트·장비: 「대상 학교 추가」(상위 선택·검색·체크), 대상/상태 엑셀(시트 `사이트`), 체크 일괄 상태, **설치 N/대상 · 검수 N/대상**. 제외는 분모에서 빠짐
- 사업 상세: 같은 진행률. 모두 검수여도 **안내만**. 완료 버튼은 기존 권한 처리

## 운영 적용 체크리스트 (데이터 직접 INSERT 금지)

1. DB 백업
2. 배포 후 InitDB가 075를 적용했는지 확인(`project_site_events` 테이블, 사이트 status CHECK)
3. 고객현황에서 충청남도교육청이 상위 기관으로 있는지 확인. 없으면 한 건 등록(또는 업로드 시 「신규 상위 기관 생성」)
4. `기관목록_업로드양식.xlsx` 미리보기 → 오류 0 확인 후 적용
5. 사업 사이트는 화면에서 대상 선택 또는 `사업사이트_업로드양식.xlsx` 미리보기 후 적용
6. 이 에이전트는 운영 DB에 학교를 넣지 않음
