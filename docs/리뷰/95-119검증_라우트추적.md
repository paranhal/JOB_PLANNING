## 1. 라우트 추적

### 1-a. `cmd/server/main.go`가 gitignore 되는 규칙

| 파일 | 줄 | 패턴 | 맞는 경로 |
|------|----|------|-----------|
| 루트 `.gitignore` | 25 | `server/server` | 바이너리 `server/server`만. `cmd/server`는 **해당 없음**. |
| **`server/.gitignore`** | **9** | **`server`** (슬래시 없음) | `server/` 아래 **이름이 `server`인 모든 경로**. `server/server`(산출물)와 **`server/cmd/server/` 디렉터리 전체**가 맞음. |

`git check-ignore -v --no-index`:

```
server/.gitignore:9:server	server/cmd/server/main.go
server/.gitignore:9:server	server/cmd/server/
server/.gitignore:9:server	server/cmd/server
server/.gitignore:9:server	server/server
```

`--no-index` 없이 `main.go`만 보면, **이미 추적 중**이라 기본 `check-ignore`는 안 찍힌다. `git add`는 무시되어 `-f`가 필요하다.

`git ls-files -v -- server/cmd/server/main.go` → `H` (일반 캐시, assume-unchanged 아님).

### 1-b. 기존 라우트 등록 위치

`GET /workboard/projects/picker-other` 는 **추적되는 `server/cmd/server/main.go`** 에 있다 (`wb.GET("/projects/picker-other", …)`). 핸들러는 `ListPickerOtherProjects`. 테스트 파일에도 같은 경로를 **테스트용 Echo에 다시** 붙인다 (`workboard_board_test.go` 등). 프로덕션 등록은 main.go 한 곳.

`sites-panel` / `site-check` 도 **같은 main.go** (HEAD `0b1da2e`에 포함됨):

- `proj.GET("/:id/sites-panel", h.Project.SitesPanel)`
- `wb.POST("/tasks/:id/site-check", h.Workboard.SaveSiteCheck)`

테스트 `mount119`는 HTTP 테스트 전용.

### 1-c. `git ls-files` · 이미지 빌드

추적되는 main 계열:

- `server/cmd/server/main.go` **있음** (추적 + gitignore 겹침)
- 그 외 `server/cmd/*/main.go` (asimport, devseed958, migrate093, mntimport, quoteform, syncsites, verifyassets)
- `scripts/mobile_audit/main.go`

Dockerfile (`server/Dockerfile`): `COPY . .` 후 `go build … -o server ./cmd/server`. 컨텍스트는 보통 `server/`. `.dockerignore`에 `cmd` 없음 → **디스크의 `cmd/server/main.go`가 이미지에 들어간다.**  
`scripts/smoke.sh`도 `go run ./cmd/server`.

**주의:** clone/CI는 **커밋된** main.go를 쓴다. 로컬에서 main.go만 고치고 `git add`가 무시되면, 이미지 빌드 스크립트가 워킹트리를 쓰면 로컬 변경이 들어가고, 원격만 받으면 **마지막 커밋 내용**만 간다. 지금은 HEAD에 두 라우트가 있어 clone도 포함된다.

### 1-e. 해결 선택지 (아직 적용하지 않음)

1. **`server/.gitignore` 9행을 `/server`로 바꾸거나 산출물만 적기** (`/server`, `*.exe`). `cmd/server`는 무시되지 않음. 영향: 바이너리 무시 유지, `git add cmd/server/main.go`가 됨. 실수로 바이너리를 `cmd/server`가 아닌 모듈 루트 `server`에 두면 계속 무시.
2. **라우트 등록을 추적·무시되지 않는 파일로 분리** (예: `internal/handler/routes.go` 또는 `cmd/app/routes.go`). `TestNavHrefsHaveGETRoutesInMain`의 `readServerMain` 경로를 같이 바꿔야 함. 영향: 테스트·도커 모두 추적본만 봄. main.go는 엔트리만.
3. **관례로 `git add -f server/cmd/server/main.go`**. 영향: 지금은 HEAD에 라우트가 있어 급하지 않음. 다음부터 `git add`가 또 빠질 수 있음.

권장 합의안은 1 또는 2. 3만 쓰면 재발한다.
