# 94-7단계 보고서 — 전체 조직 보기에서 등록 500

기준: `커서_작업지시서_94-7_전체조직보기_등록_500.md`. 마이그레이션 없음.

## 실제 이름 (지시서와 다른 점)

| 지시서 | 코드 | 이유 |
|--------|------|------|
| `assignableOrgID` 류 | `resolveInsertOrg` | 기존 `assignableOrgID`는 `/exec/work?org=` 예외를 빼면 여전히 `currentOrg`를 돌려 `*` 가 남을 수 있음. INSERT 전용으로 폼 `org_id` → 특정 `currentOrg` → 로그인 `org_id` 순, `"*"` 금지. |
| 보기 조직 | `currentOrg` / JWT `view_org_id` / `repository.OrgAll`=`"*"` | 지시서와 동일 개념 |
| 고객 INSERT | `customers.org_id` + `RequireInsertOrg` | 빈 값은 Library(`O01`)로 보정, `"*"`는 `ErrEmptyOrgID` |
| 점검 사이트 | `maintenance_site_config` | INSERT 컬럼에 `org_id` 없음(고객 `customer_id`만) |

## 원인

- **고객 등록**: vsadmin 기본 보기가 `*`. 예전 `bindCustomer`가 `OrgID: currentOrg`를 넣어 `RequireInsertOrg("*")` → Echo 500. 목록 `GET /customers`는 200.
- **점검 사이트 등록**: **같은 원인이 아님.** `UpsertSiteConfig` INSERT는 `(customer_id, short_name, …)`이고 `org_id`/`currentOrg`를 쓰지 않는다. 빈 고객·표시명은 JSON 400이었고, vsadmin 전체 보기만의 `*` INSERT 경로는 없다. 필수값 오류는 폼+한국어 메시지로 바꿨다.
- **연간 계획 생성** (`POST /maintenance`): `CreatePlan`이 `currentOrg`로 `CreatePlanForOrg`를 호출해 전체 보기에서 막혔다. 고객과 같은 `resolveInsertOrg`를 씀(400, 500 아님).

## 동작

- 전체 보기 + 쓰기 가능(비젼관리자): 고객 등록 폼에 소속 조직 필수 드롭다운. 미선택 시 폼 복귀 「소속 조직을 선택하세요」. 선택 시 그 조직으로 생성.
- 특정 보기(O02): 드롭다운 숨김, 보기 조직으로 생성.
- 조직관리자: 드롭다운 숨김, 본인 조직. 타 조직 `org_id` 조작은 거부.
- C-Level·읽기 전용: `RequireMasterWrite` 403 유지. 수정(`Update`)은 `org_id`를 바꾸지 않음(SQL도 SET 안 함).
