# 95-221 구현 보고 — 정기점검 일정 이동 시 담당자 비워짐 → 미배정 고착

작성 2026-11-24 · 브랜치 `works` · 커밋만(푸시·배포 안 함) · 운영 DB 접근·수정 없음 · 기존 데이터 일괄 UPDATE 없음(④는 SQL 제공만)

## 요약
- **재현된 원인**: 같은 담당자의 다른 업무를 정기점검 일일업무와 겹치게 옮기고 「기존 일정에서 담당자만 제외」를 확인하면 정기점검 일일업무의 담당이 비워지고 `manual`로 바뀐다(0단계 보고서 §2). 이어서 동기화가 `manual`이면 방문 담당을 복사하지 않아 영구히 미배정이 된다.
- **①②를 모두 구현**했다(③ 막힘 안내는 아래 설명). 게이트 `make test-gate`: 통과 2575 / 실패 2(기존 1 · 신규 1 · 해결 6). 신규 1건(`TestHTTP95_202_RowContentAndLinks`)은 시험 데이터 날짜(11/20)가 지나서 생긴 시간 의존 실패로 이번 변경과 무관하다. 실제 브라우저 1440/820/390 통과.
- 배포 라벨은 `95-221`.

## ① 이동·수정 시 담당 보존
| 항목 | 변경 |
|---|---|
| 선택기가 비어 올라옴 | `assignee_cleared=1`(사용자가 「선택 해제」를 누른 경우)일 때만 담당을 비운다. 날짜·시간만 바꾸는 저장이나 선택기 값 누락으로는 기존 담당을 유지한다. 「선택 해제」 버튼은 플래그를 켜고, 다시 고르면 끈다(`assignee_picker.js`·`_ui_assignee_picker.html`) |
| 수동 지정 전환 | 담당 **이름이 바뀌었거나, 이미 있던 담당 ID가 다른 사람으로 바뀔 때만** `manual`. 같은 사람의 ID만 채워지는 것은 전환하지 않는다 |
| 겹침 처리 「담당자만 제외」 | 정기점검에서 생긴 일일업무는 주담당이 제외 대상이고 **보조 담당이 없으면 막고** 「정기점검 업무의 담당자는 겹침 처리로 뺄 수 없습니다. 일정을 옮기거나 담당자를 바꿔 주세요」를 보여 준다(보조 담당이 있으면 종전처럼 승계). 일반 업무는 종전대로 |
| 조직 밖 담당이 저장된 업무 | 편집 화면에 현재 담당이 그대로 보이고, **확인(저장)해도 유지**된다. 이미 저장된 담당·보조 담당은 조직 밖이어도 그대로 둘 수 있게 했다(새로 조직 밖 사람을 고르는 것은 종전처럼 막힘, 95-215 규칙 불변) |

## ② 빈 담당 + manual 자가복구
`applyMntTaskLink`: 일일업무 담당이 비어 있으면 `manual`이어도 **방문 담당으로 채운다**(담당 ID도 맞춤). 채운 뒤에는 방문 담당을 다시 따라가도록 `assignee_source`를 **비수동(빈 값)** 으로 되돌린다 — 코드의 현행 체계에서 동기화로 만든 정기점검 일일업무가 비수동일 때 쓰는 값이다(지시서의 `'maintenance'` 문자열은 이 코드에서 쓰지 않는다). 담당이 있는 수동 값은 종전대로 유지. 변경 이력에 「담당이 빈 수동 업무를 방문 담당으로 채움(95-221)」로 남긴다.

## ③ 막힘 안내
담당 지정이 조직 규칙에 막힐 때는 400 오류 화면에 「같은 조직의 담당자만 지정할 수 있습니다」가 표시되어 조용히 무시되지 않는다(저장이 거절되고 담당은 바뀌지 않음). 겹침 처리로 담당을 뺄 수 없을 때도 이유를 위 문구로 알린다. 별도의 새 화면은 만들지 않았다.

## ④ 기존 데이터 보정 (사용자 실행 — 백업 후)
대상 조회(읽기 전용):
```sql
SELECT t.task_id, t.title, v.assignee, v.assignee_user_id FROM work_tasks t
JOIN maintenance_visits v ON v.visit_id=t.source_id
WHERE t.source_type='maintenance' AND TRIM(COALESCE(t.assignee,''))='' AND TRIM(COALESCE(v.assignee,''))<>'';
```
- 지시서 기준 대상은 WT-1618, WT-1631 2건이다. **이번 배포 후에는 서버가 일정표·일일업무를 열 때 동기화로 자동 복구되므로 위 목록은 배포 후 비어 있게 되는지로 확인할 수 있다.** 직접 보정이 필요하면 아래를 백업 후 실행한다.
```sql
UPDATE work_tasks
   SET assignee = (SELECT v.assignee FROM maintenance_visits v WHERE v.visit_id = work_tasks.source_id),
       assignee_user_id = (SELECT NULLIF(v.assignee_user_id,'') FROM maintenance_visits v WHERE v.visit_id = work_tasks.source_id),
       assignee_source = ''
 WHERE source_type='maintenance' AND task_id IN ('WT-1618','WT-1631')
   AND TRIM(COALESCE(assignee,''))='';
```

## 시험 (게이트 편입)
- `TestMntTaskMoveKeepsAssignee95_221`: 날짜만 바꿔 저장(선택기 비어 올라옴) → 담당 유지, 수동 전환 안 됨.
- `TestMntTaskAssigneeIDFillIsNotManual95_221`: 같은 사람의 ID 채움은 비수동, 다른 사람으로 바꾸면 수동.
- `TestMntTaskExplicitClear95_221`: 명시 해제 → 비워지고 수동.
- `TestMntTaskBlankManualSelfHeals95_221`: 빈 값 + manual + 방문 담당 → 채워지고 비수동, 담당이 있는 수동 값은 유지.
- `TestMntTaskHealedLeavesUnassigned95_221`: 복구되면 미배정 목록에서 빠진다.
- `TestMntTaskOverlapLeaveKeepsOwner95_221`: 겹침 「담당자만 제외」로 정기점검 담당이 비워지지 않고 이유를 알린다, 일반 업무는 종전대로.
- `TestMntTaskForeignAssigneeKeptOnConfirm95_221`: 조직 밖 담당 업무를 열고 확인해도 유지(95-215 규칙과 일치).
- `Test95_221_Browser`(1440/820/390): 현재 담당이 보이고, 「선택 해제」가 플래그를 켜며 다시 고르면 꺼지고, 날짜만 바꿔 저장해도 담당이 유지된다. 스크린샷 `docs/리뷰/screenshots/95-221/`.
- 고친 기존 시험: `Test95_71_EditUsesAssigneePickerAndChecksOwner` — 선택기 값 누락은 이제 기존 담당 유지이므로 그 단계를 추가하고, 「담당자 비움 거절」은 명시 해제(`assignee_cleared=1`)로 확인한다.
