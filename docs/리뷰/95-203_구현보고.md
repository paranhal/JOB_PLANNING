## 1. 변경 (CSS·템플릿만, DB·로직 변경 없음)
- `web/css/input.css`

## 3. 한계·질문
1. 저장 **제출까지** 실제 클릭으로 확인한 화면은 AS 조치뿐이다. 작업 조치·AS 접수 폼은 마우스가 버튼에 닿는 것까지만 확인했다(제출은 필수 입력이 많아 이 시험 환경에서 하지 못함). 구조 일괄 저장 바·영업 상세 바는 미측정(코드 기준).
2. **탭바 높이를 고정값으로 둘지 JS 로 측정할지**: 고정값(45px = 항목 44 + 테두리 1) + `env(safe-area-inset-bottom)` 한 변수로 했다. 탭 항목 높이를 키우면 변수도 같이 고쳐야 한다(탭바 자신이 `height:var(--mobile-tab-h)` 라 어긋나면 눈에 띈다). JS 측정으로 바꾸려면 알려 달라.
3. **기존 문제(수정하지 않음, lg 이상 변경 금지 범위)**: AS 접수 폼은 1024 이상에서도 `main` 아래 여백(24px)보다 고정 바(약 62px)가 커서 스크롤 맨 아래에서 마지막 콘텐츠가 최대 약 39px 가려진다.
4. 구조 일괄 저장 바(z-40)는 모바일에서 탭바를 덮는다. 다른 하단 고정 UI(저장 바 계열)와 같은 규칙으로 통일할지는 별도 결정이 필요하다.
5. 95-201 보고서의 「390·820 저장 버튼 가림」 질문은 이 건으로 해소된다(95-201 시험 스크립트의 JS 클릭 대체는 그대로 남아 있어, 필요하면 실제 클릭으로 되돌릴 수 있다).
