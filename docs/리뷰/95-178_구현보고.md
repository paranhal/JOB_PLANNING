## 3. 시각 통일 (95-133, 95-133B)

**저장 (KST)**: `work_activities`·`mail_outbox`·`sms_outbox`·아이디 예약, `work_tasks.created_at`(INSERT 2곳), `org_head_history.acted_at`. `LocalNowString()`은 서버 TZ와 무관하게 Asia/Seoul이다.

**읽기**: `parseTime`이 시간대 없는 값을 KST로 읽는다. 조치 세트 완료 시각의 `+9시간`(`as_action_set.go`의 `.In(time.Local)`)이 사라졌다. 드라이버가 `DATETIME` 문자열에 붙이는 가짜 `Z`는 숫자를 그대로 KST로 읽는다(안 그러면 모든 화면이 +9시간).

**표시 (UTC로 계속 쓰는 열)**: 협업 이력·업무 그룹 이력·정기점검 계획 수정 시각·휴가 결근 기록은 `FormatUTCDateTime`으로 KST 분 단위 표시. 쓰기 경로 179곳을 건드리지 않고 이미 쌓인 데이터도 보정 없이 맞는다. 이 열들의 기본값이 UTC인지는 시험이 잡는다(`TestUTCDefaultColumnsAreUTC`).

**부수 결함 수정**: `FindRecentDirectTask`(같은 업무 연속 저장 방지)는 UTC 기본값 `created_at`을 현지 `since`와 비교해, **운영(TZ=KST)에서 방금 만든 업무를 한 번도 찾지 못했다.** 이제 같은 KST 기준이라 처음으로 의도대로 동작한다(아래 「주의」).

### 과거 UTC 행 보정 도구 `cmd/utcshift133`

| 항목 | 내용 |
|---|---|
| 대상 | `work_activities.created_at`, `mail_outbox.created_at`, `sms_outbox.created_at`, `work_tasks.created_at`, `org_head_history.acted_at` |
| 제외 | `updated_at`(쓰기가 계속 UTC라 같은 열에 UTC·KST가 섞이면 구분 불가), 표시 변환 열 |
| 방식 | **cutoff(저장 코드가 KST로 바뀐 빌드를 운영에 올려 처음 기동한 시각, 한국 시각)를 사람이 정한다**(기본값 없음). `created_at < cutoff` 인 행만 +9시간. 기동 표식(`95_133_local_now_since`)은 95-161A부터 기록돼 실제 반영 시각과 다를 수 있어 참고로만 출력 |
| 안전장치 | 미리보기가 기본(읽기 전용 DB, 마커 안 씀), `-apply`는 한 트랜잭션·한 번만(재반영 거절), 미래 cutoff 거절 |
| 미리보기 출력 | 표별 대상 건수, 가장 이른·늦은 시각, **날짜가 바뀌는 건수**(보정 후 일자별 통계가 달라지는 규모) |

운영 순서(사용자가 직접): ① `deploy/data/app.db` 백업 → ② cutoff 결정 → ③ 미리보기
`go run ./cmd/utcshift133 -db data/app.db -cutoff "2026-11-12 07:06"` → ④ 반영(`-apply`).
**cutoff를 모르면 반영하지 마세요.** 틀리면 이미 KST인 행이 두 번 +9되거나 UTC 행이 빠진다.
