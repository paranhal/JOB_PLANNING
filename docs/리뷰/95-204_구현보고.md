## 1. 확정한 기본안 4가지 (사용자 확인)
1. **AS 연결은 `asset_id` 만 채운다.** `project_id` 는 다시 계산하지 않는다(소속 사업이 일괄 연결로 바뀌지 않게). 변경 이력(건별)·검색 색인 갱신은 단건 저장과 같다.
2. **점검 연결은 업무를 새로 만들지 않는다.** 방문 대상 행을 **하나 더하고**(기존 직접입력 행 보존), 방문 업무가 이미 있을 때만 `work_task_assets` 를 채운다. 단건 경로의 전체 교체는 쓰지 않았다.
3. **제품 불일치 판정은 명백한 조합만**: 방문 `KLAS` ↔ 자산 제품군 `RFID자동화`, 방문 `앤로보틱스` ↔ `자료관리`. 그 밖의 제품군·빈 제품·제품군 없는 자산은 막지 않는다. AS 에는 제품 규칙이 없다.
4. 키워드 사전 변경 없음, 「홈페이지」 라벨은 보류.

## 2. 변경

### ① 정렬 (§2)
- `sort` 쿼리 파라미터. **화이트리스트 맵**(키 → ORDER BY 조각)만 쓰고 사용자 입력은 키로만 쓴다. 모르는 값·다른 탭의 키·인젝션 문자열은 기본 정렬. 기본은 현행 유지(AS 접수일 최신순, 점검 방문일 최신순).
- AS: 접수일 최신/오래된순·고객명·담당자(없음은 맨 아래)·후보 자산 수(많은 순). 점검: 방문일 최신/오래된순·사이트명·점검 제품(빈값 맨 아래)·회차·후보 자산 수(**1개에 가까운 순 — 일괄 연결 대상이 위로**).
- 화면: 머리말 클릭(▲▼·`aria-sort`, 같은 키 다시 누르면 다음 정렬, 기본으로 돌아가면 주소에서 `ul_sort` 제거) + 「정렬」 선택 상자(바꾸면 바로 조회). 쪽 이동·필터에서 유지, 주소(`ul_sort`)에 남아 새로고침·뒤로 가기에서 유지.
- **한계(후보 자산 수 정렬)**: DB 에서 상관 서브쿼리 한 줄(`SELECT COUNT(*) FROM assets …`)로 정렬하므로 앱 쪽 N+1 은 없지만, 정렬 키가 후보 행마다 한 번씩 평가된다. 시험 규모(AS 850·방문 870)에서 체감 지연 없음. 규모가 훨씬 커지면 고객별 자산 수 집계를 조인으로 바꾸는 것이 다음 단계.

## 5. 질문
1. **정렬 기준 확인**: 지시서의 기본안(AS: 접수일 최신/오래된순·고객명·후보 자산 수·담당자 / 점검: 방문일 최신/오래된순·사이트·제품·회차·후보 자산 수)으로 구현했다. 원하는 순서가 다르면 알려 달라(특히 전 보고서에서 물었던 **지연·미완료를 앞에 두는 점검 정렬**이 필요한지).
2. **청구기호출력기**가 KLAS(KDevice 연결 장비)·RFID 중 어느 쪽 키워드인지 — 확정 시 사전 두 줄과 시험 표 행만 고치면 된다. `book_stats`·`opac`·`대출관리`(KLAS), `무인회원증`(RFID) 추가도 같이 확정해 달라. 「홈페이지」 라벨은 보류 중.
3. 점검 일괄 연결은 방문 업무가 없으면 `work_task_assets` 를 만들지 않는다. 이후 업무가 생길 때 방문 대상에서 자산이 복사되는지는 별도 확인이 필요하다(현재 단건 경로 동작에 의존).
4. 닫힌(완료) AS 는 `asUnlockAllowsClosed` 규칙에 따라, 잠금 해제가 필요한 사용자(비전관리자·관리자 역할)는 체크박스에 「완료된 건은 잠금 해제 후 조치 화면에서 연결하세요」로 표시된다(일괄 처리에서 잠금 해제는 하지 않음).
