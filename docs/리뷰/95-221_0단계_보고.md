# 95-221 0단계 보고 — 정기점검 일정 이동 시 담당자 비워짐 → 미배정 고착 (재현)

작성 2026-11-24 · 코드 변경 없음(재현은 `server/` 복사본에서 임시 시험·브라우저 스크립트로만, 저장소에는 없음) · 운영 DB 접근 없음

## 결론
- **운영에서 확인된 상태(일일업무 담당 빈 값 + `manual`, 방문 담당은 그대로)를 만드는 경로를 재현했다.** 작업지시서의 원인 A(담당자 선택기가 빈 채로 올라옴)가 아니라 **겹침 처리의 「기존 일정에서 담당자만 제외」(`overlap_action=leave`)** 다.
- 원인 B(빈 값 + `manual`이면 방문 담당을 영영 복사하지 않음)는 **그대로 재현**: 방문에 담당이 있어도 일정표를 열어 동기화해도 복구되지 않는다(고착).
- 증상 3(「담당자를 입력해도 계속 미배정」)은 **재현하지 못했다**(아래).

## 1. 원인 A(선택기 값 누락) — 재현 안 됨
정기점검 일일업무 편집 화면을 **실제 브라우저로 열고 예정일을 11/20로 바꾼 뒤 저장**(지연 사유 입력 포함)했다. 일일업무 담당이 어떻게 저장돼 있든 담당은 유지됐다.

| 상태 | 저장 전 화면 제출 값 | 저장 후 담당 |
|---|---|---|
| A 이름+ID 있음(조직 안 사용자) | owner·assignee_user_id 채워짐 | 유지 (`maintenance`) |
| B 이름만(ID 비어 있음)·사용자 있음 | ID가 채워져 올라옴 | 유지, **`source`가 `manual`로 바뀜**(아래) |
| C 이름만·사용자 없음(미등록) | owner 빈 값 + 이름(`assignee_external`)로 올라옴 | 유지 |
| D 이름+ID·사용자 비활성 | 값은 올라옴 | **저장 거절 400** 「같은 조직의 담당자만 지정할 수 있습니다」(비워지지는 않음) |
| E 이름+ID·선택 불가 역할(observer) | 값은 올라옴 | 유지 |
| F 담당 빈 값 + `manual` → 선택기에서 양기헌 선택 후 저장 | 「담당자 미지정」으로 열림 | **담당 저장됨**(→ 증상 3 재현 안 됨) |
- 선택기는 이름만 있는 담당도 외부 이름(`assignee_external`)으로 함께 보내므로, 빈 선택기로 올라와 `postedPicker && sel.Empty()`가 되는 경우를 만들지 못했다. **운영에서 어떤 계정·값일 때 빈 채로 열리는지는 운영 데이터가 필요하다.**
- 참고(부수 효과): B처럼 `assignee_user_id`가 비어 있던 업무를 편집 화면에서 저장하면 ID가 채워지며 `assignee_source`가 **`manual`로 바뀐다**(담당 이름은 그대로). 이후 방문 담당이 바뀌어도 일일업무가 따라가지 않게 된다.

## 2. 재현된 경로 — 겹침 처리 「담당자만 제외」
`/workboard/schedule`로 **같은 담당자의 다른 업무를 정기점검 일일업무와 겹치는 시간으로 옮기면** 겹침 경고가 뜨고, 사용자가 「기존 일정에서 이 담당자만 제외」를 확인하면 겹친 쪽(정기점검 일일업무)의 담당이 빠진다.

| 단계 | 정기점검 일일업무 | 방문 |
|---|---|---|
| 처음 | 담당 양기헌, `source`=비수동 | 담당 양기헌 |
| 겹치는 이동 요청(처리 선택 전) | 그대로 | 그대로 |
| `overlap_action=leave` 확인 후 | **담당 빈 값, user_id 빈 값, `source=manual`** | 양기헌 그대로 |
| 일정표(보드)를 열어 동기화한 뒤 | **여전히 빈 값 + manual (복구 안 됨)** | 양기헌 그대로 |
- 코드: `handler/workboard_overlap.go` `dropNamesFromTask` → (주담당이 제외 대상이고 보조 담당이 없으면) `SetTaskAssignee(taskID, "")` → `assignee_source='manual'`. 운영 확인 상태(빈 값 + manual, 방문 담당 유지, 날짜 11/19 vs 방문 11/20)와 같다.
- 이어서 `repository/wb_mnt_sync.go` `applyMntTaskLink`가 `manual`이면 방문 담당을 복사하지 않아 **영구히 미배정**(원인 B).

## 3. 증상별 판정
| 증상 | 판정 |
|---|---|
| 1. 일정표·일일업무에 미배정으로 보임 | 담당이 빈 업무가 「미배정」 쪽으로 나오는 것은 확인. **월 일정표에서 날짜 칸에 아예 안 보이는 것은 시험 데이터에서 재현하지 못함**(카드는 양쪽 상태 모두 화면에 나옴) |
| 2. 일정 이동 시 담당자 란이 비워짐 | **겹침 처리 「담당자만 제외」 경로로 재현**(위 §2). 편집 화면의 선택기 경로는 재현 안 됨 |
| 3. 담당을 입력해도 계속 미배정 | **재현 못 함**(F: 선택기에서 입력하면 저장됨). 운영에서 어떤 화면·어떻게 입력했을 때 안 되는지 필요 |

## 4. 구현 단계에 주는 영향 (확인 요청)
1. **① 담당 보존**: 선택기 쪽(원인 A) 방어는 그대로 넣되, **실제 재현된 겹침 처리 경로**를 함께 막아야 한다. 제안: 정기점검에서 생긴 일일업무(`source_type='maintenance'`)는 「담당자만 제외」로 담당을 비우지 않는다(비울 수 없다고 안내 또는 보조 담당이 있으면 승계, 없으면 제외 불가). 다른 업무는 종전대로.
2. **② 자가복구**: 일일업무 담당이 비면 `manual`이어도 방문 담당을 복사 — 지시서 안대로 진행. 단 이 경우 사용자가 일부러 비운 경우와 구분되지 않는다. 정기점검 일일업무는 방문의 담당이 본이므로 **복사해도 된다고 보고 진행**하려 한다. 복사 뒤 `assignee_source`는 `maintenance`로 되돌려 이후 방문 담당 변경을 따라가게 하는 안을 제안한다(「manual」을 유지하면 다시 고착될 수 있음).
3. **B 부수 효과**(ID만 채워져도 `manual`이 되는 것): 담당 이름·ID가 같은데 ID만 채워진 경우는 `manual`로 바꾸지 않도록 비교를 「이름과 ID가 실제로 다른 사람으로 바뀔 때」로 좁히는 것을 ①에 포함할지.
4. 증상 3의 재현 정보(어느 화면에서 어떻게 입력했는지, 입력 뒤 화면 문구)가 있으면 알려 주세요. 없으면 ①②를 적용한 뒤 운영에서 다시 확인하는 것으로 둔다.
5. ④ 기존 데이터 보정 SQL은 지시서대로 목록 조회만 제공한다(실행은 사용자). 대상 건수는 지시서의 2건(WT-1618, WT-1631)을 그대로 쓴다.
