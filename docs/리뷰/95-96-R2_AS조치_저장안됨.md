# AS 조치 「저장」이 임시저장 안내만 보이고 끝나던 문제 (95-96 R2·R6, 95-95 §2)

작성: 2026-11-03. 지시서 파일 없음. 근거: 95-96 R2(결과 없는 세트 → `err=set_draft_N`, 재조회로 입력 유실처럼 보임) · R6(`keepPostedAsDraft`) · 95-95 §2(처리담당자 이름).

## 0단계 (코드 수정 전)

로컬 `server/data/app.db` 에는 `R2611-005` / `R2611-006` 이 없다(최신이 `R2610-045`). 같은 조치 화면 경로로 픽스처 `R2611-001` 렌더 HTML을 파싱해 `POST /as/:id/update` 했다.

| 칸 | 렌더 직후 POST | 의미 |
|----|----------------|------|
| 처리담당자 picker `assignee_user_id` | **비어 있음** (Alpine `x-for` 는 정적 HTML에 없음) | `assignee_multi=1` 만 전송 |
| 세트 `s1_assigned_to` | 값 있음 (`양기헌`) | 접수 배정 이름은 있음 |
| 세트 `s1_result_code` | **비어 있음** | 기본 「선택하세요」 |
| 최종 저장 `result_code` | **비어 있음** (사용자가 아래만 고르면 값은 여기로 감) | |
| 원인분류 `s1_cause_cat1` | **비어 있음** | |
| 작업일 `s1_work_date` | 값 있음(오늘) | |
| 근무구분 `s1_work_place` | 값 있음(`field`, 기본 외근) | 세트 1이 “있는 것”으로 수집됨 |

| 시나리오 | HTTP | `err=` |
|----------|------|--------|
| A. 렌더 그대로 「저장」 | 303 | **`assignee_required`** (`focus=assignee`) |
| B. 최종 저장 결과만 `done` | 303 | **`assignee_required`** (담당자 검사에서 먼저 막힘) |
| C. 세트 채움·결과 비움 | 303 | **`set_draft_1`** |
| D. 세트+결과 완료(+ `assignee_external`) | 303 | 없음 (저장 성공) |

확정 원인:

1. **처리담당자.** 조직관리자/지원은 picker 선택이 필수인데, Alpine이 안 돌리면 `assignee_user_id` 가 안 나간다. 접수에 이미 `양기헌` 이 있어도 `ParseSelection(Required:true)` 가 거부한다. 운영의 모든 건에서 「저장」이 같은 이유로 막힐 수 있다. 오류 문구는 폼 **안쪽** 빨간 박스이고, 화면 **위** 에는 임시저장 안내(amber)가 있어 안내만 보인 것처럼 느껴진다.
2. **결과.** 세트 `s1_result_code` 가 비면 `err=set_draft_1`. 사용자가 「최종 저장」의 `result_code` 만 고른 경우에도 세트 결과가 비어 있으면 같은 코드. `persistPostedSets` 가 폼을 다시 읽어 브리지를 타지 않으면 한 번 더 막힌다.
3. **안내 스타일.** `DraftSetN` 문구가 오류처럼 amber 였다. R2 증상과 겹친다.

원인분류·작업일은 이 경로의 1차 차단이 아니었다.

## 구현 (재지시 반영)

- **폴백:** `assignee_user_id` 키가 POST에 **없을 때만** 접수에 저장된 담당자를 유지한다. 키가 있으면(값이 있든 없든) 폼이 우선. 로그인 사용자·조직관리자 ID로 채우지 않는다. 접수도 비면 `err=assignee_required`.
- **picker hydrate (95-95 §2와 층이 다름):** 95-95는 `nameOf`/`pickerDisplayName`이 리터럴 「담당자」를 쓰지 않게 한 표시 함수다. 이번 수정은 Alpine이 부모 `preAssigneeIds`만 봐서 조치 화면에서 선택이 비던 초기화다. `assigneePicker({ ownerId, selectedIds, external })` 로 extra를 처음부터 채운다. 정적 HTML에는 `assignee_user_id` 숨은 칸을 넣지 않아 폴백 테스트와 충돌하지 않는다.
- 세트 결과가 비고 최종 저장 `result_code` 가 있으면 세트로 복사.
- `err=assignee_required` → 상단 배너 + 담당자 칸 `data-assignee-error` 「처리담당자를 선택하세요」 + 포커스. 임시저장 안내는 슬레이트 상태 문구.
