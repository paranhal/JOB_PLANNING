# 95-182 구현 보고 — 작업·행정/지원 등록의 하부 업무 선택과 사이트 다중 선택

작성: 2026-11-12. 요청: 수행 구조가 있는 사업이면 등록 때 하부 업무를 고르고, 그 하부 업무에 등록된 사이트를 「선택화면_기관별_지역_다중선택」 모양(유형·시도·시군·지역 검색·카드 다중 선택)으로 고른다. 나머지는 기존 로직 그대로.

## 사용자 결정 (답변 반영)
- 사이트 후보는 **하부 업무에 등록된 사이트**만(사업 전체 사이트가 아님).
- 수행 구조가 있는 사업이면 **하부 업무 필수**.
- 작업 계획 연결은 기존대로 **등록 후** 작업 상세의 「작업 계획 연결」에서 한다.
- 작업 등록과 행정/지원 등록은 **서로 다른 폼**이고, 사업을 고른 뒤의 하부 업무·사이트 선택만 **공통 화면**이다.
- 사업 등록의 이미지(`선택화면_기관별_지역_다중선택.png`)는 클라우드 환경에 없어, 대화에 붙인 사업 사이트 등록 화면 이미지를 기준으로 맞췄다.

## 구현 (커밋 12dba41)
- 공통 부분 템플릿 `_package_site_picker.html`(`package_site_picker`)과 `package_site_picker.js`를 작업(`wb_form_project_work`)·행정/지원(`wb_form_admin_sales`) 두 폼이 같이 쓴다. 행정/지원에서 업무 구분이 영업이면 나타나지 않는다.
- 흐름: 사업 선택 → (수행 구조 있으면) 하부 업무 선택(필수) → 유형 탭(학교·공공기관·도서관·민간업체, 개수 표시) → 시도·시군 체크 → 지역 검색 → 카드 다중 선택·전체 선택 → 「담기」 → 아래 「대상 사이트」 칩(기존 `site_id` 숨은 입력 그대로). 사업 전체 사이트 검색 입력은 하부 업무를 고른 뒤 숨긴다. 구조가 없는 사업은 기존 검색 방식 그대로다.
- 하부 업무를 바꾸면 이미 담은 사이트 중 새 하부 업무에 없는 곳은 빠지고 안내가 나온다.
- 서버 API(읽기 전용): `GET /workboard/project-packages?project_id=`(사이트형 하부 업무 목록, 수량만 하부 업무는 사이트가 없어 제외), `GET /workboard/package-sites?project_id=&package_id=`(등록된 사이트와 유형·시도·시군). 대상 사이트 검색과 같은 권한·읽기 전용 규칙이다.
- 서버 검증(업무를 만들기 전에): 수행 구조가 있는 사업인데 하부 업무가 없으면 거절, 하부 업무에 등록되지 않은 사이트가 섞이면 거절(업무가 만들어지지 않음).
- 유형은 고객 업종(학교·공공기관·도서관 외는 민간업체)으로 정한다. 사업 사이트 등록 화면의 기준과 같다.
- 기존 로직은 그대로: 사이트 최대 100곳, 설치자산, 중복 제출 방지, 하부 업무가 없는 사업의 등록.

## 시험
- repository/handler HTTP(`Test95_182_*`): 구조 없는 사업은 `has=false`, 구조 있는 사업은 하부 업무 2개·등록 2곳, 사이트 항목의 유형·시도·시군, 하부 업무 없이 저장 거절, 하부 업무 밖 사이트 거절(업무 0건), 정상 저장(하부 업무 연결, 사이트 2곳), 구조 없는 사업 저장, 두 폼에 공통 선택이 들어 있음. JS 단위(유형·시도·시군 필터, 검색, 전체 선택, 최대 개수, 하부 업무 변경 시 제외).
- 실제 브라우저(작업·행정/지원 각각): 사업 선택 전에는 안 보임 → 사업 선택 후 하부 업무 필수 → 후보 2곳·유형/시도/시군 → 검색 → 전체 선택·담기(숨은 `site_id` 2개, `package_id`) → 구조 없는 사업으로 바꾸면 사라짐. 390px에서 가로 넘침 없음. 스크린샷 `docs/리뷰/screenshots/95-182/`.
- 잡은 문제: 일부 시험은 템플릿 파일 목록을 따로 들고 있어 새 부분 템플릿이 없다는 오류(`no such template`)가 났다. 목록에 추가했다.
- 전체 게이트: **통과 2732 / 실패 7**(기존에 알려진 `TestNewTestFilesDoNotCallTimeNow`, `TestWorkSelfReview*` 3건, `TestWorkToday*` 3건). `known_failures.txt` 추가 없음.

## 남은 것
- 작업 계획(3단계) 선택은 등록 후 기존 「작업 계획 연결」에서 한다. 등록 때 계획까지 고르는 것은 이번 범위가 아니다.
- 사업 등록 이미지 원본은 이 환경에 없어 붙여 준 화면을 기준으로 맞췄다. 원본과 다른 점이 있으면 알려 달라.
- 수정 화면(업무 수정)에서 하부 업무·사이트를 바꾸는 흐름은 이번에 건드리지 않았다.
