# 95-113B 보완

기준: 95-113(4323e2c) 보고 확인 후 4건. 지시서 2-E·2-B. 커밋 한 건.

## 한 일

1. AS 업무 등록 모달 대기 AS 목록 옆에 **목록 새로고침**. `GET /workboard/new-work/as-cards` JSON으로 목록만 다시 받고, 선택·검색어·모달 입력은 유지한다.
2. **AS 접수 추가**를 `<button type="button">` + `window.open('/as/new','_blank','noopener')` 로 바꿨다. 새 탭이 막히면 같은 탭으로 보내지 않고 안내 문구만 보여 준다. 조회 다이얼로그의 「접수 추가」도 같다.
3. 점검 수정 모달: `data-project-name` + `hydrateEditProject`로 Alpine 피커에 현재 사업을 넣는다. 모달을 열면 「선택: 이름」이 보인다. 폼에 `project_id` 키가 없으면 기존 `project_id`를 유지한다(HTTP·렌더 테스트).
4. 통계·사업별 집계에서 `project_match_pending=1` 업무를 빈 사업 버킷과 같은 자리에서 **사업 미매칭**으로 분리했다. 대시보드 KPI, `CountProjectActivities`, 주간보고 `SplitCompanyUnassigned`.

## 지시와 다른 점

- 95-113에서 지시서 2-E 2번 「목록 새로고침」이 빠진 이유: 저장 피커·pending·콤보 버그·AS 클릭 재현에 맞춰 범위를 잘랐고, 대기 목록 새로고침은 후속으로 미뤘다. 이번 커밋에서 넣었다.
- AS 접수 추가의 운영 95-106 무반응은 코드의 `<a>`만의 문제가 아닐 수 있어, 코드 이중 안전과 운영 빌드 점검을 나눴다.

## 운영 빌드 점검 (AssetQuery · 배포 이미지)

모달이 쓰는 JS는 `as-register-lookup.js`, `mnt-quick-register.js` 이다. 템플릿에 `?v={{.AssetQuery}}` 를 붙였다.

`AssetQuery()`(`server/internal/handler/buildinfo.go`)는 `version + "-" + built` 이다. 빌드 시각·버전이 바뀌면 질의문자열이 바뀌어 브라우저 캐시를 탄다.

확인 방법:

1. 배포 이미지에서 앱을 띄운 뒤 로그인 HTML 소스에 `/static/js/as-register-lookup.js?v=` 값이 있는지 본다.
2. 같은 값을 `/version` JSON의 `version`·빌드 시각과 대조한다. 이미지가 새로 구워졌다면 `v=` 가 이전 배포와 달라야 한다.
3. 컨테이너에서 `grep as-register-lookup.js` 로 이미지 안의 템플릿·정적 파일이 이번 커밋을 포함하는지 본다. `v=` 가 없고 예전 JS면 이미지가 오래됐거나 정적 파일이 복사되지 않은 것이다.
4. 브라우저 개발자 도구 Network에서 해당 JS가 200(또는 캐시)인지, 응답 본문에 `openASReceiptTab` / `refreshASWaitingList` 가 있는지 확인한다.
