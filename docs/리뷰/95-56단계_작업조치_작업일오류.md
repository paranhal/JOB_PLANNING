# 95-56단계 — 작업 조치 저장 시 「작업일을 입력하세요」

기준: `커서_작업지시서_95-56_긴급_작업조치_저장_작업일_입력하세요_오류.md` (D-201).  
선행: 95-11A(534d57c0) 이후 조치 템플릿에서 `work_date` 입력 제거. 실행일: 2026-10-26. 배포 이미지는 요청 시에만.

## 원인 재현

`applyProjectWorkActionForm` 이 `FormValue("work_date")` 를 필수로 요구했다. 화면 `workboard/project_work_action.html` 에는 해당 `name` 이 없다(좌측 「작업일」은 표시만). 기존 HTTP 테스트 4건은 폼에 없는 `work_date` 를 직접 넣어 통과했다.

`Test95_56_RenderedFormPostWithoutWorkDate` 가 GET 한 HTML 의 `#as-action-form` 을 파싱해 `work_date` 없이 POST 한다.

```
REPRO_BEFORE form_has_work_date=false
REPRO_BEFORE 수정 전 검사: FormValue(work_date)="" → pwActionErr{work_date}
  → Location=/workboard/tasks/WT-001/action?err=work_date
REPRO_AFTER status=303 loc=/workboard/tasks/WT-001/action?back=%2Fworkboard%2Fboard&ok=saved
```

수정 전: 완료·추가조치·이관 저장이 항상 `err=work_date` 리다이렉트. 입력값이 사라지고 오류는 화면 맨 위 한 줄.

## 수정

- 작업일: 폼 값(예전 클라이언트) → `t.WorkDate` → `complete_datetime` 의 날짜. 셋 다 비면만 `work_date`.
- 완료일시가 작업일보다 이전이면 막지 않고 확인 안내. `confirm_complete_before_work=1` 이면 입력값 그대로 저장. 빈 완료일시는 현재 시각(기존).
- 조치 저장 실패는 리다이렉트하지 않고 같은 화면을 입력값 유지해 다시 그림. 저장 바 위·필드 옆 오류, 해당 필드로 포커스. `pwActionErr` 전 코드 동일. 잠금 해제(`unlock_password`)는 기존 리다이렉트.
- 결과 라디오 초안은 `FormResult` 로만 표시. `t.ResultCode=done` 을 덮으면 닫힌 건으로 오인되어 폼이 사라졌다.
