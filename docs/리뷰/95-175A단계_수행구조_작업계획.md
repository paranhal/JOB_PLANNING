## 권한

단계·하부 업무 수정은 `canDesignProjectWork` 만 쓴다. 수행 담당은 빠진다. 계획 생성·상태·삭제·사이트 이동은 `canManagePlans`(같은 권한 + 수행 담당 `duty=execution`)다. 읽기 전용·C-Level·옵저버·view-as 는 버튼이 없고 POST 는 403. 다른 조직 사업에 계획을 쓰는 요청은 404 또는 403.

## 테스트·브라우저

저장소 `Test95_175A_PlanCRUDAndSearch`, `Test95_175A_MergePlansOnly`, `Test95_175A_ProgressQueryCap`. 모델 `Test95_175A_FormatCommaAndMatch`. HTTP `Test95_175A_StructureHTTP`. 95-120P HTTP 도 같이 통과했다.

## 코드 확인 중 생긴 질문

설계서 §10 의 7건과, 이번에 받은 ①기본 단계명 유지 ②구조 수정은 `canDesignProjectWork` ③유지보수 접기 ④단계 담당자 없음 은 반영했다. 다시 묻지 않는다.

1. 「미분류 작업」「계획 미배정」은 패키지가 있을 때만 보여 준다. 지시의 「항상」과, 구조 없는 사업을 120P 와 같게 두는 요구가 겹쳐서 후자를 택했다.
2. 계획이 없는 통합에서 같은 이름 단계가 지워지면, 그 단계에만 매달린 하부 업무(계획 없음)는 따라가지 않는다. A 는 계획이 있을 때만 하부 업무를 다시 붙인다.
3. 페이스 칩은 `PlanPace` 를 쓰지만 일 실적은 B 단계라, 지금은 「판정 전」만 나온다. 영업일은 `service.Calendar` 이고 개인 휴가는 보지 않는다.
4. 계획 진행률은 `package_sites` 의 완료 수와 수량 인식이다. 95-119 `TaskSiteCheckRate` 는 작업에 묶인 사이트 체크라 분모가 다르다. 분모 0 은 `—`. 설치·검수 건수와 문구를 섞지 않았다.
5. 「다른 사업에서 구조 복사」POST(`/projects/:id/structure/copy`)는 단계·하부 업무만 복사한다. 빈 사업 화면에 입력 칸을 두면 120P 와 달라져 화면에는 두지 않았다.
6. down 은 새 표만 지운다. `project_phases` 에 더한 열과 `work_tasks.package_id`·`plan_id` 는 SQLite 한계로 남긴다.
