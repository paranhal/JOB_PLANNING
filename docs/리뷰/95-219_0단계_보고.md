## 4. 다중 값에서 의미 충돌이 나는 곳 (결정 필요)
1. **「업종 하나로 분기」하는 곳**: 사이트 유형 판정(#14·16)과 기본 사이트 유형(#15).
   - 기본안 「포함하는 업종 중 하나라도 맞으면 해당 규칙」은 **둘 이상일 때 어느 규칙을 쓸지 정하지 못함**. 제안: **고정 순서(도서관 → 학교 → 공공기관 → 민간) 중 첫 번째**를 대표 유형으로 쓴다(저장 순서와 같아 예측 가능). 예) `도서관,학교` → 도서관.
   - 후보 목록(#11)은 포함 판정이라 문제 없이 양쪽에 나온다.
2. **통계 합계**: 다중 고객은 각 업종에 1번씩 → 합계가 고객 수보다 큼(지시서 기본안). 화면에 한 줄 안내.
3. **업종 필수**: 현재 서버는 업종을 **검사하지 않는다**(별표만 있음, 빈 값 저장 가능, 가등록·영업 승격 등은 업종 없이 만든다). 지시서의 「필수 유지」를 **서버 검사로 새로 넣을지**, **표시만 유지(검사 없음)** 할지 정해야 한다. 서버 검사를 새로 넣으면 기존에 비어 있던 고객을 수정할 때 업종을 강제로 고르게 되는 동작 변경이다. **제안: 검사 없이 현행 유지(별표 표시만)** — 기존 동작을 바꾸지 않고, 원하면 후속으로 검사.
4. **기동 시 `UPDATE`(#18)**: 「기관명에 도서관이 들어가면 업종을 도서관으로 통일」은 다중 값을 되돌린다. **제안: 이 보정은 업종이 비었거나 도서관이 포함되지 않은 경우에만 실행**하도록 조건 변경(기존 단일 값 결과는 동일). 다만 이 보정 자체가 「학교 이름에 도서관이 들어간 고객」을 도서관으로 덮는 기존 동작이어서, 다중 선택으로 학교를 함께 고른 고객은 보존됩니다.
