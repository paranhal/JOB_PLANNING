# 95-87 — 사업 등록 조직 오류 + 주관 부서 선택·이관 + 유관 부서

## 원인 재현
SI 조직관리자가 영업 사업 등록 → 수주·계약 → `POST /sales/:id/promote` 하면, 예전에는 `ParseWorkProjectForm`이 `OrgID`를 비워 두고 `ProjectRepo.Create`가 **O01(도서관사업팀)** 으로 보정했다.

수정 후 `Test95_87PromoteSIOrgNotLibrary`: 전환된 `work_projects.org_id == O03`(영업 사업과 같음). 폼에 주관/유관 표시. 조직관리자가 `org_id=O01`을 넣어도 홈 조직(O03)으로 저장.

| 위치 | 수정 전 | 수정 후 |

시드·테스트가 Create 보정에 기대던 건이 많아, 테스트 `WorkProject`/`SalesProject` 생성에 `OrgID`를 명시했다.

## 마이그레이션
`100_work_project_orgs.sql` / `.down.sql`. `share_to` 있는 `is_shared=1`만 유관 백필. 전 팀 공개(`share_to` 빈 값)는 조회 전용 유지(Q-1).

## 불일치 후보 SQL (읽기 전용, 자동 변경 없음)

```sql
SELECT wp.project_id, wp.name, sp.sales_id, sp.org_id AS sales_org, wp.org_id AS work_org
  FROM work_projects wp
  JOIN sales_projects sp ON sp.sales_id = wp.sales_project_id
 WHERE TRIM(COALESCE(sp.org_id,'')) != ''
   AND TRIM(COALESCE(wp.org_id,'')) != ''
   AND TRIM(sp.org_id) != TRIM(wp.org_id)
 ORDER BY wp.project_id;
```

운영 DB는 이 세션에서 열지 않음. 사용자가 이관으로 바로잡는다.

## Q-1~Q-4
기본값 적용. 전 팀 공개=조회만. 유관=업무 등록·조회만. 업무 org=등록자 조직. 부문 일괄 선택은 95-77.
