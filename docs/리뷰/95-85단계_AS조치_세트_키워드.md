## 95-78A · 95-82 겹침

- 95-78A §1 AS 조치·하부 조치의 작업 구간 템플릿은 **95-85가 대체**. `Test95_78A_ActionHTMLShowsTwoSegments`는 AS 화면에 구간이 **없음**으로 바꿨다. 정기점검 방문 조치·작업 조치는 구간 유지.
- 95-82 작업 리스트는 AS 조치 화면에서만 제거. `project_work_action` 유지.
- `savePostedActionSegments`: `seg_start` 없으면 기존 구간을 지우지 않음.

## Q-1~Q-5 기본값

- Q-1: 마지막 조치 결과만 상태·부수효과에 반영 (`asActionSideEffectRuns` 최종 저장 1회, 임시 저장 0).
- Q-2: 결과 선택 시 임시 저장 + 「임시 저장」 보조 버튼. 주기적 자동 저장 없음. `beforeunload`만.
- Q-3: 새 키워드 그룹은 규칙 추정. 사용자는 체크 해제 또는 직접 입력으로 정정.
- Q-4: 자재·고객확인자·같은 조치 적용은 접수 단위.
- Q-5: 「철수 시간 동일」 기본 체크. 외근에서 해제 시 철수 필수. 자정 넘김 거부. 시작·작업 시간은 선택.

## 지시서와 다른 점

- 원인 2·3차는 세트마다 텍스트 입력(전체 캐스케이드 UI는 숨은 래퍼 ID만 유지해 95-65 테스트 호환).
- 처리유형·근무구분 미러 필드를 폼에 남겨 기존 POST(`work_place`/`process_type`)와 단일 세트 회귀를 유지.
- JS의 완료시간 계산은 화면 즉시 반영용. 저장·표시 포맷의 단일 소스는 `FormatKoreanTime`.
- 조치 사진 `action_set_id`는 업로드 폼에 실으나, 세트 여러 개가 한 첨부 폼을 공유하면 마지막 열린 세트 ID가 우선(세트별 전용 업로드 UI는 후속).
- `/as/:id/update` 부수효과는 `ActionApplyInput`을 받는 기존 `ApplyActionResult` 경로를 그대로 1회 사용(핸들러 전체 추출 대신 입력 구조체 재사용).
