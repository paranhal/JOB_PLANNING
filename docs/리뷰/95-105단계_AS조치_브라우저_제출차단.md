# 95-105 — AS 조치 저장이 브라우저에서 막힘

작성: 2026-11-03. 운영 배포는 하지 않았다.

## 0단계 (수정 전, Playwright 실제 클릭)

픽스처 `95_105_save_block_diag.html`: 접수 `action_taken` 빈 값, 세트 `.as-set-text` 는 채워짐, `#as-action-taken` 에 `required` 를 JS 가 붙임(구 `ta.required = !on`). 저장 버튼은 폼 밖 `form=` 연결.

| 항목 | 결과 |
|------|------|
| `form.checkValidity()` 클릭 전/후 | `false` / `false` |
| `:invalid` | `#as-action-taken` (`name=action_taken`, `required`, 값 `""`, `hidden`, `display:none`) |
| `#as-action-taken` 값 | 클릭 후에도 `""` (`mirrorLast` 미실행) |
| 콘솔 | `[]` (headless Chrome 이 `An invalid form control … not focusable` 를 남기지 않음) |
| 네트워크 POST | `[]` |

원인: 숨은 필수 textarea 가 HTML5 검증에서 제출을 막는다. `submit` 이벤트가 없어 `mirrorLast()` 가 세트 본문을 옮기지 못한다. 화면에는 임시 저장 안내만 남는다.

## 수정

- (a) `#as-action-taken` 에 `required` 를 두지 않는다. 접힌 세트 원인칸(`as_action_set_cause.js`)도 HTML5 `required` 를 붙이지 않는다. 숨은 `visit_date` / `process_type_reason` 도 동일.
- (b) 저장 버튼 클릭 capture 단계에서 `prepareSubmit()` → `mirrorLast()` + 숨은 `required` 제거.
- (c) 「조금 더…」·다른 접수 확인 뒤 `prepareSubmit` 하고, `submit` 이벤트 안에서 바로 `requestSubmit()` 하면 명세상 무시되므로 `setTimeout(0)` 뒤에 `requestSubmit()` (없으면 `submit()`).
- (d) 짧은 본문 판단은 마지막 `.as-set-text`.
- (e) `invalid` / 빈 결과: 세트를 펼치고 칸에 포커스, `#as-action-client-err` 문구.
- (f) `keepPostedAsDraft` 유지 (95-96 R6).
