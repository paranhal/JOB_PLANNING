### ② 중복 원인 (이번 미수정)

운영 DB는 이 작업에서 조회하지 않음. 칸반 `+ 업무 등록` → `js-keep-modal` fetch는 제출 버튼을 잠깐 막지만 `finally`에서 다시 켜고, 서버 `submit_token` 멱등이 없다. 더블 클릭·재시도로 같은 행정 업무가 여러 건 생길 수 있다.

후속: 등록 fetch가 끝날 때까지 버튼을 잠그고, `submit_token`으로 같은 제출을 한 번만 받기. **이번 범위에서 구현하지 않음.**

### ③ └ 행

`paletteTaskCard`가 `ParentTaskID` 있으면 제목 앞에 `└ `. 하위 업무 표시. 반복 실행분(`recurrence_role=occurrence`)은 별도로 삭제 불가(상위 일정). 하위가 있는 상위는 `CountSubtasks>0` 이라 삭제 불가.

### ④ bulk-delete 규약 · JS 재사용

- CSRF: `jp_csrf` 쿠키 + form `csrf` / `X-CSRF-Token`. JSON은 `Accept: application/json`.
- 미리보기 `{deletable, skipped}`, 확정 `{deleted, skipped}`. 최대 200.
- `work_list_select.js`는 CSRF·preview fetch만 재사용. 단건 모달·Esc·포커스·카드 제거·건수 갱신은 `unplaced_delete.js`. 확정은 페이지 리로드 없이 JSON POST. 감사 사유 폼 `reason=미배치 업무 삭제`(허용 목록만, 규칙 함수 변경 없음).
