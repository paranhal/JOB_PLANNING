## ① 시기 기준이 쓰이는 곳

### `SalesYMOf` (`server/internal/model/sales_forecast.go`)

| `basis` | 컬럼 |
|---------|------|
| `contract` | `ContractedAt` |
| `won` | `WonAt` |
| `bid` | `BidYM` |
| `plan` | `ExpectedYM` (사업 시기) |
| **그 외(빈 값·`revenue`·오타)** | `RevenueYM` (매출 시기) |

미정 판정은 `BuildSalesForecast`에서 `ym := SalesYMOf(...); un := ym == ""`. 카드·행렬 미정 열·엑셀이 이 `Unsched`를 쓴다.

### `BuildSalesForecast` / `DefaultForecastOpts`

- `DefaultForecastOpts`: `Basis: "revenue"`, From=이번 달, To=+11개월.
- `BuildSalesForecast`: `opts.Basis == ""` 이면 `"revenue"`. **알 수 없는 값은 여기서 고치지 않고** `SalesYMOf` default(매출)로 떨어진다.
- 핸들러 `renderSalesPipeline`: 쿼리 `basis`가 **있을 때만** 덮어씀. `/sales?view=pipeline`(파라미터 없음) → 매출 시기.

호출: `sales_pipeline_xlsx.go` 화면·엑셀 공통. 테스트 `TestBuildSalesForecastToleratesBadYMAndOrphanQuote`는 기본 opts(매출)로 빈·짧은 YM을 미정으로 본다.

### `sales_pipeline.go` ExpectedYM 고정

| 함수 | 사용 | 화면 |
|------|------|------|
| `BuildSalesPipeline` ~331 | `NormalizeSalesYM(p.ExpectedYM)`, 빈값 키 `unscheduled` 라벨 「미정」 → `Pipe.Months` | **파이프라인 화면에 없음.** 대시보드는 `Pipe.Stages`만. `Months`는 테스트 `TestBuildSalesPipelineMetrics`만 |
| `BuildSalesTimelineAxis` ~494·523 | `ExpectedYM` | 목록 **예정월 타임라인** (`list.html`) — 파이프라인 view 아님 |
| 칸반 정렬 (`sales_board.go`) | `ExpectedYM` | 단계 칸반 — 이번 지시 범위 밖 |

### `pipeline.html`

- 부제 `기준 {{.BasisLabel}}`.
- 엑셀 링크에 현재 `basis=` 명시.
- select 순서: **매출 → 계약 → 수주 → 입찰 → 사업**. 라벨은 짧은 말(「매출」). `ForecastBasisLabel`과 불일치.
- 카드 「시기 미정」: `Summary.UnschedN/UnschedAmt`. **어떤 시기가 비었는지는 안 씀.**
- 표 「기준 시기」: `Unsched`면 `—`.
- 행렬 「미정」 열: `Matrix` (같은 forecast).
- 미정 행 클릭 안내·수정 링크 **없음**(번호만 `/sales/:id`).

### 엑셀 (`writePipelineXLSX`)

- 같은 `DefaultForecastOpts` + 쿼리 `basis`.
- 조건 문구: `기준: %s · …` (`ForecastBasisLabel`). 기본이면 「기준: 매출 시기 · …」.
- 시트 「월별 합계」= `fc.Matrix` (예측과 동일). 「미정」 열 있음.
- 목록 시트는 `ExpectedYM`·`RevenueYM` 등을 **둘 다 컬럼으로** 찍고, 집계 월은 `Basis`를 따름.

### 이번 단계가 아닌 곳

목록 필터 `period=`·그룹 from~to·`SalesMissingInfo` 「시기」·등록 폼 `expected_ym`/`revenue_ym`. 스키마·자동 채움 없음.

## ② 월별 합계와 예측 표/카드가 다른 시기를 쓰는가

**파이프라인 화면(`/sales?view=pipeline`)과 엑셀 「월별 합계」는 같은 `BuildSalesForecast`다.** 카드·표·행렬이 갈라지지 않는다.

어긋남은 **기본 basis=매출** vs **담당자가 넣는 사업 시기**, 그리고 쓰이지 않는 `BuildSalesPipeline.Months`(사업 시기 고정)이다.

가정: 진행 중·금액 1,000만·기간 기본(2026-11~2027-10). 휴면·실주 아님.

| 건 | 사업 시기 `ExpectedYM` | 매출 시기 `RevenueYM` | 파이프라인 기본(매출) 카드·표·엑셀 | 파이프라인 `basis=plan` | `BuildSalesPipeline.Months` (화면 미표시) | 95-134 보완 필요 「시기」 |
|----|------------------------|----------------------|-------------------------------------|-------------------------|------------------------------------------|---------------------------|
| A 사업만 | `2026-11` | (빈) | **시기 미정** 1건. 11월 칸 0 | 2026-11 칸에 1,000만. 미정 아님 | `2026-11` | 채워짐 → 시기만으로는 보완 목록에 안 잡힘 |
| B 매출만 | (빈) | `2026-11` | 2026-11 칸. 미정 아님 | **시기 미정** | 「미정」 버킷 | **시기 공란** → 보완 필요(다른 항목 OR) |
| C 둘 다 | `2026-11` | `2027-04` | **2027-04** 칸 (매출). 11월 0 | **2026-11** 칸. 4월 0 | `2026-11` | 채워짐 |
| D 둘 다 없음 | (빈) | (빈) | 시기 미정 | 시기 미정 | 「미정」 | 시기 공란 → 보완 필요 |

지금 담당자 체감(A): 사업 시기만 넣었는데 파이프라인 기본이 매출이라 「시기 미정」.

**T7 통일 제안(확인 사항):** 파이프라인 화면은 이미 한 함수라 숫자 불일치는 없다. `BuildSalesPipeline.Months`를 `SalesYMOf`로 바꾸면 대시보드가 나중에 월을 붙여도 맞고, 기본 `plan`이면 A/C와 파이프라인 기본이 같다. 지시 3-B 「별도 확인 후」이므로 **이번 구현에 넣을지 확인**이 필요하다. 타임라인·칸반은 이번 금지 범위로 두는 것을 권한다.

참고: forecast는 휴면·실주·중단을 빼고, `BuildSalesPipeline` 단계는 실주도 센다. 월 버킷을 맞춰도 **단계 합계와 예측 진행 합은 다를 수 있다.**

## ③ basis 값·라벨·URL

| 값 | `ForecastBasisLabel` | 지금 select 문구 | 기본인가 |
|----|----------------------|------------------|----------|
| `plan` | 사업 시기 | 사업 (맨 뒤) | 아니오 |
| `revenue` | 매출 시기 | 매출 (맨 앞, 미지정과 동일) | **예** |
| `contract` | 계약 시기 | 계약 | 명시 시만 |
| `won` | 수주 시기 | 수주 | 명시 시만 |
| `bid` | 입찰 시기 | 입찰 | 명시 시만 |
| `""` / 오타 | (코드상 매출) | — | 매출로 떨어짐 |

- 즐겨찾기 테이블·저장된 보기 **없음**.
- 메뉴·테스트는 `/sales?view=pipeline` (**basis 없음**) → 기본값 변경의 영향 범위. `basis=revenue`가 붙은 북마크·엑셀 링크는 **기존 매출 유지**(지시와 같음).
- 엑셀 버튼은 현재 화면의 `basis`를 URL에 넣는다. 기본 화면에서 엑셀을 받으면 지금도 `basis=revenue`가 쿼리에 실린다(핸들러가 Default를 넣은 뒤 템플릿에 넘김). **구현 후** 같은 경로면 `basis=plan`이 실릴 것.
- 알 수 없는 `basis=foo`: 지금은 매출. 지시는 **plan**. 명시적 동작 변경.

구현 시 손댈 곳(확인 후): `SalesYMOf` default, `BuildSalesForecast` 빈 값(+오타 정규화), `DefaultForecastOpts`, `pipeline.html` select 순서·`ForecastBasisLabel` 재사용, 카드 제목, 미정 안내 링크, 엑셀 조건 문구는 라벨 함수만 따라가면 됨.

회귀: `TestBuildSalesForecastToleratesBadYMAndOrphanQuote`의 정상 행은 Expected·Revenue가 같아 기본 변경에 버팀. A유형 단언은 T1로 새로.

## 95-134 보완 필요와 일치

`SalesMissingInfo` 「시기」=`ExpectedYM` 공란 (`ListRelevant`).

기본을 `plan`으로 바꾸면 **파이프라인 「시기 미정」 집합 ⊆ 보완 필요(시기 공란)** 이 된다(휴면·종료는 예측에서 빠지고 보완 박스도 숨김).  
`basis=revenue`로 보면 B처럼 매출만 있는 건은 파이프라인에 월이 있고 보완 목록에는 시기가 빈 채로 남을 수 있다 — **선택한 기준이 사업 시기일 때만** 지시 3-C와 같다.

안내 문구 「사업 시기를 입력하면…」은 기본·`plan`에 맞고, 매출 기준 미정에는 「매출 시기를 입력하면…」이 카드 제목과 맞다.
