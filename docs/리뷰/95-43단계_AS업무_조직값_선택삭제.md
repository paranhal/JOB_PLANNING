# 95-43단계 — AS 연동 업무 조직값(org_id) 누락·타 조직 판정·AS 관리 선택 삭제

기준: `커서_작업지시서_95-43_긴급_AS업무_조직값_오류_타조직판정_AS관리_선택삭제.md`  
선행: 95-42. 실행일: 2026-10-25.

## 한 줄

`SyncASDailyTask`가 `work_tasks.org_id`를 비워 `CreateTask`가 O01로 넣었고, 선택 삭제는 그 값을 보고 SI 조직관리자에게 「타 조직 업무」로 거부했다. 동기화·보정·AS 접수 `org_id` 기준 판정·`/as` 선택 삭제로 고친다. **배포 후 마이그레이션 적용 전에 운영 DB 백업**을 받을 것.

## 원인 재현

1. `wb_as_sync.go` `SyncASDailyTask`의 `model.WorkTask{…}`에 `OrgID`가 없었다.
2. `WBRepo.CreateTask`는 OrgID가 비면 `RequireInsertOrg` → **O01(도서관)** 기본값.
3. 95-42가 `as:` 키로 `GetTaskBySource`를 쓰면서, 잘못된 `work_tasks.org_id`가 `listDeleteBlockReason`의 첫 조직 비교에 걸렸다.
4. 부가: `ASRepo.GetByID`가 `ar.org_id`를 SELECT/Scan하지 않아, 접수 기준 조직 판정이 빈 값이면 조직 검사를 건너뛰었다. 이번 단계에서 `COALESCE(ar.org_id,'')`를 넣었다.

재현 테스트: `TestSyncASDailyTaskOrgIDFromReceipt` — SI(O03)·미디어(O02) 접수를 **실제 `SyncASDailyTask`**로 만들면 `work_tasks.org_id`가 각각 O03/O02. (수정 전이면 O01.)

오염 복구: `TestCorrectWorkTaskOrgFromSourceIdempotent` — 업무를 O01로 덮은 뒤 보정 1건(O03), 2회 실행 0건.  
`Test95_43_PollutedASTaskDeletesByReceiptOrg` — 보정 전이라도 `si_admin` 미리보기/삭제는 `as_receipts.org_id`로 통과.

## 조직별 보정 건수

`CorrectWorkTaskOrgFromSource` / `applyWorkTaskOrgFromSourceV87`(기동 시 멱등).

| 환경 | 결과 |
|------|------|
| 단위 테스트 (오염 1건 O03) | 1차 **1건 `{O03:1}`**, 2차 **0건** |
| 운영 복사본(95-21) | 이 작업에서 실측하지 않음. **배포·기동 로그 `087 work_task org_id: 보정 N건 map`** 을 남긴 뒤 리뷰에 붙일 것. 적용 전 백업 필수 |

정안초 건은 접수가 O03이면 업무 org_id가 O01→O03으로 맞춰진다.

## 권한 표 (삭제)

자기 조직 `org_admin`은 담당자·완료·조치 이력과 무관하게 같은 조직 AS를 삭제한다. 연결 접수는 번호와 함께 거부. 「타 조직」은 조직명을 붙인다.

| 주체 | 자기 조직 AS | 타 조직 AS | 직접 등록 업무(자기 조직) |
|------|--------------|------------|---------------------------|
| 비전관리자 | 가능 | 가능(OrgAll) | 가능 |
| 자기 조직 org_admin | 가능(담당 무관, 완료·조치 포함) | 거부 + 조직명 | 가능(`canEditTask` 조직장) |
| 타 조직 org_admin | — | 거부 + 조직명 | 거부 |
| support(95-36) | 접수자 규칙만(처리 전). 조직장 아님 | 거부 | 기존 `canEditTask` |
| 접수자 | 처리 전만 | 거부 | 해당 없음 |
| 담당 tech | 불가 | 거부 | 본인 담당만 |
| c_level | 읽기 위주 불가 | 거부 | 기존 규칙 |

확인: `Test95_43_OrgAdminDeletesOthersCompleteWithProcess`, `Test95_43_OtherOrgNamedReason`, 95-38/42 매트릭스.
