# 95-42단계 — 선택 삭제: AS 합성 행 체크박스 값(`as:`/`task:` 키)

기준: `커서_작업지시서_95-42_긴급_선택삭제_AS행_체크박스_값_비어있음.md`  
선행: 95-41. 실행일: 2026-10-25.

## 한 줄

v95-41에서 정안초 AS를 골라 「확인 결과를 받지 못했습니다」가 뜬 것은 CSRF가 아니라, 리스트 합성 AS 행의 `Task.TaskID`가 비어 체크박스 `value=""`가 되고, `formIDList`가 빈 값을 버려 **200 + deletable/skipped 0건**이 된 탓이다. 행마다 `DeleteKey`(`as:<접수ID>` / `task:<TaskID>`)를 쓰고, 유효 id 0개면 400을 돌려준다.

## 원인 로그

1. 95-41 가드는 선택 N인데 `deletable+skipped==0`이면 위 문구를 띄운다. 상태 코드 접미사가 없으므로 HTTP 200 + 빈 본문이다.
2. `BulkDeletePreview`는 id마다 deletable 또는 skipped에 넣는다. 둘 다 0이면 서버가 받은 유효 id가 0개.
3. `workListToBoardItem`의 `WorkPrefixAS` 분기는 `SourceType`/`SourceID`만 채우고 `TaskID`는 비운다. 템플릿이 `value="{{.Task.TaskID}}"`라 AS 행은 `value=""`.
4. 95-39~41 테스트는 `work_tasks` 실제 행(TaskID 있음)이라 합성 경로를 타지 않았다.

재현: `Test95_42_WorkListToBoardItemASKeyNotEmpty` — 합성 AS의 `Task.TaskID==""`, `DeleteKey==as:<RefID>`.

## 수정

- 서버가 행마다 `DeleteKey` 계산. AS는 `as:<SourceID>`, 직접 등록은 `task:<TaskID>`. 정기점검·영업·확인/지원은 키 없이 비활성 + 사유.
- 템플릿: `CanDelete && DeleteKey`일 때만 활성 체크박스. 빈 `value` 금지.
- 미리보기/삭제가 `as:`/`task:` 파싱. 접두 없는 값은 예전 TaskID. `as:`는 `work_tasks`가 없으면 AS 조회로 합성 `WorkTask`를 권한 판정에 씀. 같은 접수는 한 번만 삭제.
- 받은 id는 있는데 유효 id가 0개(또는 아예 없음)이면 `400 {"error":"삭제 대상 ID 가 비어 있습니다"}`.
- JS: 체크된 칸의 `value`가 비면 fetch 없이 「선택한 항목의 삭제 대상을 확인할 수 없습니다」. 200인데 결과가 비면 ID가 비었을 수 있다는 문구.
