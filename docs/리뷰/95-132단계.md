## 2-1. board vs register 일 보기·칸반

| | `/workboard/board` | `/workboard/register` |
|--|--|--|
| 핸들러 | `WorkboardHandler.Board` → `personalBoardData` | `WorkboardHandler.Register` |
| 일 템플릿 | `board_day.html` + `_board_bar.html` + `_board_unplaced.html` + `board_schedule.js` | `register.html`(인라인 Alpine) + `_register_state.html` + `_palette.html` |
| 칸반 템플릿 | `board_kanban.html` 열: 지연 / 진행중(일정 외) / 오늘의 업무[계획·진행중·부분완료·완료] | `register.html` `display=kanban`: 미계획업무 / N/N 예정 / 진행중 / 지연 / N/N 완료 |
| 칸반 POST | `/workboard/board/kanban-move` → `BoardKanbanMove` (`service` board 열) | `/workboard/register/kanban-move` → `RegisterKanbanMove` / `applyRegisterKanbanMove` (5열 `WorkBucket*`) |
| 일정 데이터 | `collectBoardEntries`: `ListTasksBetweenForOrg` + `ListTasksWithProcessBetweenForOrg`(95-127) + 미배치 팔레트 | `ListTasksBetweenForOrg` + `registerPalette`(AS·점검·행정·영업 대기) + `UnassignedCards` |
| 일 그리드 | 담당자별 열 **또는** `cols=flat` 한 줄. 시간 미정 줄. 미배치는 주·월만 `_board_unplaced`(유형 칩 있음). 일 보기 오른쪽 대기 패널 **없음** | 담당자별 열, 「날짜 미정」·시각 미기재, 오른쪽 「단위 업무별 대기」+「미계획업무」+「등록」. 지난날 잠금·겹침·끌기 |
| JS | `board_schedule.js` | register.html 내부 `place()` / `pick()` |

**공용화 제안 (register.html 무변경):**

1. **복사 + 리다이렉트** — board용 새 템플릿(`board_schedule_day.html` 등)에 register 일·칸반 **마크업을 복사**하고, `redirect`/`POST`만 `/workboard/board?...`로 둔다. `register.html`·`Register()`·기존 register 테스트는 손대지 않음. 드리프트 위험은 있으나 **무변경 보장**이 가장 확실하다.
2. **부분 추출은 register를 고치게 됨** — `_register_state.html`·`_palette.html`은 이미 공용. 그리드·칸반 본문을 partial로 빼려면 `register.html`을 `{{template}}`로 바꿔야 해서 **금지**.
3. **같은 템플릿을 Board가 렌더** — 제목·메뉴·URL이 register로 남거나 조건 분기가 register에 들어가 **금지**.

쓰기·ACL·잠금: `registerPastDayLockEnabled`, `CanWrite`, `CanUnlockPast`, `POST /workboard/schedule`은 **핸들러 재사용**(redirect만 board). 칸반 이동은 **register 5열 규칙**을 board URL로 쓰도록 `RegisterKanbanMove`에 redirect 허용(register 기본 redirect는 현재 하드코드 `/workboard/register?...` — board에서 **별도 POST 래퍼**를 두면 register 파일을 안 고침).

**예상 변경 파일 (구현 시, 이번 조사는 미수정):**  
`workboard_board.go`, `parseBoardView`, `board_day.html`/`board_week.html`/`board_month.html`/`board_kanban.html`, `_board_toolbar.html`/`_board_views.html`/`_board_head.html`, 신규 `board_summary.html`, 신규 요약 집계, 필요 시 `workboard_kanban.go` 래퍼, 테스트.

## 2-2. 요약 집계 설계

**한 건 한 카드는 SQL 20개가 아니라 후보 집합 1회 + Go 분류.** 우선순위: 지연 > 오늘 업무 > 진행중. 전일 완료는 완료일이 직전 근무일이라 오늘 카드와 날짜가 다름.

| 카드 | 재사용 | 판정 |
|------|--------|------|
| 전일 완료 | `ListTasksWithProcessBetweenForOrg(prev, prev)` (95-127 병합: 조치∪완료일, 점검 `completed_date` 1순위 금지, DedupKey, parent·취소 제외) | 직전 근무일 완료만. 종류 5행 |
| 오늘 업무 | 일정표 일과 **같은 목록**이어야 함 → board `collectBoardEntries`의 그날 배치 건(취소 제외, 완료 포함). 전체=고유 수, 완료=`boardItemDone` 또는 95-127 완료 집합 | 오늘 일정에 올라온 건 |
| 지연 | `model.TaskDelayState` / AS·점검은 `WorkListTaskDelayState`(종료일=예정일) | 미완료·미취소·종료일&lt;오늘 |
| 진행중 | 위 셋에 안 들어간 미완료·미취소 중 (a) 기간이 오늘을 포함·시작&lt;오늘 또는 (b) 상태 진행중(부분완료 포함) | 지연·오늘에 뺏긴 뒤 잔여 |

종류: `admin`+`support`→행정/지원, `as`, `maintenance`, `project_work`→작업, `sales`(활동 포함)→영업. `boardTypeStyleOf`와 동일.

범위: 기존 `resolveBoardScope` [내 업무|전체]. 반복 `recurrence_role=parent` 제외. 취소 제외(95-130).

**쿼리 수:** 전일 완료 1 + 오늘 collect(이미 일정표가 쓰는 묶음) + 열린 건(지연·진행중 후보) 1~2. 종류별 COUNT 분기 금지. 성능: 일 단위·조직 필터는 현재 board collect와 같은 급.

**숫자 맞춤:** 요약 「오늘 업무 전체」= 일정표 **일**에 올라온 고유 건(95-127 배지=목록). 「지연」= 칸반 「지연」열과 **같은 함수**. 지금 board 칸반 지연은 `TaskDelayState(WorkTask)`라 AS/점검은 `due_date`만 봄. register 칸반은 `WorkListTaskDelayState`. **요약은 지시서대로 TaskDelayState 한 곳 — 종류별은 WorkListTaskDelayState를 써야 AS/점검이 맞음.** 일정표·칸반을 register 정의로 바꾸면 세 화면이 맞춰짐. 현재 board 칸반을 유지하면 요약 지연 ≠ board 칸반 지연(아래 2-4).

## 2-4. 칸반 컬럼 대조 · 숫자 불일치

지시 칸반 = **register 5열**. 컬럼 제목은 `PlanKanbanColumnTitle`: 선택일=오늘이면 「오늘 예정」「오늘 완료」, 아니면 `8/18 예정` 형태. **유지하는 것이 맞음.**

| 열 | register (`ApplyPlanKanbanMapping`) | 현재 board (`classifyKanban`) | 요약 카드 |
|----|--------------------------------------|-------------------------------|-----------|
| 미계획 | NeedPlan·예정일 없음·담당자 없음 | **없음** | 없음 |
| 예정 | 선택일=예정일, 지연 아님, 진행중 아님 | 「계획」(오늘 일정·비진행) | 오늘 업무(완료 포함) |
| 진행중 | `WBKanbanBucket==in_progress` 또는 시작&lt;선택≤종료 | 오늘 일정의 진행중 **또는** 일정 없는 진행중(별열) | 진행중(오늘·지연 제외) |
| 지연 | `WorkListTaskDelayState` | `TaskDelayState(WorkTask)` | TaskDelayState(종류별 권장 WorkList*) |
| 완료 | 완료일=선택일 | 완료일=오늘만, 칸반 view는 **날짜를 오늘로 고정** | 전일 완료는 **다른 날** |
| 부분완료 | 진행중 쪽으로 흡수 | 「부분 완료」별열 | 진행중 (b) |
| 일정 외 진행 | 진행중 열 | 「진행중(일정 외)」 | 진행중 |

**이동 규칙:** board `BoardKanbanMove`는 오늘 열 안에서만·지연/일정외로 못 보냄(`KanbanErrForbidden`). register `RegisterKanbanMove`는 미계획→예정, 지연→예정/진행중, 예정↔진행중, 완료 확인 등 **§7.8.5**. 지시서는 register 구성을 가져오므로 **이동은 register 규칙 + board redirect**. 현재 board 칸반 규칙을 쓰면 열이 다름.

**불일치 가능성**

| 상황 | 요약 | 일정표 일(현 board) | register 칸반 | 현 board 칸반 |
|------|------|---------------------|---------------|---------------|
| 오늘 예정 미완료 | 오늘 업무 | 그날 배치 | 「예정」 | 「계획」 |
| 오늘 완료 | 오늘 완료/전체의 분자 | show=완료 토글 | 「오늘 완료」 | 「완료」 |
| 어제 완료 | 전일 완료 | 어제 일 | 어제 칸반 완료 | **안 보임**(항상 오늘) |
| AS 종료일만 지남 | WorkList*면 지연 | board 목록 Overdue는 TaskDelayState(due) | 지연 | due 없으면 **지연 아님** |
| 여러날 진행·오늘 일정 없음 | 진행중 | 일 그리드에 없을 수 있음 | 진행중 | 진행중(일정 외) |
| 미계획 | 카드 없음 | 미배치 패널(주월) | 미계획 열 | 없음 |

구현 후 숫자를 맞추려면 **일정표 일·칸반을 register 정의로 통일**하고, 요약은 그 목록을 카드로만 나눈다.

## 2-7. 주·월 요약·칸반 (§5-A·B)
