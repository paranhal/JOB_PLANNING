# 95-36A단계 — AS 신규 접수 장비 행 담당자 필수·입력값 보존

기준: `커서_작업지시서_95-36A_긴급_AS접수_담당자필수_장비행_반응없음.md`  
선행: 95-36, 95-37. 실행일: 2026-10-25.

## 한 줄

org_admin·support가 `/as/new`에서 장비 행 담당자를 비우고 「접수 등록」을 누르면, 리다이렉트로 입력이 지워지지 않고 같은 폼에 오류·포커스가 남는다. 개인·그룹·직접입력 중 하나면 통과한다.

## 원인 재현

95-36 서버는 장비 행(`rows`)마다 `assigneeFilled`를 보고 `/as/new?err=assignee_required&focus=assignee`로 **리다이렉트**했다. 신규 화면 장비 행에는 `data-focus-target="assignee"`·필수 `*`·`eq_work_group_id`가 없어 클라이언트 검사가 통과하고, 거부 후 입력값이 사라지며 배너는 페이지 맨 위에만 떠 **무반응**으로 보였다.

재현(수정 전 코드 기준, `jwtCookie` role=`admin` → `NormalizeRole` 후 `org_admin`):

- GET `/as/new`: `eq_assigned_code`는 있으나 `data-focus-target="assignee"`는 수정 화면 분기에만 있음.
- POST 장비 행 담당자·그룹 공란 → 303 Location `/as/new?err=assignee_required&focus=assignee`.

수정 후 `Test95_36A_OrgAdminNewReceiptEmptyAssigneePreservesForm`: 같은 POST가 **422**로 폼을 다시 그리며 증상·연락처·사진 메모가 남는다.

## 구현 요지

- 장비 기본 행·`eq-row-template`에 수정 화면과 같은 담당자 UI(`data-focus-target="assignee"`, 필수 `*`, `eq_work_group_id`).
- `parseEquipmentRows`가 `eq_work_group_id`를 `WorkGroupID`로 읽음. 장비 필드가 비면 기존 `assigned_to` 값을 유지(다중 장비 테스트·레거시 POST).
- 지원 GET은 `applySupportAssigneeDefault`로 첫 행 본인 선택. POST에서 비우면 거부.
- 신규 접수 검증 실패 시 리다이렉트 대신 `renderASNew`(422)로 입력값 재표시. 오류는 장비 섹션·해당 행, 로딩 시 그 select로 스크롤.
- `base.html` 공용 검사가 `#eq-rows .eq-row` 단위로 개인/직접입력/그룹을 본다.
- `.cursor/rules/form-error-visible.mdc`: 서버가 폼을 거부하면 사용자가 보는 위치에 오류를 보여 준다.
