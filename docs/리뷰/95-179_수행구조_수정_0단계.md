# 95-179 수행 구조 수정 요구 — 0단계 (읽기 전용 현황 대조)

작성: 2026-11-12. **코드 수정 없음.** 구현은 사용자 확인 뒤(AGENTS: 0단계 → 확인 → 구현).
요구: 사용자 메시지 「수행 구조 만들기에 대한 수정 내용」. 용어는 사용자 표현을 따른다 — **1단계 업무 = 단위 업무(`project_phases`)**, **2단계 하부 업무 = 하부 업무(`phase_packages`)**.

## 0. 먼저: 사업의 사이트는 어디서 등록하나 (질문에 대한 답)

**사업 수정 화면에는 사이트 입력이 없다(의도된 구조).** 수정 화면의 설명이 「기본 정보와 AS/정기점검 귀속 범위를 설정합니다」이고 `project/form.html`에 사이트 필드가 없다.
사이트는 **별도 화면 `/projects/{사업ID}/sites`(「사이트 등록」)** 에서 등록한다. 진입 링크는 사업 상세에 두 곳이다.
1. 사업 상세 맨 위 줄 「…연차 · **사이트 등록**」(`show.html:9`)
2. 사업 상세 「사이트·진행」 카드 안 「**사이트 등록**」(`show.html:177`)

이 화면(`project/sites.html`)에서 하는 일:
- 유형 탭(학교 / 공공기관 / 도서관 / 민간업체) → 학교명·시도·시군으로 검색 → 체크 → **「사이트 등록」**(`POST /:id/sites/add-schools`, 개별 저장은 `POST /:id/sites`)
- 엑셀 등록: 학교 엑셀(`schools-template.xlsx` 받아서 미리보기 → 반영), 설치자산 엑셀(`template.xlsx`)
- 상태 일괄 변경, 사이트 제외
- 등록된 사이트는 `project_sites`(사업 사이트 풀)에 들어간다. 운영 WP-061은 매칭 요약 「설치 0/801 · 검수 0/801」이므로 **이미 801곳이 등록돼 있다.**

**점검 결과(문제점)**
- 기능 자체는 있으나 **찾기 어렵다**: 수정 화면에서는 어디에도 안내가 없고, 사업 상세에서도 작은 파란 글씨 링크뿐이다. 「사이트·진행」 표는 **작업과 연결된 사이트만** 보여 주므로(등록은 801곳이어도 목록은 비어 보인다) 등록 여부를 오해하기 쉽다.
- 수행 구조(작업 계획)는 이 풀에서 사이트를 골라 담는다(후보 = 그 사업의 `project_sites`, 제외 상태 제외). 즉 **사업 사이트 등록이 수행 구조의 선행 조건**인데 그 연결 안내가 없다.
- 제안(작은 변경, 승인 시): ① 사업 수정 화면 아래에 「등록된 사이트 N곳 · **사이트 등록/관리**」 카드와 링크 ② 사업 상세 「수행 구조」의 사이트 선택 창에 「사이트 등록」 바로가기 ③ 「사이트·진행」 표 머리에 「등록 801곳 중 작업 연결 N곳」.

## 2. 설계 제안 (확정 아님 — 질문 답에 따라 바뀜)

### 데이터 (마이그레이션 113, 기존 행 불변, `.down.sql`)
- `phase_packages` 추가: `plan_start`, `plan_end`, `actual_start`(TEXT, 기본 `''`), `badge`(TEXT, 8자 이내, 기본 `''`).
- 새 표 `structure_date_changes`: `change_id TEXT PK('DC-001')`, `project_id`, `org_id`, `level('phase'|'package'|'plan')`, `target_id`, `field('plan_end'…)`, `old_value`, `new_value`, `reason`(연장은 필수), `changed_by`, `changed_at(KST)`. 인덱스 `(project_id, changed_at)`.
- 하부 업무의 사이트 범위는 기존 `package_sites`를 쓰되, **작업 계획 없이도** 만들 수 있게 한다(`plan_id=''`은 이미 「계획 미배정」으로 허용됨).

### 규칙
- **연장**: 마감을 **뒤로** 미루면 사유 필수 + 이력(일자·ID·사유). 앞당김은 이력만(사유 선택, 질문 3).
- **실제 시작일**: 저장된 값이 아니라 **파생**으로 계산해 화면에 쓴다 — 하부 업무 = 그 하부 업무에 연결된 작업의 **첫 완료일**(`work_tasks.complete_date`, 사이트 완료 이벤트의 첫 일자 중 이른 쪽), 단계 = 하부 업무 값의 최소. 수동 입력 칸은 없애거나 자동값 우선으로(질문 4). 계산은 `model/stats.go`처럼 한 함수에서만.
- **배지**: 하부 업무에 `badge`. 사이트 목록(사업 상세 「사이트·진행」, 사이트 등록 화면)에서 그 사이트의 완료된(`package_sites.status='done'`) 하부 업무 중 배지가 있는 것을 **완료 일자순**으로 칩으로 표시. 배지 없는 하부 업무는 표시 안 함. 새 쿼리는 사업 ID 일괄 GROUP BY(N+1 금지, 쿼리 수 상한 시험).

### 화면
- **1단계 만들기**: 이름 · 예정일 · 마감일 · **사이트(시군 접기 → 학교 체크박스, 시군 체크 시 하위 전체)** · 「사업 사이트 전체 가져오기」 · 저장.
- **2단계 만들기**: 이름 · **배지(선택)** · 예정일 · 마감일 · **그 1단계의 사이트만** 후보로 한 체크박스 목록(시군/학교) · 「1단계 사이트 전체 가져오기」 · 저장.
- 사업 상세 하부 탭 **「변경내역」**: 연장 이력 표(일자·ID·대상·이전→이후·사유). 마감 수정 창에 사유 입력(연장일 때 필수).
- 사이트 목록: 배지 칩 열.

### 구현 순서(단계별 0단계 생략 가능 여부는 확인 후)
A. 일자·사이트 범위 등록(마이그레이션 113a, 1·2단계 만들기 화면) → B. 연장 이력과 「변경내역」 탭 → C. 실제 시작일 자동 → D. 배지 → (병행) 사이트 등록 안내(§0).
각 단계: 보고서·시험(권한, org 조건, 쿼리 상한, 구조 없는 사업 회귀, 실제 브라우저 390/820/1440).

## 4. 질문 (결정이 필요한 것)

1. **작업 계획(3단계, 「홍천 지역 50곳」) 유지 여부**: 이번 요구는 1단계 업무 / 2단계 하부 업무 두 단계만 말한다. 지난 95-175 요구(하부 업무 아래 작업 계획 → 「홍천 지역 50곳 중 4곳」 진행 보고)는 그대로 두고, 하부 업무에서 **계획 없이도** 사이트를 직접 등록하게 하는 것으로 이해해도 되는가? 아니면 작업 계획을 없애는가?
2. **마감 임박 알림 방식**: 대시보드 칩(「마감 N일 전」), 사업 상세 표시, 메일·문자 중 무엇인가? 임박 기준(예: 7일 전)은?
3. 마감을 **앞당길 때**도 이력과 사유를 남길까(연장만 필수)?
4. **실제 시작일**: 완전 자동(수동 입력 폐지)인가, 자동값을 기본으로 하되 수정은 허용인가? 「작업이 완료되면」의 기준은 작업 **완료일**이 맞는가(착수일이 아니라)?
5. **2단계 마감이 1단계 마감을 넘을 수 있는가**(막을지/경고만 할지/허용). 하부 업무 사이트가 1단계 사이트 범위를 벗어난 경우의 처리.
6. 시군→학교 **트리 체크박스**가 필수인가, 지금의 검색+지역 필터+결과 전체 선택으로 충분한가? 사이트가 801곳이면 트리는 접기·검색이 함께 필요하다.
7. **배지 이름 길이·중복**: 최대 몇 자(제안 8자)? 같은 배지를 둘 이상의 하부 업무가 가질 수 있는가? 배지 색은 고정인가?
8. 배지는 사업 상세 사이트 표 외에 **업무 화면·주간 보고서**에도 보여야 하는가?
9. §0의 **사이트 등록 안내**(수정 화면 카드·바로가기·등록 N곳 표시)를 이번에 같이 할까?
