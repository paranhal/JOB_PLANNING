# 95-188 구현 보고 — 작업 등록(project_work) 「하부 업무를 선택하세요」 오류

작성: 2026-11-13. 푸시·배포·VERSION 변경 없음. 작업지시서 본문(§3 A·B-1, §4)은 파일을 찾지 못해, 붙여 주신 요약(재현 → A·B-1 구현 → 재현 시험이 수정 전 실패/수정 후 성공)에 맞춰 진행했다. 지시서와 다른 점이 있으면 알려 주세요.

## 1. 재현 (브라우저, 임시 DB)
작업 등록 모달 → 「작업·행정/지원」 아닌 **사업 업무(project_work)** → 수행 구조·계획이 있는 사업 선택 → 수행 단계 「단계 없이 등록」 → 하부 업무 선택 → 사이트 전체 담기 → 작업명·구분 입력 → 저장.
- 폼 안의 `package_id` 입력은 **2개**였고, DOM 순서는 ① 수행 단계 패널(`plan-sites.js`, 값 빈 문자열, 사업을 고를 때 만들어짐) → ② 하부 업무 선택(`_package_site_picker.html`, 값 PK-001). `plan_id` 도 빈 값 1개가 함께 제출된다.
- 서버는 `c.FormValue("package_id")`(첫 값)만 읽어 **빈 값**을 받고, 계획도 없으므로 「수행 구조가 있는 사업입니다. 하부 업무를 선택하세요」 오류가 났다(화면에 오류 표시 확인).
- 수행 단계 패널은 사업에 계획이 있어야 만들어지므로, 계획이 없는 사업은 1개라 오류가 없었다(95-182 시험은 이 경우만 봤다).

## 2. 수정
- **A (서버)** `formFirstNonEmpty`([project_structure.go](server/internal/handler/project_structure.go)): 같은 이름의 값이 여러 개 오면 **비어 있지 않은 첫 값**을 쓴다. `bindPostedPlan`·`checkPostedPackageSites` 의 `package_id`·`plan_id` 에 적용. 둘 다 비면 기존대로 오류.
- **B-1 (화면)** [plan-sites.js](server/web/static/js/plan-sites.js): 수행 단계 패널의 숨은 `package_id`·`plan_id` 는 **값이 비면 `disabled`**(제출되지 않음). 수행 단계를 고르면 같은 폼의 하부 업무 선택도 같은 하부 업무로 맞춘다(Alpine 데이터 `pkgId` 설정 + `onPackage()`).
- 스키마·DB 변경 없음.

## 3. 시험
- 신규 브라우저 `Test95_188_BrowserPackageIDSingle`(`95_188_package_dup_browser.mjs`): 계획이 있는 사업, 「단계 없이 등록」 + 하부 업무 선택 + 사이트 담기 + 저장 → 제출되는 `package_id` 1개·값 있음·오류 문구 없음·등록 성공(`ok=task`).
- 신규 HTTP `TestHTTP95_188_PostedPackageIDFirstNonEmpty`: `package_id=["", pkg]` 오류 없음, `["",""]` 는 기존 오류, 값 1개는 통과.
- **수정 전 실패 확인:** 수정 파일(`plan-sites.js`, `project_structure.go`)만 되돌리고 돌리면 두 시험 모두 실패(브라우저: 「제출되는 package_id 가 1개여야 한다 [{v:'',…},{v:'PK-001',…}]」, HTTP: 「빈 package_id 가 먼저 읽혀 오류」). 수정 후 통과.
- 시험 보조 변경: 일정표 시험 라우터(`workboard_board_personal_test.go`)에 `/projects/:id/structure/options` 를 추가했다(수행 단계 패널이 실제처럼 만들어지도록). 이로 95-182 브라우저 시험이 「첫 `package_id` 입력」을 읽던 부분이 빈 값을 읽어 실패해 `:not([disabled])` 로 바꿨다(수정 후 통과).
- 전체 게이트: 통과 2771 / 실패 8 (기존 7 · 신규 1). 신규 1은 위 95-182 브라우저 시험이었고 고친 뒤 해당 시험과 95-188 시험만 다시 돌려 통과했다. **고친 뒤 전체 게이트는 다시 돌리지 않았다.**

## 4. 한계
- 수행 단계에서 하부 업무를 고르면 하부 업무 선택이 바뀌지만, 사이트 목록은 하부 업무 선택의 기존 동작대로 다시 불러온다(이미 담은 사이트는 사업·하부 업무가 바뀌면 지워지는 기존 규칙).
- 같은 사업 화면(수행 구조 화면 등)의 다른 `package_id` 폼은 이번에 건드리지 않았다.
