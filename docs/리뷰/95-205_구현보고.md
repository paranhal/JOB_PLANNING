## 1. 변경 (줄 생성 한 곳: `internal/repository/company_weekly_group.go` 신규)
- **묶음 키** = (사업, 묶음 ID). 사업은 조회가 이미 사업별. 묶음 ID: `parent_task_id` 가 있으면 그 값(반복·하위 일정 모두) → 목록에 자신을 상위로 가진 건이 있으면 자기 ID → 아니면 **정규화한 제목**(공백 연속→1칸·앞뒤 공백 제거·대소문자 무시). 제목·상위가 다르면 묶지 않는다(유사도 매칭 없음).
- **금주 추진내역**: 묶음당 1줄 `대표제목(기간)`. 대표 제목 = 상위 업무 제목(조회에 `LEFT JOIN work_tasks pt` 로 `ParentTitle` 추가; 상위 줄이 목록에 있으면 그 제목, 반복·프로젝트 작업 라벨은 첫 건 제목), 상위가 없으면 가장 이른 날짜 건의 제목. `N회` 는 완료 줄에서 기간으로 대체.
- **기간 표기**: 단일 `(11/9)`, 연속(다음 날 또는 토·일만 건너뜀) `11/9~11/11`, 비연속 `11/9·11/11`(3개 초과는 `외 N일`). `formatWorkDateRange` **단일 함수**, 월·연 경계 포함 표 시험.
- **차주 추진계획**: 같은 규칙. 예정일이 있으면 기간 표시(지금까지 차주 줄은 날짜가 없었다 → 새 동작, 사용자 확인한 기본안). AS 후속·정기점검 이월 줄은 묶지 않는다.
- **이월 줄**: 현행 형식 유지 `제목 N회(이월)` / `제목(N주 지연) N회`. 지연 주 수는 제목에 붙이던 것을 `DelayN` 필드로 옮겨 묶음의 최대값을 쓴다(대표 제목이 상위 제목이므로).
- **같은 문구 중복 제거**: 같은 구역의 자동 줄 문구가 공백 정규화 후 완전히 같으면 1줄만 남긴다(`dedupeAutoLines`, 먼저 나온 줄 유지). 직접 입력(manual) 줄은 이 함수를 거치지 않는다.
- **줄 Key**: 묶음 줄은 `grp:{구역}:{묶음ID}`(예 `grp:done:p:P1`, `grp:carry:t:입찰서류 준비`), 낱줄(상위 없는 한 건)은 현행 `task:ID`. 구역(done/plan/carry)을 포함하므로 같은 상위의 계획·이월이 Key 를 공유하지 않는다.
- `collapseCompanyAdminLines` 는 제거(조회 함수는 원본 줄을 돌려주고 compose 가 묶는다). `dropDupMntAdmin` 이 묶기 **전** 원본 줄(고객 ID 보유)에서 동작하게 되어 순서 문제도 해소.
- **`## ##`**: `weeklyActivityName`(엑셀·HWPX 공용)이 `## 활동명` 한 번만. 화면 카드 제목은 그대로.
- 마이그레이션 없음. 저장된 보고서 JSON 은 그대로(재집계 때 새 규칙 적용).

## 4. 알려진 한계·확인 질문
1. **활동 행(기술영업·자산관리 등)·사업 미연결 줄은 이번에 묶지 않았다.** 활동 행은 같은 문구 중복 제거만 `keyedToAuto` 에 공통 적용(`TestKeyedToAutoDedupesSameText95_205`). 활동 행도 기간 축약이 필요하면 별도 지시가 필요하다.
2. **날짜 없는 상위 업무(하위 일정을 가진 부모)가 이월 줄로 따로 남는다.** 예: 하위 일정이 차주 계획에 `현장 실사(11/17·11/18·11/20)` 로 나오는데 부모 `현장 실사(이월)` 줄도 이월에 나온다. 문구가 달라 중복 제거되지 않는다. 지시서 범위 밖이라 두었다 — 부모를 이월에서 빼는 규칙이 필요하면 지시해 달라.
3. **저장된 보고서의 `hidden` 키**(`task:{상위ID}`)는 새 Key(`grp:…`)와 달라, 사용자가 숨겨 둔 반복 묶음 줄은 재집계 때 다시 나올 수 있다(지시서 「저장 JSON 일괄 수정 금지」 준수). 필요하면 한 번 다시 숨기면 된다.
4. 비연속 날짜 표기는 지시서 그대로 `11/17·11/18·11/20`(일부만 연속이어도 전부 나열).
5. 팀 교육: 같은 업무인데 제목이 다르고 상위도 없으면 합쳐지지 않는다 → 팀원이 하위 일정으로 기록하거나 제목을 통일해야 한다(지시서 §7 질문 그대로).
