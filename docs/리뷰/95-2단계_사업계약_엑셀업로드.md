## 확인한 실제 테이블·컬럼

계약 = `work_projects`(§46.10). 별도 `contracts` 표 없음.

| 양식 | 실제 |
|------|------|
| 사업명 | `work_projects.name` |
| 부서 → 조직 | `work_projects.org_id` (O01/O02/O03) |
| 발주처 | `ordering_party_id` + `ordering_party`(이름) |
| 최종수요처 | **다대다 표 없음** → `contract_end_customers` 신설이 필요 |
| 사업유형 | `project_kind` 코드 5종: `construction` 공사, `build` 구축, `dev` 개발, `maintenance` 유지보수, `other` 기타. **용역·구매 코드 없음** |
| 계약방식 | `contract_type`(자유 문자열) + `contract_category`(조달 등 코드) |
| 거래구분 | **컬럼 없음** → `direction`(`revenue`/`cost`) 신설이 필요 |
| 기간 | `start_date` · `end_date` |
| 계약금액 VAT포함 | `contract_amount` 정수. `amount_vat_included` 플래그 있음. **공급가·세액 컬럼 없음** |
| 계약번호 | `contract_no`(선택). 내부키 `project_id`는 `WP` 생성기 |
| 계약담당·업무담당 | `project_assignments`(duty: sales/execution/management/accounting). `work_projects.assignee` 컬럼 없음 |
| 상태 | `status` 기본 `active`. 기간 상태는 화면에 계산 |
| 영업 연결 | `sales_project_id` — 업로드 시 비움 |
| 연차 | `contract_years`(95) |
| 배치 | `contract_import_batches` 없음 → 신설 |

집계: 대시보드·합계가 `contract_amount`를 쓰는지 구현 전에 전수 확인이 남아 있음(매입 제외).

95-E 한도 상향은 **이미 코드에 있음**. 합성 1000사이트·20000장비 테스트는 95 단계 범위.

## 하지 않은 것

업로드 화면, 파서, 마이그레이션 073, 작성본 48건 적용, 운영/개발 DB 변경, push.

## 질문 (답하면 95-2 구현 재개)

1. **사업유형 `용역`·`구매`**: 기존 5종에 없는 값이다. (가) `dev`/`other`로 접을지, (나) `service`·`purchase` 코드를 새로 넣고 화면 옵션도 늘릴지.
2. **계약담당·업무담당**: `project_assignments`의 `sales` / `execution` 으로 넣어도 되는지.
3. **VAT**: 공급가·세액 컬럼을 만들지 않고 `contract_amount`=VAT포함 + `amount_vat_included=1`만 쓸지(지시 8의 「없으면 포함 금액만」).
4. **`AppSchemaVersion` 72**: 071 지시 대신 최대 번호 72로 맞춘 것이 맞는지.
5. **C-Level 장비 분류 메뉴**(95-1 잔여): 넣을지 말지.
6. SI·미디어 점검 제품(95-5): 95-4 전에 화면 등록은 사용자가 함. 코드 시드 없음 — 이대로 두어도 되는지.
