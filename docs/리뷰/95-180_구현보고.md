# 95-180 구현 보고 — 작업 계획(3단계) 수정과 마감 연장 이력

작성: 2026-11-12. 0단계: `95-180_작업계획_마감수정_0단계.md`. 사용자 답변: ① 이름·다음 할 일도 같이 연다 ② 완료된 계획도 수정 허용(이력으로 남김) ③ 사이트 구성은 건드리지 않는다.

## 구현 (커밋 c978e96)
- `POST /projects/:id/plans/:planID` — 이름·예정 시작·마감·다음 할 일 수정(`PlanUpdate` → `repository.UpdatePlan`).
- 마감 연장은 **사유 필수**(200자), 앞당김·해제는 사유 없이 이력만. 한 트랜잭션에서 `structure_date_changes`(`level='plan'`)에 기록한다. 1단계·하부 업무와 같은 `recordEndChangeTx`를 쓴다.
- 같은 하부 업무 안 이름 중복은 거절. 다른 사업의 계획은 거절. 완료된 계획도 수정 가능.
- 사이트 구성·진행 기준(`progress_basis`)·상태는 건드리지 않는다.
- 화면: 사업 상세의 각 작업 계획 줄에 「계획 수정」 접기(권한 있는 사용자만). 「변경내역」 화면에는 작업 계획 이력이 기존 표에 그대로 나온다.
- 대시보드 마감 임박 칩(95-179E)은 작업 계획 마감일을 이미 보므로 수정 결과가 따라간다.
