## 원인 재현 (담당자 변경이 안 됨)

재현: 방문에 `maintenance_visit_assignees` 2행(최혜영 주담당, 양기헌 지원)을 넣은 뒤, 조치 POST에 **단일 `assignee=김서준`만** 보내는 경로(수정 전 `UpdateVisitAction`).

수정 전 코드는 `v := *existing` 후 `v.Assignee`만 덮고 `applyVisitAssigneesFromForm`을 호출하지 않았다. `GetVisit`도 People을 채우지 않지만, 계획 관리·업무 동기화는 People/`work_group_id`를 우선한다. `UpdateVisit` → `syncVisitAssigneeRows`:

- `work_group_id`가 있으면 그룹 구성원으로 **다시 채움** → 폼의 개인 선택이 사라짐.
- People 행이 있으면(복사본이 넘어가면) 옛 행을 그대로 `ReplaceVisitAssignees`.
- 화면 담당자 select에는 업무 그룹·복수 체크가 없어 그룹 변경 자체가 불가.

확정 테스트: `Test95_47_AssigneePeopleRowsWereBlockingLegacySave`. 수정 후 `assignee_multi=1` + `assignee_user_id`로 김서준 1명만 남음. 레거시 `assignee`만 보내는 경우에도 People을 대표 1명으로 교체해 `TestVisitActionSyncsAssignee`가 유지됨.

## 원인 재현 (점검 대상 입력이 안 됨)

재현: 조치 화면에 장비 이름 여러 개를 넣어도 저장 컬럼이 `maintenance_visits.product_type`(슬롯 식별 문자열 1개)뿐이라 장비 목록이 남지 않음. 같은 날·같은 기관·같은 제품이면 UNIQUE `idx_maintenance_visit_dedup` / `clearVisitSlotConflict`(다른 방문 삭제) / 회차 가드가 거부하고, 예전에는 `echo.NewHTTPError(400)`이라 입력 화면이 사라짐.

확정 테스트: `Test95_47_EquipmentRowsNotProductType`(직접 입력 4행 → `게이트A, 게이트B, 데스크 외 1대`, 다른 제품 슬롯 방문은 유지), `Test95_47_AssetCheckboxAndForeignReject`(사이트 자산 선택 / 타 사이트 자산 거부, 400 페이지 없음).

제품 슬롯(`product_type`)과 장비(`maintenance_visit_targets`)는 별개. 값이 있는 제품 칸은 읽기 전용(계획 관리에서 변경).

## 동작

- 저장·완료·오류: `jp_flash_ok` 쿠키(95-38). 제목 「저장되었습니다.」/「점검이 완료되었습니다.」 요약 팝업. 오류는 입력 보존 + 「확인해 주세요」(400 금지). 새로고침 시 재표시 없음.
- 「방문 완료 처리」(`mark_done=1`): 완료 + 실제 방문일(없으면 오늘) → 팝업 확인/Esc/바깥 클릭 시 `back` 이동. 완료 건에서 버튼 숨김. 임베드 `postMessage`.
- 방문 시각·종료·이동(편도)·현장 소요(자동/칩). 종료≤시작 거부. 업무 `work_tasks` 시간 동기화. 리스트 일정 `10/12 (월) 10:00~11:30`. 겹침은 저장 후 경고만.
- `maintenance_visit_targets` 최대 50. 설치자산 체크 + 직접 입력 행. 자산 신규 생성 없음. `org_id`(95-43).
- 담당자: 95-14A 선택기(그룹·복수·제외). `applyVisitAssigneesFromForm`. 조직관리자·지원 필수. 완료 건 수정은 조직관리자·지원·admin.
