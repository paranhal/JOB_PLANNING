# 95-185 구현 보고 — 1단계 업무에 「+ 하부 업무」 버튼을 눈에 띄게

작성: 2026-11-13. 근거: 작업지시서 95-185(사용자가 채팅에 붙여 줌), 인수인계 §2 규칙. 선행: 95-183(`dd1c498`, `b035c7b`, 운영 반영됨). **푸시·배포·운영 DB 접근 없음.** 커밋 해시는 이 보고서가 들어간 커밋(아래 「커밋」)이다.

## 사용자 결정 (0단계 보고 후 답변)
- **A로 진행**: 지시서의 「모달」 대신 **단계 안에서 펼쳐지는 패널**. 0단계 확인에서 「+ 작업 계획」은 모달이 아니라 사업 화면 맨 아래의 숨김 폼을 여는 방식임이 드러나, 지시서의 「작업 계획과 동일한 모달」 전제가 맞지 않았다.
- `CreatePackage` 수정 허용(비활성·정규화 중복 안내를 새로 만들 때도 쓰려고).
- 오류가 나면 패널을 열어 두고 입력값을 되돌려 채움.
- 지시서 결정 2(수행 담당은 하부 업무 추가 불가)는 기존 정책 그대로.

## 변경 내용
1. **1단계 칸 버튼 줄(↑ ↓ 진행 완료 삭제 옆)에 「+ 하부 업무」 버튼**(`btn btn-primary btn-sm`, `data-add-package="{단계ID}"`). 설계 권한자(`CanEditPhase`: 비전관리자·조직관리자·PM)에게만 렌더된다.
2. **그 버튼 바로 아래에 단계별 추가 패널**(`form[data-add-package-panel]`, Alpine `x-show`, 처음엔 닫힘, 열면 이름 칸에 포커스, 「취소」는 닫고 입력값을 비운다). 필드·POST 경로·핸들러는 기존과 같다: 하부 업무명(필수, 100자), 유형(사이트/수량만), 배지(8자), 예정 시작, 마감, 「하부 업무 추가」/「취소」. 단계마다 폼이 하나씩 있어 **대상 단계가 자연히 정해진다.**
3. **하부 업무가 0개인 단계**에는 「하부 업무가 없습니다. [+ 하부 업무]로 추가하세요」(`data-no-packages`)와 같은 버튼을 한 번 더 보여 준다(그 단계 패널을 연다). 권한이 없는 사용자에게는 문장만 보이고 버튼은 없다.
4. **맨 아래 인라인 폼 제거.** 검증 문구(`required`, `maxlength` 100/8)·필드 이름은 새 패널로 옮겼다. 단계당 하부 업무 추가 폼은 패널 1개뿐이다.
5. **추가 뒤**: 새 하부 업무 줄로 이동(`#package-{ID}`), 성공 문구 「하부 업무를 추가했습니다.」. 사이트 기준이면 그 줄에 「사이트 등록·관리」 링크가 바로 보인다(사이트 선택은 별도 화면 유지). 단계는 접히지 않으므로 「펼친 채」 조건은 이미 충족.
6. **오류**: `err=…&add_open={단계}`와 입력값(이름·유형·배지·일자)을 되돌려 주소에 실어 패널을 **그 단계만** 열고 값을 채운다(`#add-package-{단계}`로 이동). 값을 잃지 않는다.
7. **`CreatePackage`**: 이름 중복 검사를 정규화 기준(공백·괄호 무시, 비활성 포함)으로 바꿨다(95-183의 `packageNameFreeTx` 재사용). 비활성과 같은 이름이면 「이름이 같은 비활성 하부 업무가 있습니다(「홍성」). 아래 비활성 목록에서 되돌리거나 다른 이름을 쓰세요」. 이전에는 정확히 같은 이름만 막고 일반 문구만 냈다. (95-183에서 이름 변경 때 쓰던 문구도 같은 함수라 조사를 피하도록 다듬었다.)

## 질문·남은 것
1. 오류 후 입력값 복원은 주소(쿼리)에 이름·배지·일자를 싣는다. 민감한 값이 아니지만 서버 로그에 남는다. 괜찮은지.
2. 패널은 같은 화면의 JS(Alpine)로 열고 닫는다. JS가 꺼진 환경에서는 패널이 숨겨진 채라 추가할 수 없다(`x-cloak`). 기존 「+ 작업 계획」도 JS가 필요하므로 같은 전제로 두었다.
3. 95-184(링크를 버튼으로)는 지시서 파일을 아직 찾지 못했다. 경로나 내용을 받으면 이어서 진행한다.
