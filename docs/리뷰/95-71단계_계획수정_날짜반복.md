## 시작 전 조사

### 시작일/종료일 저장 로직 (사실)

이미 **업무 시작일 = `work_date`**, **업무 종료일 = `due_date`** 로 저장한다. 필드 이름을 바꾸지 않았다.

- 등록 폼 `name="work_date"` / `name="due_date"` → `parseRequiredSchedule` → `WorkTask.WorkDate` / `DueDate`
- 종료일이 비면 시작일로 채운다(`dueDate = workDate`). 미정+사유면 종료일을 비운다.
- 일정 배치·보드 칸은 **`work_date`(수행일)** 를 본다. `due_date`만 있고 `work_date`가 비면 미배치/예정 취급이 된다.
- 반복 기간 전개(`ExpandDailyDates`)만 “종료일이 시작일보다 앞입니다”를 이미 검사했다. **일반 등록·수정은 ① 전까지 이 검사가 없었다.**

화면 칸 순서만 어긋나 있었다. 행정 모달·행정 전용 등록은 시작→종료, AS/점검 모달·계획 수정·AS 상세의 일일업무 폼은 종료→시작이었다.

### (a) 「조용한 실패」 재현

맞다. 겹침으로 거절되면 `overlapRedirect`가 `?err=` + 한글 문장(`최혜영의 09:00~09:30에 다른 업무가 있습니다`)으로 돌려보낸다.

- **예전 일정표** `/workboard/register`는 `FlashErr`를 그려서 문구가 보인다(코드 `overlap`이 아니라 문장 그대로).
- **일일 업무 보드** `/workboard/board`는 `personalBoardData`에 `FlashErr`가 없고 템플릿에도 배너가 없다. `?err=`가 URL에만 남고 화면은 성공한 것처럼 보인다. **저장은 되지 않는다.**
- **오늘 업무** `/work`도 `err` 쿼리를 읽지 않는다.

재현: `Test95_71_OverlapErrSilentOnBoard` (보드·오늘 업무에는 문구 없음, 일정표에는 있음, DB에 새 행 없음).  
이 표시는 ④에서 고친다. ①에서는 손대지 않았다.

### (b) 저장했는데 목록에 안 보이는 다른 원인

겹침 거절과 별개로, 실제로 저장된 뒤에도 안 보일 수 있는 것:

| 원인 | 동작 |
|------|------|
| 보는 날짜 ≠ `work_date` | 보드는 조회일의 `work_date`만 올린다. 종료일만 다른 날은 그 날짜 목록에 없다. |
| 범위 필터 | 기술·영업 기본 **내 업무**. 팀원별 보기(`members=`)에 본인이 없으면 빠진다. |
| 조직 격리 | O01/O02/O03. 다른 조직 건은 안 보인다. |
| 접수/조치 토글 | `show` 가 일정만/조치만이면 한쪽이 숨는다. |
| 미배치 | `work_date`가 비면 리스트 본문이 아니라 미배치 박스. |
| 지난날 잠금 | 저장 거절(`err=past`). 목록에 없는 것은 저장 실패. |

이번 재현에서 「새겹침」은 **저장 자체가 안 된 경우**였다.
