# 95-95 §2 — 처리담당자 이름 표시

작성: 2026-11-03. 지시서 `커서_작업지시서_95-95_긴급_사이드바_x-data_노출_처리담당자_이름_담당자_표시.md` **§2만**. 사이드바(§1)는 95-93에서 끝났고 이번 작업에서 `_nav_tree.html`을 건드리지 않았다. Q-1 기본값: 이름 전혀 없으면 「이름 미등록」.

## 0단계 (수정 전 원인)

증상은 선택기 **버튼**에 사람 이름 대신 「담당자」가 보이는 것이다. 서버 사용자 행·템플릿·JS를 나눠 보면 아래가 겹친다.

| 층 | 무엇이 비나 | 판정 |
|----|-------------|------|
| DB `users.full_name` / `username` | 비거나 `USR-…`이면 예전 `pickerDisplayName`이 리터럴 **「담당자」**를 내려줌. 그 값이 `assigned_to`·`data-name`에 굳으면 JS도 복구 못 함 | **(가)** 가능. 이름 있는 계정은 여기가 1차 원인이 아님 |
| 템플릿 `_action_set.html` | `PickerNames`는 `$root`로 넘기지만 **`SelectedIDs`가 없음**. 버튼은 `<span x-text="summaryLabel()"></span>`만이라 **서버 HTML에 이름이 없음**. Alpine이 돌기 전(또는 extra가 비면) 사용자는 필드 라벨 「처리담당자」/목록 제목 「담당자」만 봄 | **(나) 확정** |
| JS `summaryLabel` | 선택이 비고 `external`만 있으면 그 문자열을 버튼에 씀. `assigned_to`가 「담당자」이면 그대로 표시 | **(다)와 결합** |
| 선택 인원이 `ListAssignable` 밖 | 이름표에 ID가 없으면 `nameOf`가 예전엔 「담당자」 | **(다)** — `pickerNamesFor` extra로 막아야 함 |

확정: **표시가 비는 지점은 템플릿(나) + JS fallback(다)** 이다. 서버 맵만 고쳐도 버튼 SSR이 비어 있으면 화면에는 「담당자」로 보인다.

## 구현 (§2만)

- 표시 순서: full_name → username → 로그인 아이디 → 「이름 미등록」. 리터럴 「담당자」·`USR-`는 사람 이름으로 쓰지 않음 (`pickerPersonLabel`).
- 조치 세트 선택기에 `SelectedIDs`·정제한 `ExternalName`을 넘김. 버튼 안쪽에 `pickerButtonLabel`로 **실제 이름을 SSR**.
- `summaryLabel`은 `external === '담당자'`이거나 `USR-`로 시작하면 버튼 문구로 쓰지 않음.
- 접수 `PickerOwnerName`도 `pickerPersonLabel`로 정제.
- 세트·접수 `AssignedUserID`는 기존처럼 `ensurePickerUsers` / `pickerNamesFor` extra.
