## 7. 질문 (임의 결정 금지)

**(a) 집계·대시보드 숫자 변화 후보**  
등록 관리를 OrgAll로 열면 팀 화면 건수는 늘어난다. 사업 대시보드·계약 관리·C-Level KPI는 InOrg를 유지했으므로 후보는 「등록 관리만 확대 / 대시보드는 현행」. 주간업무·조직 사업 현황을 같은 원칙으로 넓힐지는 미정.

**(b) 고객 등록 `org_id`**  
컬럼 유지. 직원 등록=본인 조직. 시스템 관리자 전체(*) 미선택=도서관 `O01`(스키마 NOT NULL·92 기본 소속에 맞춤). 조회에 안 쓰이므로 장기적으로는 NULL 또는 등록 이력 전용으로 정리할 수 있음.

**(c) 동명 병합**  
로컬은 `official_name` 2쌍뿐. 운영에 지시 예시 학교가 있으면 화면 병합(상위기관·지역 보여 주고 참조 이전)이 별도 단계 후보. 이번엔 경고+확인만.

**(d) 같은 원칙 확대 후보**  
영업 파이프라인(`sales_projects`), 점검 사이트 목록(검색은 이미 95-6/9A 전 조직), AS 목록. 쓰기는 조직 유지가 자연스러움.
