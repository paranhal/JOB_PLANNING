# 95-28 주간 보고 — 미연결 사업 행 일괄 추가

작성: 2026-10-24 · D-172. VERSION `95-28`. 마이그레이션 없음. 운영 배포 안 함.

## 원인 (§2 가정과 일치)

`listCompanyUnassigned` 의 `addIf` 는 `project_id` 가 비었거나, 값이 있어도 그 조직 `weekly_report_rows` 의 `mapped[pid]` 가 거짓이면 미배정에 넣는다. 화면이 사업명을 붙이면 **업무→사업은 되어 있고 행만 없는 경우**다. 구역 제목 「(사업 연결 안 됨)」이 두 경우를 섞어 오해를 만들었다.

§3-1 픽스처(O03, P1 행 없음 3건 · P2 행 있음 1건 · 사업 없음 1건, 지난주 완료): 수정 전 Unassigned는 P1 3 + 사업 없음 1, P2는 없음(`Reason` 공백으로 실패). 수정 후 P1=`no_row`, 사업 없음=`no_project`.

로컬 `server/data/app.db` 의 O03 `weekly_report_rows` 는 0건이라 SI 실주차 건수는 여기 적지 않았다(고객·직원 이름 금지).

## 변경

- 집계 결과에 `Reason`(`no_row`|`no_project`)을 채우고 `SplitCompanyUnassigned` 로 묶음. 새 업무 쿼리 없음.
- 부분 템플릿 `stats/_weekly_unassigned.html` 을 95-27 화면·예전 `reports.html`·시트 결과 화면이 같이 쓴다. 제목: `보고서에 포함되지 않은 활동 N건`.
- `POST /stats/company-weekly/rows/from-projects` → 기존 `InsertWeeklyReportRow` / `SetWeeklyReportRowActive`. 허용 사업은 `ListWeeklyRowProjects`. 타 조직은 확인 체크. 한 트랜잭션.
- `POST /stats/company-weekly/tasks/project` → 기존 `SetTaskProject` + 조치 기록 `사업 연결: 없음 → …`. 상한 200. 완료 잠금은 수정 비밀번호. 이름 추측 자동 연결 없음.
- 행 관리: 최근 8주 `ListUnmappedWeeklyProjects`(같은 집계 재사용).
