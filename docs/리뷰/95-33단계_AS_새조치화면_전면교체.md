## 동작

- AS 건을 여는 기본 주소는 `/as/:id/action`. Go `asOpenHref` / 템플릿 `asHref` (`model.ASOpenHref`).
- `GET /as/:id` 는 `legacy=1`·`embed=1`·POST 가 아니면 **302** → `/as/:id/action`. 타 조직 ID 는 리다이렉트 전에 **404**.
- `legacy=1` 이면 예전 `as/show.html` + 배너 「예전 화면입니다. 새 조치 화면으로」. 사이드바 「예전 화면 보기 › AS 접수 상세 (예전)」 = `/as?legacy=1`. 새 화면 상단 「예전 화면으로」.
- 접수 iframe 은 `/as/:id?embed=1` 유지(중첩 조치 화면 방지).
- 예전 화면에만 있던 기능을 조치 화면으로 옮김: 보고서 이력, 지원업무, 행정 이관, 삭제, 재접수, 고객/기기 이력, 이관 배너, 함께 접수된 건, 긴급 뱃지. 95-8 레이아웃(고정 헤더·독립 스크롤)은 유지.
- 저장 후 복귀(`as.go` POST, `as_unlock`/`as_to_admin`/`as_support`/`attachment`/`as_report`)는 `/action?ok=`/`?err=` 이고 `asShowOK("report_saved")` = 「저장했습니다」.
- 행정 이관으로 만든 `work_tasks` 에 `org_id` 를 넣는다. 조직관리자가 옮겨 온 업무 상세를 열 수 있다.
- 95-26 타팀 지원·95-25 AssigneePicker 는 이 단계 범위 밖. `as_href.go` 주석.

## §2 치환 grep

### 전 (지시서 점검)

진입이 `href="/as/{{.ASID}}"` 또는 Go `"/as/"+id` 로 접수 상세를 가리키던 곳:

`as/_list_table.html`, `_kanban_col.html`, `_history_table.html`, `_gap_receipts.html`, `_parent_complete.html`, `_transfer_link.html`, `customer/tab_as.html`, `workboard/task_show.html`, `stats/list.html`·`overview.html`·`_case_table.html`, `workboard.go` ASHref/SourceHref, `meeting_weekly_edit.go`, 주간 미배정, POST 리다이렉트(`as.go`·`as_unlock.go`·`as_to_admin.go`·`as_support.go`·`attachment.go`).

### 후 (2026-10-25)

```
rg 'href="/as/\{\{' web/templates --glob '*.html' | rg -v '/action|/edit|/report|/work/|/new|/stats|/search|/knowledge|/keywords|/kb/'
# (출력 없음 — 접수 상세 하드코딩 진입 없음)

rg '"/as/" \+' internal --glob '*.go'
# Show embed PhotoRedirect 만 /as/:id?embed=1 (의도)
# 나머지는 asOpenHref / asOpenHrefQuery
```

템플릿 목록·칸반·이력·고객 탭은 `asHref` / `asLegacyHref`. JS 동적 행(`form.html`·`action.html` 이력 테이블)은 `'/as/'+id+'/action'`.
