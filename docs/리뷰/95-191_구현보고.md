# 95-191 구현 보고 — 완료·취소 업무의 등록정보 수정(관리자급 허용)

작성: 2026-11-14. 푸시·배포·VERSION 변경 없음. 작업지시서 파일(95-191)은 찾지 못해 붙여 주신 지시문과 확인 뒤 정한 기본안으로 진행했다. 앞서 한 번 올라온 반대 방향 지시(「완료 건 수정 링크 숨김」)는 이번 지시로 대체해 따로 하지 않았다. 지시서와 다른 점이 있으면 알려 주세요.

## 0. 확인 결과 (변경 전)
- `EditTask`(`/edit` 열기)와 `UpdateTask`의 `scope=register`(등록 정보 저장), `SaveTaskAssets`(설치자산 저장)가 모두 `denyUnlessCanPlanEdit` → `canPlanEditTask` 가 **완료·취소 업무를 거부**하고, 거부는 `echo.ErrForbidden`(JSON 403)이었다.
- 상세 「수정」 링크(task_show.html)는 `CanWrite` 만 봐서 완료 건에도 보였고, 눌러서 /edit 에서 JSON 오류를 만났다. 「계획 수정」은 `CanPlanEdit`.
- `model.IsAdminGrade` = 조직관리자·비전관리자.

## 1. 재현 (수정 전)
임시 DB, 도서관 조직관리자가 완료 업무 `/edit` → **403 `{"message":"Forbidden"}`**. 수행 담당의 완료 건 상세에는 안내 문구가 없었다. 재현 시험이 수정 전 실패(3건)했고 수정 후 통과한다.

## 2. 변경
- **`canEditRegistrationTask`**(새, `workboard_overlap.go`): 진행 중 업무는 `canPlanEditTask` 와 같고, **완료·취소 업무는 관리자급(`IsAdminGrade`)만** 허용한다(읽기 전용·쓰기 권한 없음·다른 조직 업무는 기존대로 거절). **`canPlanEditTask` 는 바꾸지 않았다**(이월·분할·칸반 이동·AS/점검 조치 화면 그대로).
- 적용 범위(지시대로 등록 정보 경로만): `/edit` 열기(`EditTask`), 등록 정보 저장(`UpdateTask` scope=register), 같은 화면의 설치자산 저장(`SaveTaskAssets`), 상세 「수정」 링크.
- **관리자급이 아닌 사용자**가 완료·취소 업무의 `/edit` 로 직접 들어오거나 저장하면(쓰기 권한은 있는 경우) JSON 403 대신 **상세 화면으로 돌아가 「완료된 업무는 수정할 수 없습니다」(취소는 「취소된 업무는…」)** 를 보여 준다. 그 밖의 거절(권한 없음·타 조직)은 기존 403.
- 상세 화면: `CanEditRegistration` 이면 「수정」 링크(`data-registration-edit`), 쓰기 권한은 있지만 닫힌 업무면 링크 대신 안내(`data-registration-lock`).
- **이력**: 관리자가 완료·취소 업무를 저장하면 `audit.LogWithReason`(work_tasks / 「완료 업무 등록정보 수정(관리자)」, 변경 전후 제목·상태)로 남긴다. 업무 전용 이력 테이블은 없다.
- 스키마·DB 변경 없음. 상태는 저장 폼이 보낸 값(현재 상태)을 그대로 쓰므로 수정만으로 완료가 풀리지 않음을 시험으로 확인.

## 3. 변경 파일

- 신규: `server/internal/handler/workboard_registration_95_191_{http,browser}_test.go`, `server/web/static/js/95_191_registration_edit_browser.mjs`

- HTTP `TestHTTP95_191_*`(3): 관리자 완료·취소 `/edit` 200·상세 링크·「계획 수정」 없음(canPlanEditTask 불변)·저장 반영과 상태 유지 / 수행 담당·타 조직: 링크 없음+안내(완료·취소 각각), 직접 `/edit` 와 저장이 상세로 이동(303, 안내 포함), 타 조직은 열람 불가 / 진행 중 건 링크·열기·저장 정상.
- 실제 브라우저 `Test95_191_BrowserRegistrationEdit`(임시 DB, 390/1440): 수행 담당 상세에 링크 없음·안내 표시, 직접 `/edit` 가 JSON 없이 상세로 돌아와 안내, 진행 중 건 링크 있음, 관리자가 링크를 눌러 수정 화면에서 제목을 고쳐 저장(상세에 반영), 가로 넘침 없음. 스크린샷 `docs/리뷰/screenshots/95-191/`.

## 5. 같은 패턴(링크는 CanWrite·서버는 다른 조건) 점검
- `task_show.html:81` 「계획 수정」: `CanPlanEdit` — 이미 서버와 일치.
- `task_show.html:332` 「수정」: **수정함**(`CanEditRegistration`).
- 칸반 카드 「수정」(`kanban/_board.html:93`, `workboard_person.go:161` 이 `EditHref` 를 항상 채움)과 일정표 `data-edit`(`board_day.html:162`): 링크 조건은 `CanWrite`/`EditLocked`. 완료 카드에서 눌러도 이제 JSON 이 아니라 관리자는 열리고, 그 외는 상세 안내로 돌아간다(링크를 숨기지는 않음).
- 일정표 계획 수정 링크(`PlanEditHref`, `stampBoardPlanEdit`)는 `canPlanEditTask` 로 이미 일치.
- 서버가 `/edit` 로 보내는 곳(`work_reschedule.go`, `workboard_recurrence.go`, `workboard_overlap.go`)은 진행 중 업무 흐름이라 영향 없다.
- `workboard_items.go`, `workboard_carry.go`, `workboard_split.go`, 칸반 이동은 `canPlanEditTask` 를 그대로 써서 완료 건 거부(JSON)가 그대로다. 사용자가 이 화면 링크를 직접 보지는 않는다.

## 5-2. 후속: 일정표·칸반 완료 카드의 「수정」 숨김 (「그럼 구현해 줘」)
- 일정표 카드(`WBCard`)에 `NoEdit` 를 두고, 완료·취소 업무를 고칠 수 없는 사용자(관리자급 아님)의 카드에는 `EditHref()` 가 빈 값을 준다. 일일 보기·등록 일정표(`taskCardFor`/`Register`)와 보드 막대(`stampBoardMove`)에 적용. 열린 업무 카드는 그대로.
- 등록 칸반의 「오늘 완료」 열 카드도 같은 규칙(`stampKanbanRegistrationAccess`).
- 시험 `TestHTTP95_191_BoardAndKanbanEditHidden`: 관리자는 완료 카드에 수정 링크가 있고 수행 담당은 없으며, 진행 중 카드는 둘 다 그대로. (브라우저 클릭은 이 후속에 따로 추가하지 않았다.) 후속 포함 전체 게이트: 통과 2783 / 실패 7(기존 7 · 신규 0).

## 6. 한계·남은 것
1. 칸반 「오늘 완료」 열 밖에 있는 취소 카드 등은 이 규칙을 적용하지 않았다(서버가 막고 안내로 돌려보낸다).
2. 이력은 감사 로그뿐이다. 화면에서 보는 「수정 이력」은 없다.
3. 관리자가 완료 건에서 상태를 직접 바꾸는 것은 막지 않았다(등록 화면의 상태 선택은 기존 그대로).
