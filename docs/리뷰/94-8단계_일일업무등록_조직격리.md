# 94-8단계 보고서 — 일일업무등록 조직 격리

기준: `커서_작업지시서_94-8_일일업무등록_조직격리.md` (D-126)  
실행일: 2026-10-20. 작업 DB는 테스트 temp DB만. 운영·개발 DB 변경 없음. 배포 없음.

## 원인

`WorkboardHandler.Register`의 팔레트만 `currentOrg`를 쓰고, 일정표·날짜미정·칸반·자동배치는 전 조직 `work_tasks`를 읽었다.

## 수정

- `work_tasks` 조회: 행 `org_id` → 담당자 `users.org_id`(id 또는 이름) → `created_by_user_id` 소속. 셋 다 비면 조직 지정 화면에서 제외, `OrgAll`에서만 보임.
- `ListTasksBetweenForOrg` / `ListUndatedASTasksForOrg` / `ListTasksNeedingAutoPlaceForOrg`
- 정기점검 동기화 `SyncMaintenanceBoardRangeForOrg`(사이트·고객 `org_id`). 조직 지정 시 고아 삭제는 하지 않음.
- 칸반 `ListBucketOnForOrg` + `ListUnplannedForOrg` 후 필터.
- 고객 선택 `ListAllInOrg`. 사업 `ListProjects`는 `work_projects`에 조직 컬럼이 없어 이번엔 그대로(아래 감사).
- 쓰기: `denyOtherOrgTask`는 조직 지정 시 `org_id`가 다르거나 비면 404. 내리기·칸반 이동도 동일.
