# 95-38단계 — AS 접수 저장 완료 팝업, 중복 방지, 접수 삭제

기준: `커서_작업지시서_95-38_AS접수_저장완료팝업_중복방지_접수삭제.md`  
선행: 95-36A. 실행일: 2026-10-25.

## 한 줄

`/as/new`에서 접수가 되면 조치 화면(또는 2건 이상이면 목록)에 일회성 팝업으로 접수번호·기관·증상 앞 10글자를 보여 주고, 같은 내용의 연속 저장은 토큰·60초 중복 검사로 막는다. 비전관리자·자기 조직 조직관리자·미처리 건의 접수자는 확인 모달 뒤 기존 `ASRepo.Delete`로 지울 수 있다.

## 구현 요지

- `Create` 성공 시 `jp_flash_ok`에 AS ID만 넣고, 다음 렌더에서 DB를 조회해 팝업을 그린 뒤 쿠키를 지운다. 새로고침에는 다시 뜨지 않는다.
- 신규 폼 `submit_token`(10분 메모리). 같은 토큰 재전송은 신규 생성 없이 첫 건으로 안내. 토큰이 있는 POST만 60초 동일 조직·고객·증상 중복 경고. 「그래도 새로 접수」(`confirm_dup=1`)만 생성.
- 「접수 등록」은 `data-submit-guard`로 제출 시 「저장 중…」 비활성화.
- `POST /as/:id/delete`에서 `adminOnly` 제거. `canDeleteAS` + CSRF(`jp_csrf`). 이관/재접수 연결 건은 삭제 거부.
- `ASRepo.Delete` 같은 트랜잭션에서 조치·하부업무·키워드·자재·첨부·알림·일일 업무(관련 자식 테이블)를 정리. `work_task_members`는 업무 행 삭제 트리거가 지운다(주담당 트리거와 충돌하지 않음). 자재 재고 반환 규칙은 없음(사용 기록만 삭제).
