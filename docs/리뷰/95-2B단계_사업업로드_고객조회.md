## 5. 질문 (임의 결정 금지)

### 5-4. SI 계정에 도서관 사업이 「사업 등록 관리」에 보이는 이유

**86단계 팀간 공개가 아니다.** `docs/진행현황_지시서_20261020.md`에 86은 「해당 없음 / 구현하지 말라는 표시. `is_shared` 코드 0건」.

원인은 **92단계가 지적한 격리 누락**이다. `listProjects`/`ListFiltered`/`ListContracts`는 `work_projects.org_id`를 WHERE에 쓰지 않고, 핸들러도 `currentOrg`로 목록을 거르지 않는다(`커서_작업지시서_92단계_조직별_데이터_격리_점검.md` 표 1). 그래서 SI 조직관리자에게 도서관 사업이 그대로 보인다.

현재 정책과의 일치:

- **업로드(쓰기)**: 조직관리자는 자기 부서 행만(이번에도 권한 확대 없음). 맞음.
- **작업 폼 사업 콤보(95-9A Q3 / 95-12)**: 조직 무관, 취소·종료만 제외. 의도적으로 전사 후보.
- **사업 등록 관리 목록**: 92 사용자 요구(「타 부서 자료는 보이지 않아야」)와 **불일치**. 고치려면 목록·상세에 org 필터를 넣는 별도 결정이 필요하다. 이번 단계는 조회만 손대지 않음.

### 5-5. 계약상대(원청·중간업체)와 최종고객 구분 표시

보류. `customers.party_kind`(`customer`/`partner`/`vendor` 등)는 있으나 고객 목록에서 계약상대 vs 최종수요처를 나누어 보여 주는 화면은 없다. 업로드는 발주처·최종수요처를 **같은 고객 마스터**에서 이름으로만 찾는다. 구분 표시는 이번 범위 밖.
