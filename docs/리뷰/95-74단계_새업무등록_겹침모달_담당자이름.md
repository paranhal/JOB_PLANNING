# 95-74단계 — 새 업무 등록 저장 무반응 · 담당자 고유번호 표시

기준: `claude/커서_작업지시서_95-74_긴급_새업무등록_저장_무반응_담당자_고유번호표시.md` (저장소에 없음, 채팅 요점).  
실행일: 2026-11-02. VERSION `95-74`. 마이그레이션 없음. **운영 DB는 코드로 고치지 않음.**

## 원인

1. `#overlap-resolve` 와 새 업무 등록 모달이 둘 다 `z-50` 이고, 겹침 모달이 `base.html` 앞쪽(콘텐츠·새 업무 모달보다 DOM 앞)에 있었다. 같은 z-index면 뒤에 그려진 새 업무 모달이 겹침 해결을 가렸다. [저장]은 409를 받았지만 사용자는 반응이 없고, 새 업무 [취소]로 위 모달이 사라진 뒤에야 「시간이 겹칩니다」가 보였다.
2. `assignee_picker.js` `nameOf` 는 체크박스·그룹 구성원에서 id를 못 찾으면 **id 문자열을 그대로** 반환했다. `USR-1792139370211635000` 은 운영 `users` 의 **양현모** (`hmyang`, 역할 `tech`, 조직 `O02` 미디어, 활성). 목록에서 빠진 이유: 선택 id가 담당자 체크박스 DOM에 없고(그룹 구성원은 펼치기 전 `x-for` 미렌더, 또는 그룹 JSON `name` 공란, 또는 `ListAssignable` 에 없는 extra id) `nameOf` 가 id로 떨어졌다. 운영 행은 수정하지 않았다.

## 수정

- `#overlap-resolve` 를 `body` 끝으로 옮기고 `z-[80]` (AS 삭제 `z-[70]` 보다 위). 열 때 `document.body` 끝으로 재부착.
- Esc(캡처)·Tab 포커스 트랩. 취소/Esc는 해결 모달만 닫고 `pendingForm`·새 업무 입력은 유지. 새 업무 모달을 닫으면 `closeOverlapResolve(true)` 로 해결 모달과 pending 을 함께 비움.
- `handleKeepModalResponse` 와 keep-modal `fetch` 는 409/400/500/네트워크/필수 누락마다 플래시 또는 리다이렉트. `form.submit()` 우회 삭제.
- 서버 `PickerNames` (`pickerDisplayName`: FullName → Username → `담당자`, `USR-` 금지). 선택 id·현재 사용자·그룹 구성원을 `ensurePickerUsers` 로 목록에 포함. `nameOf` 는 사전·그룹·체크박스 순이며 **USR- / raw id 를 절대 표시하지 않음**.

## §3-1A 겹침 4가지 선택 후 저장 완료

저장 → 겹침 선택 화면(`#overlap-resolve` z-[80])이 맨 위·포커스. 선택 후 **같은 `CreateTask` 경로**로 검증·담당자·사이트 다건·반복·이력·알림·조직 격리·redirect 를 수행한다.

| 선택 | 새 업무 | 기존 업무 | 이동 |
|------|---------|-----------|------|
| 담당자만 빼고 새 계획 등록 | 저장 | 겹친 **전체**에서 해당 담당자만 제외 | 두 모달 닫힘 → 일일 업무 목록 |
| 기존 계획 삭제 | 저장 | 겹친 전체 삭제. 원본 연결·완료는 선택 화면 안 오류 | 일일 업무 목록 |
| 기존 계획 수정 | **저장하지 않음** | 그대로 | 기존 계획 수정 + 안내 문구 |
| 취소 | 저장하지 않음 | 그대로 | 선택 화면만 닫힘, 입력 유지 |

처리 중 버튼 비활성·「처리 중…」. 실패는 `#overlap-resolve-err`. 충돌 여러 건은 일괄. 선택 화면이 열린 사이 목록이 바뀌면 409로 재검사.

테스트: `Test95_74_Overlap31A_*` (HTTP 4선택·일괄·재검사·원본/완료/조직·사이트·반복·이력) + Playwright `95_74_overlap_31a_browser.mjs` (포커스·Esc·복귀·elementFromPoint·4선택 실제 클릭).

## §7 계획 수정 폼 태그 조기 닫힘

`task_show.html` 수정 폼 `class="…text-sm">` 의 여분 `>` 때문에 `data-require-assignee` 와 `@submit`(openOcc 확인창)이 속성 대신 본문 글자로 나왔다. `>` 를 제거하고 `@submit="…">` 에서만 태그를 닫았다.

- 조직관리자 렌더 HTML: 본문 텍스트에 `data-require-assignee` / `@submit` / `openOcc` 없음. `form.js-keep-modal` 에 `data-require-assignee`·`@submit` 있음. (`Test95_74_EditFormAttrsNotLeaked`)
- keep-modal·겹침 모달 `#overlap-resolve` 는 같은 레이아웃에 유지.
- Playwright: 담당자 비움 → 「담당자를 선택하세요」. 담당자 채움 + 완료 + openOcc>0 → 확인창. (`Test95_74_EditFormBrowserConfirmAndAssignee`)
