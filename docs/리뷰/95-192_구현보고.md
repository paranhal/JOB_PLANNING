# 95-192 구현 보고 — 주간 보고서: 정기점검 진행율 폼 제거, 팀 전체 금주·차주 추진내역

작성: 2026-11-14. 푸시·배포·VERSION 변경 없음. 작업지시서 파일(95-192)은 찾지 못해 붙여 주신 지시문과 확인한 기본안으로 진행했다(§4 원문은 못 봤다). 지시서와 다른 점이 있으면 알려 주세요.

## 0. 확인 결과 (변경 전)
- `EncodeCompanyWeeklyDoc` 는 `{progress, rows}` 두 키의 고정 구조체만 쓴다. 새 최상위 키는 Parse 가 읽지 않고 Encode 가 쓰지 않아, 저장·진행율 저장·자동 생성·다시 집계(모두 Parse → 수정 → Encode)를 한 번만 거쳐도 사라진다(확정만 원문 그대로 넘긴다).
- 진행율 폼은 `company_weekly.html` 의 `{{if and .Edit (eq .View.ProgressMode "manual")}}` 블록(`/stats/company-weekly/progress`).
- `extrasOnlyChanged` 는 행의 금주·차주 줄만 비교해, 확정 보고서에서 지원 필요사항·주요 의사결정만 바뀌면 확정을 유지한다.

## 1. 재현 (수정 전)
`{"rows":{…},"team_done":[…]}` 를 Parse → Encode 하면 **`team_done` 이 버려진다**(출력 `{"rows":{"401":{…}}}`). 수정 전 코드에서 임시 시험으로 확인했고, 정식 시험(`TestCompanyWeeklyDoc95_192_RoundTripKeepsTeamAndUnknownKeys`)은 수정 전에는 필드가 없어 컴파일에서 실패한다.

## 2. 변경
- **저장 형식**(`company_weekly_doc.go`): `CompanyWeeklyDoc` 에 `TeamDone`·`TeamPlan`(JSON `team_done`·`team_plan`, `omitempty`)과 `Extra`(알 수 없는 최상위 키 보존)를 추가했다. Parse 가 읽고 Encode 가 되돌려 써서, 앞으로 필드가 늘어도 같은 코드가 지우지 않는다. 옛 형식(행 맵만)·팀 전체가 없는 보고서는 `team_` 키를 만들지 않는다.
- **화면**: 진행율 폼 블록을 템플릿에서 **화면만** 제거했다. `SaveWeeklyProgress`(`/progress` 라우트)·저장된 `progress` 값·정기점검 카드의 진행율 줄·뷰의 `Progress*` 는 그대로다. 편집 모드의 저장 폼 맨 위에 「팀 전체」 구역(금주 추진내역·차주 추진계획 텍스트칸, 줄마다 한 항목)을 두고 같은 저장 막대로 저장한다. 읽기 모드에는 카드 위에 「팀 전체」 구역이 나온다.
- **저장**(`SaveWeeklyReport`): 폼에 `touch_team=1` 이 있을 때만 `team_done`·`team_plan` 을 `SplitWeeklyLines` 로 읽어 저장한다(다른 저장 경로가 팀 전체를 지우지 않는다).
- **확정**: `extrasOnlyChanged` 가 팀 전체 금주·차주도 비교한다 → **확정 보고서에서 팀 전체를 고치면 「작성 중」으로 돌아간다**(지원 필요사항·주요 의사결정만 바뀐 경우는 종전처럼 확정 유지).
- **엑셀**: 사업 행보다 앞의 **첫 데이터 행**에 「팀 전체」(담당·사업 열 비움, 금주·차주 열에 줄). **HWPX**: 팀 제목 아래 첫 항목 「▶ 팀 전체」. 사업 줄이 없고 팀 전체만 있어도 내보내진다.
- 스키마·DB 변경 없음(보고서 내용 JSON 안의 키만 늘었다).

## 5. 한계·남은 것
1. 진행율 입력 화면은 없어졌다. 기존에 저장된 `progress` 값은 DB·엑셀 진행율 열·정기점검 카드 줄에 그대로 남지만, 새로 입력할 방법은 `/progress` 라우트 직접 호출뿐이다(요청대로 경로는 남겼다).
2. 줄이 없는 주차(보고서 있음·카드 0)의 편집 화면에는 「넣을 줄 없음」 안내와 「다시 집계」만 나와 팀 전체 칸이 보이지 않는다.
3. 팀 전체 줄에는 수동 입력 표시(자동 집계 키)가 없다. 사업 행처럼 숨김·되살리기도 없다.
