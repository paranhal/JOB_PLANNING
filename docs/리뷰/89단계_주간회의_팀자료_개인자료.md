# 89단계 보고서 — 주간 회의 팀 자료 / 개인 자료 (D-95)

기준: `커서_작업지시서_89단계_주간회의_팀자료_개인자료.md` (개정), D-77·D-95, 75-D.

## 한 줄

메뉴 404는 **배포 이미지(`deploy/server-app.tar`, 2026-10-19 13:44)가 75-C 메뉴만 넣고 75-D 핸들러(`0f464f6`, 15:27) 이전 빌드**였기 때문이다. 소스에는 팀/내 자료를 나누고, 회의 화면에서 기존 권한으로 수정하며, 개인 엑셀·휴가·결재 카드를 붙였다.

## 404 원인 (89-A)

링크 오타가 아니다. 사이드바 `href`는 `/meeting/weekly`가 맞다.

| 확인 | 결과 |
|------|------|
| 소스 `cmd/server/main.go` | `GET /meeting/weekly` → `h.Meeting.Weekly` (커밋 `0f464f6`, 15:27) |
| 메뉴 `nav_menu.go` | `/meeting/weekly` (75-C `117d166`, 13:03에 먼저 들어감) |
| `deploy/server-app.tar` mtime | **13:44** (메뉴 커밋 이후, 핸들러 커밋 이전) |
| tar 레이어 문자열 | `/meeting/weekly` **있음**(메뉴). `meetingWeekMonFri` / `WeeklyMe` **없음**(핸들러 없음) |
| `VERSION` 워킹트리 | 75. HEAD 커밋 메시지 기준 핸들러는 이후 커밋에 있음 |
| 미들웨어가 라우트 미등록 | 없음. 인증 그룹 `g`에 GET이 그대로 있음 |

브라우저 JSON `{"message":"Not Found"}`는 Echo 기본 404다. **실행 중인 배포본에 라우트가 없어서** HTML 레이아웃 404도 나오지 않았다.

**재배포가 필요하다.** 이 단계에서는 운영 배포를 하지 않았다. 사용자 승인 뒤에 빌드·배포하면 된다.

재발 방지: `TestNavHrefsHaveGETRoutesInMain` — 메뉴 잎 `Href`마다 `main.go` GET이 있어야 한다. HTML `Accept` 404는 `error/not_found.html`(대시보드 링크), JSON은 기존 Echo 본문.

## 동작

- **팀 자료** `/meeting/weekly`: 로그인한 전원. 조직 범위 `currentOrg`. 담당자 드롭다운 유지. 기술 역할은 기본이 본인(기존 `resolveMeetingAssignee`), `assignee=all`이면 팀 전체.
- **내 자료** `/meeting/weekly/me`: 전원. 본인(view-as면 보고 있는 사용자)만. `assignee`/`mine` 무시.
- 탭 「팀 자료 | 내 자료」 모두에게 표시. 메뉴 「주간 회의 (팀)」「주간 회의 (내 자료)」 전원.
- **수정**: 행 「수정」 → 팝업(Esc, Tab 가둠, 닫으면 단추 포커스). AS는 기존 `UpdateVisitScheduledDate`·`UpdateReceipt`(이력 `data_change_logs`). 권한은 `canEditASReceipt`/`canSaveASReceipt`/`canEditTask`. 읽기 전용·view-as·타인 건·비전 관리자의 완료 잠금은 단추 숨김·서버 403. 비로그인 POST는 로그인으로.
- **개인 엑셀** `/meeting/weekly/me.xlsx`: `writeWeeklyStatsSheet`·`writeWeeklyAllListSheet` 재사용 후 본인 행만. 파일명 `YYYYMMDD_내주간자료_<이름>.xlsx`. 타인 쿼리 무시.
- **휴가·결재** 카드: 기존 `ListMine`·`ListInbox`. 잔여 연차는 원장 조회를 새로 만들지 않아 `—`. **협조(87)는 미구현이라 카드 없음.**

운영·개발 DB는 코드로 고치지 않았다. CSS 빌드는 기존 토큰만 써서 하지 않았다.

## 질문

### Q-1 (지시서 개정 전 초안) 개인 엑셀을 숨길지
개정안에서 **「내 주간 자료 엑셀」을 두라**고 확정되어 `/meeting/weekly/me.xlsx`를 넣었다.

### Q-2 (초안) 팀 자료를 조직관리자만?
개정안에서 **전원 열람**으로 폐기했다. 기술 역할의 기본 담당자 필터(본인)는 기존 일일 회의와 같다. 팀전체는 드롭다운 `팀전체`.

### Q-3 (초안) 휴가·결재·협조를 주간에 넣을지
개정안에서 개인 자료 카드로 넣었다. 협조는 87 미구현이라 숨김(Q-6).

### Q-4 일일 업무 회의(`/meeting`)에도 같은 직접 수정을 적용할지
**지금은 주간 화면만** 적용했다. 일일은 조회 전용(`CanWrite=false`)을 유지한다. 같은 팝업·권한 함수를 재사용할 수 있으니, 쓰겠다면 다음 단계에서 `/meeting`에만 붙이면 된다.

### Q-5 일반 팀원이 팀 자료에서 남의 업무를 고치게 되는 경우

회의 화면은 권한을 넓히지 않는다. 수정 단추가 안 보이는(서버도 거부하는) 대표 사례:

| 상황 | 단추 | 서버 |
|------|------|------|
| 기술 본인 진행 AS | 보임 | 저장 |
| 기술, 다른 담당 AS | 숨김 | 403 |
| 읽기 전용 | 숨김 | 403 |
| view-as | 숨김 | 403 |
| 비전 관리자, 완료 AS(잠금 미해제) | 숨김 | 403 |
| 완료 AS 본인(등록·배정) | 기존 D-65대로 가능 | 기존 접수 수정과 동일 |
| 조직관리자(자택 조직) 타인 진행 건 | 기존 AS 규칙대로 가능 | 기존과 동일 |
| 타 조직 건 | `GetByID(currentOrg)`로 없음 | 404 |

일반 팀원이 팀 자료에서 **남의 건을 고치려면 그 업무 기존 규칙이 허용할 때만**이다(예: 조직관리자). 기술 역할은 본인 배정만.

### Q-6 휴가·협조가 없을 때 카드 숨김으로 충분한지
휴가·결재 기능은 있어 카드를 보여 주고, 해당 주 0건이면 안내 문구·건수 `—`다. **협조(87)는 기능 자체가 없어 카드를 숨겼다.** 잔여 연차는 원장 API를 이 단계에서 연결하지 않아 `—`다. 숨김으로 충분하다. 협조가 생기면 같은 자리에 카드를 켜면 된다.
