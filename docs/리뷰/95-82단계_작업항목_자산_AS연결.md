## §0 사용자 확정 4가지

1. 항목은 상위 작업 일정 안에서만 수행. **항목 날짜·「하위 업무로 올리기」는 만들지 않음.** 기존 `parent_task_id` 하위 업무는 유지.
2. 설치자산(`assets`)과 `work_task_item_assets`로 연결하고 자산 상세에 작업 이력을 남김.
3. 사업·작업 단위 집계 「장착 N건 · AS N건」(0건 생략). 화면은 모두 `ItemKindSummary`/`ItemKindSummaries`.
4. 상위 담당자 **표시** = 항목 담당 합집합(체크박스). `work_task_members` / `work_tasks.assignee` 는 **바꾸지 않음**.

## §4-4 일정 이중 표시 방지 — 방식과 근거

**방식:** `work_task_items.as_id` 가 있는 접수는 **일일업무 `work_tasks`(source=AS) 를 만들지 않고, 이미 있으면 지운다.**

근거:

- 캘린더 막대는 `ListTasksBetween` 의 `work_tasks` 이다. `schedule_confirmed=0` 이어도 `SyncASDailyTask` 가 담당자만 있으면 날짜가 있는 일일업무를 만든다 → 상위 작업과 **같은 날 두 막대**.
- `ReconcileASDailyTasks` 는 모든 접수를 `SyncASDailyTask` 에 넘긴다. 링크만 두고 Sync를 그대로 두면 정리 루프가 막대를 되살린다.
- 그래서 `SyncASDailyTask` 진입 시 `ASLinkedToWorkItem(asID)` 이면 `DeleteTasksBySource(WBSourceAS, asID)` 하고 return. 링크·신규 접수 직후에도 Sync를 한 번 불러 기존 막대를 지운다.
- 새 접수는 `VisitScheduledDate`=상위 작업일, **`ScheduleConfirmed=false`**. AS 목록·접수 관리는 `as_receipts` 를 그대로 보여 준다.
- 독립 AS(항목 미연결)의 확정 일정·95-80 지연 판정은 **변경 없음**.

## 기본값으로 정한 기타

- 관리유형 기본은 **빈 값(선택 필수)**. 「정기점검」을 미리 넣지 않음.
- AS 대상 자산 목록 = **이 작업 `customer_id` 의 자산만**. 다른 기관 건수는 `hidden` 안내.
- 공사·기타 자산 연결 role=`ref`(선택). 장착 등록 role=`install`. AS role=`service`.
- 집계 「N건」= **항목 수**. 수량 합은 상세 `LineQty`(장착 N건(M대))만.
