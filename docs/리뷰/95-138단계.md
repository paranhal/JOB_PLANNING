## 원인 후보 판정

**① 고객 `type=hidden` required**  
코드에 `required` 있음. Chromium에서 `type=hidden`은 `:invalid`에 안 잡힘(D). **침묵 차단의 실체는 hidden required가 아니라, 열자마자 `visit_date` x-model이 비어 네이티브 검증(A)** 이거나, hidden이 빈 채로 서버 400 → flash+303으로 모달이 닫혀 **창 안 오류가 없음**.

**restore `items[0]` 대체 (C, 코드 확정)**  
`customerCombo.restore()`:

```
var it = items.find(id === selectedId) || items[0];
// selectedId는 안 바꾸고 q/label만 덮음
```

include가 빗나가면 칸에는 다른(또는 유일) 고객 이름이 보이고 hidden은 원래 ID. 운영에서 직산이 목록 8건에 없고 include가 빠지면 빈 칸 또는 엉뚱한 이름.

**② 담당자 표시 vs 전송**  
수정 직후(A) picker는 비어 있고, hydrate 후(B) 버튼·hidden이 같이 `관리자`. hydrate가 늦거나 실패하면 이전 방문 잔상이 남을 수 있음(이번 픽스처는 방문 1건이라 양기헌 잔상은 못 봄). `data-require-assignee`는 hidden이 비면 배너(E). **버튼에 이름이 있는데 hidden이 빈 경우**는 hydrate 실패+이전 extra 가 유력.

**③ 서버 거부 후 입력 소실**  
`UpdateVisit` 고객 없음 → 400 → `http_error` flash 쿠키 + Referer 303. 모달이 닫히고 값이 폼에 안 남음. 두 번째 저장에서 담당 필수만 보이면, 그때는 고객은 채워지고 담당 hidden만 빈 상태.
