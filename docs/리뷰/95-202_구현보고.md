## 0. 0단계 확인 결과 (변경 전, 읽기 전용)
**로컬 DB 사본(10월 25일자 구버전) 기준** — 운영 값은 이 환경에서 확인하지 못했다(지시서의 825건은 다른 사본 값).
- **자산 연결 없는 AS**: 취소·테스트 제외 1,445건 중 **855건(59%)**. 상태별 완료 845·담당자 배정 2·진행 3·부분완료 5.
- **자산 연결 없는 정기점검 방문**: 868건 **전부**(사본에 `maintenance_visit_targets` 가 0건). 제품별 KLAS 489(`K-LAS` 표기 1건 포함)·앤로보틱스 340·테크센터정기점검 8·제품 빈값 30, 완료 701·미완료 167. 운영은 95-165D 이후 일부 연결됐을 수 있다.
- **고객 자산 보유**: AS 미연결 고객 80곳 중 자산이 하나도 없는 곳 19곳. 정기점검 고객 98곳 중 자산 없는 곳 14곳. AS 미연결 고객의 자산 수 분포는 0개 19곳·1개 15곳·2개 4곳·3개 6곳·4개 이상 나머지 → **자산이 1개뿐인 고객 15곳**이 일괄 연결 후속 후보.
- **`/as` 목록의 조직·권한 범위**: `AppendOrgSQL("ar", currentOrg(c))` + `mineAssigneeCond`(담당자·업무그룹 구성원). 기술담당(`tech`)은 기본 「내 배정」(`mine=0` 으로 해제), `assignee`/`assignee_name` 이 있으면 해당 담당자 필터, 그룹 포함은 `viewGroupInclude`. → 새 목록이 같은 규칙을 그대로 쓴다.
- **정기점검 조직·권한**: 방문에는 `org_id` 가 없고 `plan_id → maintenance_plans.org_id` 로 구분한다. `/maintenance` 조회 라우트에는 별도 메뉴 권한 가드가 없어(수정만 `RequireMaintenanceEdit`) 정기점검 탭은 AS 메뉴를 볼 수 있는 모든 role 에게 보인다(탭 숨김·403 불필요). 담당자 조건은 `mineOrGroupCond(AssigneeKindMaintenance, "v.", …)`.
- **기존 판정·제목 함수**: 「연결됨」을 한 번에 판정하는 함수는 없고 `ListASLinkedAssets` 는 건별 조회(N+1)라 쓰지 않았다. AS 작업명은 `model.FormatASWorkTitle`, 정기점검은 번호용 `FormatMaintenanceVisitNumber` 뿐이라 작업명(`{사이트} {제품} 정기점검 {회차}회`)을 새로 만들었다.
- **성능 가드**: `TestASListAndShowQueryPath` 는 `List` 본문에 `.Exec(`·`UPDATE`·`CloseOpen` 이 없어야 한다.

## 1. 변경
- **판정 SQL 한 곳**(`repository/as_unlinked.go`): `asUnlinkedWhere`·`mntUnlinkedWhere` 상수. 건수·목록·시험이 모두 같은 상수를 쓴다.
  - AS: `as_receipts.asset_id` 가 비어 있고(NULL·공백), 해당 AS 업무(`source_type='as'`)에 `work_task_assets` 도 없다. 취소·테스트 제외.
  - 정기점검: `maintenance_visit_targets` 에 `asset_id` 가 있는 행이 없고, 해당 방문 업무(`source_type='maintenance'`)에도 `work_task_assets` 가 없다. 테스트 제외, 완료된 방문 포함.
  - 자산을 연결하면 다음 조회부터 자동으로 빠진다(별도 처리 없음).
- **조회**: `CountUnlinkedAS/Mnt`(범위만), `ListUnlinkedAS/Mnt`(최근 접수일·방문일 순, 20건 페이지). 후보 자산(자산 수·제품군 요약)은 **고객 ID 묶음 한 번의 집계 쿼리**로 구한다(N+1 없음). `days_elapsed` 가 NULL 이어도 읽히게 `COALESCE` 했다(완료 일시가 없는 옛 건 대비).
