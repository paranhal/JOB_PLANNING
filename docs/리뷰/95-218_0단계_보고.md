# 95-218 0단계 보고 — 정기점검 사업 연결 거절 · 완료 시 사업 미저장 · 저장 시 줄 중복

작성 2026-11-23 · 코드 변경 없음(재현은 `server/` 복사본에서 임시 시험으로만 수행, 저장소에는 없다) · 운영 DB 접근 없음

## 결론
| 증상 | 판정 |
|---|---|
| ① 사업 연결이 「사이트가 등록되지 않은 사업」으로 거절 | **확정.** 연결 검사는 `project_sites`만 보고, 방문 사업 자동 판정은 `project_scope_rules`만 본다. 범위 규칙으로만 묶인 사업이면 연결은 항상 거절된다(H1). 같은 이름 사업 2개에서 사이트가 없는 쪽을 고르면 거절(H4) |
| ② 조치 완료해도 사업이 저장되지 않음 | **확정.** 완료 저장은 사업을 확정하지 않는다. 사업이 비어 있고 후보가 `project_sites` 한 곳뿐인 경우에도 빈 채로 완료된다. 범위 규칙이 있는 경우만 저장 시 옛 판정으로 채워진다 |
| ③ 저장할 때마다 같은 내용이 복사 | **현재 코드에서 재현 안 됨**(아래). 구조적 약점 2개는 확인. 원인 확정에는 운영 문서 JSON이 필요하다 |

## 1. ①② 재현표 (사업 WP-M, 방문 V1·V2 미완료, 사업 비어 있음)
| 경우 | 새 방문 자동 판정 | 보고서에서 사업 연결 | 조치 완료 저장 후 `project_id` |
|---|---|---|---|
| ⒜ `project_sites`만 | 빈 값 | **허용**(WP-M 저장) | **빈 값** (완료는 됨) |
| ⒝ 범위 규칙만 | WP-M | **거절** 「이 사이트가 등록되지 않은 사업입니다」 | WP-M (옛 판정이 채움) |
| ⒞ 둘 다 없음 | 빈 값 | **거절** | **빈 값** (완료는 됨, 경고 없음) |
| ⒟ 같은 이름 2개, 사이트는 WP-M2에만 | 빈 값 | WP-M(사이트 없는 쪽) 선택 시 **거절** | 빈 값 |
| ⒠ 둘 다 있음 | WP-M | 허용 | WP-M |

- 같은 구조로 AS(`as_project.go`)도 같은 검사(`requireVisitSiteProject`)를 쓴다. **일반 업무** 연결에는 사이트 검사가 없다(코드 확인) → 방문·AS만 거절되는 비대칭.
- 후보가 하나뿐인 ⒜에서 완료 시 자동 저장이 없고, 후보가 없는 ⒞에서도 완료를 막거나 알리지 않는다.

## 2. ③ 저장 반복 재현표 (현재 코드)
행: 사업 행(키 있는 자동 줄 3개), 정기점검·AS 활동 행, 기술영업 활동 행. 화면에 그려진 텍스트를 그대로 저장 → 다시 열기를 반복.

| 시나리오 | 저장 1회 | 2회 | 3회 |
|---|---|---|---|
| A 수정 없이 저장 | 줄 수 불변 | 불변 | — |
| B 저장 사이 데이터 변동(점검 1건 추가) | 불변 | 불변 | 불변 |
| C 한 줄 수정(번호 「1.」 붙임) | 불변 | 불변 | 불변 |
| D 다시 집계 후 저장 | 불변 | 불변 | — |

- **「키 빈 자동 줄」 가설은 현재 생성기에서 성립하지 않는다.** 사업·활동(정기점검·AS, 미연결, 기술영업) 행의 자동 줄은 모두 키가 있다(`task:`, `agg:done:`, `agg:mntas:done:` …). `SplitWeeklyLines(row.PrevText)` 경로는 사실상 죽은 코드다.
- 캡처의 「정기점검 7건(24/31, 월 진행률: 77.4%), AS 4건 처리 / 1. … 2. … 3. …」 형식은 **지금 코드가 만들지 않는 옛 형식**이다(코드 전체에서 「월 진행률」 생성 지점 없음). 즉 이 줄들은 **옛 저장 문서(키 없는 줄)** 에서 온 것으로 보인다.
- 옛 형식(키 없는 줄)이 든 문서로 재현한 결과:
  | 저장된 줄 상태 | 화면 | 저장 3회 |
  |---|---|---|
  | 전부 키 없음·자동 표시 | 4줄(옛 텍스트만, 새 자동 줄은 안 보임) | 4줄 유지 |
  | 전부 키 없음·수동 표시 | **5줄: 새 자동 1줄 + 옛 4줄(같은 내용이 두 형식으로)** | 5줄 유지 |
  | 4줄 중 1줄만 수동 | **2줄로 줄어듦(자동 1 + 수동 1). 나머지 옛 3줄이 조용히 사라짐** | 2줄 유지 |
- 구조적 약점(확정): ⓐ 키 없는 줄은 숨길 수도, 갱신할 수도 없어 새 자동 줄과 **같은 내용이 두 번 보이거나**, 반대로 조용히 사라진다. ⓑ 줄 비교가 글자 완전 일치뿐이라(번호·공백 정규화 없음) 조금만 달라도 수동 복제 줄이 생긴다.
- **「저장할 때마다 늘어남」 자체는 재현하지 못했다.** 캡처가 어느 조직·주의 문서인지 알아야 한다. 아래 운영 SQL ⑤를 부탁한다.

## 3. 운영 SQL (사용자 실행) — 지시서 ①~④ 외 추가
```sql
-- ⑤ 캡처 주차(11/09 주 = 저장 주차 2026-11-16) 보고서에서 중복이 보인 조직의 행·내용 길이와 줄 키 현황
SELECT org_id, week_anchor, status, updated_by, updated_at, length(content_json) AS len
  FROM company_weekly_reports WHERE week_anchor IN ('2026-11-09','2026-11-16','2026-11-23') ORDER BY org_id, week_anchor;
-- 중복이 보인 조직 한 곳의 content_json 전문(서산 정기점검 행): done_lines 의 key 유무·manual 값을 확인
SELECT content_json FROM company_weekly_reports WHERE org_id='<조직ID>' AND week_anchor='<주차>';
```
판정: `done_lines` 에 `"key"` 없는 줄이 있으면 옛 문서 경로(위 표). 같은 `text` 가 `manual:true/false` 로 두 번 있으면 수동+자동 중복.

## 6. 운영 문서 확인 결과 (도서관사업팀 O01, 사용자가 가져온 `weekly_O01.json`)
- 저장 주차 `2026-11-09` 행은 내용이 비어 있다(길이 0). `2026-11-16`(11/09 주 보고서, 11/15 13:34 확정)와 `2026-11-23`(11/16 일회 복사본)만 내용이 있고 둘은 같다.
- **중복 확인 2건**
  - 업무지원활동(ACT-biz_support) 차주 계획: **같은 3줄이 정확히 2번(6줄)**. 6줄 모두 수동·키 없음. 줄 수정 로그가 2회(11/15 13:29, 13:31) → 저장 두 번에 3줄씩 늘어난 형태와 맞는다.
