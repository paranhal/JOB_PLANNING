지시서 파일은 레포에 없어 채팅 요구사항 문장을 기준으로 구현했다.

## 천안시 체크해도 목록이 안 바뀌던 원인

로그: `docs/리뷰/95-59-cheonan-repro.log`

1. 지역 칩 `change`가 요약만 갱신하고 `load()`를 부르지 않았다.
2. `GET /maintenance/:id/month-targets`가 `region` 쿼리를 무시했다(`sido`/`sigungu` 드롭다운만 목록 필터).

그래서 「천안시 동남구」를 체크해도 개별 사이트 표는 충남 전체(홍성 등)가 그대로였다.

수정: 칩 변경 즉시 `load()` + `region=` 반복, 서버 `MatchAnyRegionKey`. 통계(regions)는 기존처럼 전체, **sites만** 필터.

## PermMaintenanceEdit 부여 대상 (권한은 바꾸지 않음)

`canEditMaintenanceSchedule` = `hasPerm(PermMaintenanceEdit)` → canonical `mnt.edit`.

| 역할 | Builtin `mnt.edit` | 월대상 등록·일정 배정 |
|---|---|---|
| 조직관리자 (`org_admin`) | AccessFull | 가능 |
| 기술 (`tech`) | AccessFull (`techAccess`) | 가능 |
| 지원 (`support`) | AccessFull (관리 섹션 제외 전부) | **가능** — 지시서 「기술·조직관리자만」과 **다름**. 임의 변경하지 않음 |
| 전사관리자 (`vision_admin`) | 전부 | 가능 |
| 영업 (`sales`) | 없음 (`PermMntView`만) | 조회만, POST 403 |
| C-Level | 조회 이하 | 불가 |
| 레거시 `LegacyDefaultPermissions` | admin·기술에 `maintenance_edit`, 영업에는 없음 | 위와 같음 |

지시서와 다른 점: **지원 역할도 배정·월대상 편집이 된다.** 권한 테이블은 그대로 두고 보고만 한다.

## 화면·동작

- 지역 단위 체크 → 개별 사이트 목록 즉시 연동. 해당 지역 사이트 **기본 체크**, 개별 해제 가능.
- 「이 달로 등록」 삭제. 「선택한 사이트 등록」→ **확인**. 확인 팝업 후 체크된 `customer_id`만 그 달 대상 저장. 지역 POST API는 하위 호환으로 유지(95-49 테스트).
- 대기 목록: 조회 전용(체크·날짜 칸·일괄 배정 바 삭제). `POST /assign-slots/bulk`·preview·테스트는 보존.
- 배정 UI: 일정 화면 미배정 블록(`CanEdit`)·업무 등록 모달. 관리 화면 ③은 흐름 칩만.
