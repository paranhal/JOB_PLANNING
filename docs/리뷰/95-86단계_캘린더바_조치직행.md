# 95-86 후속 — 일정 캘린더 바 「조치」 직행

작성: 2026-11-04. 대상 `/workboard/board` 일·주 바 · 칸반 카드 「조치」. 상세 화면(`/workboard/tasks/:id`)은 유지.

## 원인

- `_board_bar.html` · `_board_kanban_card.html` 의 「조치」가 `Href`(상세)를 썼다. 완료 바만 `ActionHref`.
- `ShowTask` 의 actionHref 분기와 `boardActionHref` 가 따로 있어 규칙이 갈라졌다.

## 공통 함수

`(*WorkboardHandler).taskActionTarget(c, t) → href, label, can` (`workboard_action_target.go`)

| 유형 | 주소 | 라벨 |
|------|------|------|
| AS | `asOpenHref` | 접수 종료면 「조치 완료」 |
| 정기점검 | `mntVisitActionHref` (문자열 직접 조립 없음) | 완료면 「조치 완료」 |
| 작업(`project_work`) | `/workboard/tasks/:id/action` | 조치 화면 열기 |
| 영업활동 | `/sales/{id}` (기존 `SalesIDByActivity`) | 영업 사업 |
| 행정/지원 | `/workboard/tasks/:id` (상세가 곧 조치) | 조치 |

`stampBoardMove` 가 이 함수 + `hrefWithBack(back)` 으로 `ActionHref`/`ActionLabel`/`CanAction` 을 채운다. 상세 `ShowTask` 도 같은 함수. `boardActionHref` 는 이 함수 위임.

`canAction=false` 이거나 주소가 없으면 바·칸반 버튼을 숨기거나 상세(`Href`)로 보낸다.

바 본문 클릭(상세)·「수정」·「계획 수정」은 그대로다.

## 일정 리스트 (이번 범위 아님)

`board_list.html` 행은 계속 `.Href`(상세/`DetailHref`). 행 클릭을 조치 화면으로 바꾸지 않았다.

## 테스트

- `Test95_86_TaskActionTargetAndBoardActHref`: AS·점검·작업·영업·행정·지원 각 1건. 일 보기 바·칸반 「조치」 path 가 조치 화면(행정/지원은 상세). 상세 상단과 바 path 가 `taskActionTarget` 과 같음. 바 클릭 GET 200(AS·점검·작업). 완료 작업 바는 `/action` 직행.
- `Test95_86_ActButtonsAndDoneOpen` · `Test95_86_BoardItemDone` 회귀. 행정 완료 바는 상세가 조치 화면이라 `/workboard/tasks/:id`.

AS 조치 HTML은 `BackURL` 을 데이터로 받지만 화면에 링크를 그리지 않는다. 바 href 에는 `back=` 이 붙고, 점검·작업 조치 화면은 그 값으로 캘린더에 돌아온다.
