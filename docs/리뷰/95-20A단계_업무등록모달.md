선행: 95-20 (`98daf59` / 보고 보강 `0f7ad7b`). VERSION `95-20A`. 마이그레이션 없음. 운영 배포 안 함.

## 1. 한 줄

업무 관리(리스트·월·주·일) 헤더에 `+ 업무 등록`을 두고, 1단계는 새 유형 선택 UI, 2단계부터는 기존 `POST /workboard/tasks` 폼을 조각으로 불러 저장한 뒤 같은 view·date로 돌아온다.

## 2. 메뉴

95-20 메뉴를 바꾸지 않는다. `+ 업무 등록`은 `/workboard/board` 헤더에만 있다. 예전 화면 `/workboard/register` 모달 1단계(버튼 5개)는 그대로다.

| 화면 | 버튼 위치 |
|---|---|
| 리스트 | `일정 캘린더 보기` 오른쪽, 초록 주 버튼 |
| 월·주·일 | `일정 리스트 보기` 왼쪽, 월/주/일 토글 옆 |

## 5. 저장·redirect

`redirect` 허용: `/workboard/register|kanban|tasks|board` 및 `/workboard/tasks/` 접두. `://`, `//`, 개행·탭, `..`, 외부 URL은 fallback(`/workboard/kanban` 또는 조각의 `/workboard/board`).

브라우저 확인: 09:00 저장은 기존 일정과 겹쳐 `관리자의 09:00~09:30에 다른 업무가 있습니다` 로 **같은 리스트 URL**에 `err=` 이 붙었다(기존 CreateTask). 06:00~06:30으로 다시 저장하면 `view=list&date=2026-10-24` 에 새 행이 보인다. 확인 후 임시 DB에서 해당 행을 지웠다.

## 8. 판단이 애매해서 보고서에만 남긴 것

거래처 주소·레거시 사용자 ID 비교는 95-20 화면 조회 규칙 그대로이며 이번 모달에서 다시 정하지 않았다. 근거는 `docs/리뷰/95-20단계_업무관리_개인화면.md` 7장.

`js-keep-modal` 스크립트는 예전 `wb_modals` 정의 안에만 있어 보드 페이지에 안 실렸다. 새 모달 쪽에 동일 위임(중복 바인딩 가드 `__wbKeepModalBound`)을 넣었다. 검증 실패(시간 겹침)는 기존처럼 redirect+`err` 이다.

Alpine `init()` 의 `$watch` 는 환경에 따라 안 불릴 수 있어, 폼 되돌리기 클릭 리스너로 `newWorkStep=1` 을 맞춘다.
