# 95-48단계 — 정기점검 중복 정리: 당월 보호로 미완료 중복이 안 지워지던 문제

기준: `커서_작업지시서_95-48_긴급_정기점검_중복정리_당월보호로_정리안됨.md`  
선행: 95-43 조직, 95-14 회차, 95-45 month target, 95-47 방문 시간·장비. 실행일: 2026-10-25.  
운영·개발 DB를 코드로 바꾸지 않음. 배포 이미지는 요청 시에만.

## 원인 재현

`/maintenance/:id/duplicates` 「확인하고 정리」 → `CollapseDuplicateMonthVisits` → `DeleteVisitIDs` → `VisitDeleteProtected`.

오늘이 2026-10-25이면 방문일 < 2026-11-01 인 10월 방문은 **전부 보호**라서, 서산고등학교 10-13(미완료·대상 없음) Drop 이 10-12(완료) Keep 과 짝이어도 **0건 삭제**. 화면은 「기간 보호 — 제외」이고 버튼은 활성이며 결과 안내가 없어 무반응으로 보였다.

확정 테스트: `TestCollapseDuplicateCurrentMonthSeosan`, `Test95_48_CurrentMonthCollapsePopupAndAuth`. 수정 전 기대(`deleted=0`)는 `TestCollapseDuplicateSkipsProtected` 가 고정하고 있었음.

## 규칙 표

| 조건 | 중복 정리 | 일반 `DeleteVisit` / 계획 삭제 |
|------|-----------|-------------------------------|
| Drop 미완료 + Keep 같은 계획·기관·슬롯(제품/회차)·같은 달 + 실적 없음 | **기간과 무관하게 삭제** (`deleteVisitAllowProtectedDuplicate(..., true)` → `removeVisitRow`) | 당월·이전은 `ErrVisitDeleteProtected` |
| Drop 완료 | 제외 — 완료된 방문 | 완료는 삭제 불가 |
| Keep·Drop 둘 다 완료 | 제외 — 둘 다 완료 | (해당 없음) |
| Drop 에 notes / start·end_time / visit_targets / 사인·결과서 테이블 | 제외 — 조치 기록 있음 | (해당 없음) |
| 회차 또는 제품 슬롯이 다름, 다른 달 | 중복 아님 | — |
| `allowProtectedDuplicate=false` | `DeleteVisit` 과 동일(보호 유지) | — |

Keep 선정: **완료 우선**. 둘 다 미완료면 **방문일이 빠른 쪽**. 빈 제품(generic)은 같은 회차 KLAS/RFID 와 짝.

삭제 시 담당(`maintenance_visit_assignees`)·장비 행·연결 `work_tasks`(source_type=maintenance)·슬롯 캐시 무효화. month target 은 방문에 묶이지 않으므로 Keep 이 슬롯을 충족.

## 화면

상태 열: 삭제 예정 / 제외 — 완료된 방문 / 제외 — 조치 기록 있음 / 제외 — 둘 다 완료. 「기간 보호」 문구는 중복 정리에서 제거.  
요약 줄, 삭제 예정 0건 또는 권한 없으면 버튼 `disabled`. CSRF.  
실행 후 `jp_flash_mnt_dup` 팝업(새로고침 시 없음), 계획 화면으로 이동하며 `month` 유지.

권한: `canEditMaintenanceSchedule`(조직관리자·지원·기술담당 등 `mnt.edit`) + `requireVisiblePlan`. C-Level·타 조직 거부.
