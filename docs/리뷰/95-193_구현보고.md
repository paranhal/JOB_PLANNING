# 95-193 구현 보고 — 주간 보고서 「사업이 연결되지 않은 업무」에 제품 라벨 표시

작성: 2026-11-14. 푸시·배포·VERSION 변경 없음. 작업지시서 파일(95-193)은 찾지 못해 붙여 주신 지시문과 확인한 기본안으로 진행했다(§4·§6 원문은 못 봤다). 지시서와 다른 점이 있으면 알려 주세요.

## 0. 확인 결과 (변경 전)
- 생성부 `listCompanyUnassigned`(company_weekly.go)가 정기점검·AS·행정/지원을 6번의 `addIf` 로 모으고, `project_id` 가 비면 `UnassignedReasonNoProject`. 항목(`CompanyWeeklyUnassigned`)에 제품 필드가 없어 제목(고객·AS번호·업무명)만 보였다.
- 제품 출처: 정기점검 `maintenance_visits.product_type`(이미 표시 문자열), AS `as_receipts.asset_id` → `assets`(여러 장비는 `receipt_group_id` 로 묶인 접수 여러 건), 행정/지원 `work_task_assets`. 점검 대상 `maintenance_visit_targets` 는 보조.
- 운영 DB 사본(로컬 복사본에서 읽기 전용)에서 제품을 알 수 있는 건: 도서관 조직 09-21 주 52건 중 21건(약 40%), 10-12 주 41건 중 19건, 10-26 주 42건 중 24건. 정기점검은 전부, AS 는 20~40%, 행정/지원은 0건.

## 1. 재현 (수정 전)
미연결 항목에 제품 필드가 없어 라벨을 줄 수 없었다. 정식 시험(`TestCompanyWeekly95_193_UnassignedProductLabel`)은 수정 전에는 `ProductLabel` 필드가 없어 컴파일에서 실패한다.

## 2. 변경
- **모델**: `CompanyWeeklyUnassigned.ProductLabel`(비어 있으면 알 수 없음. 추정하지 않는다).
- **저장소**(`company_weekly_product.go`): `listCompanyUnassigned` 끝에서 `fillUnassignedProductLabels` 를 한 번 부른다. **N+1 금지**: 종류별로 ID 를 모아 400개 단위 `IN (…)` 쿼리로 조회한다(AS ⨝ assets, 점검 `product_type`, 제품 구분이 빈 점검만 점검 대상 보충, 행정/지원 ⨝ `work_task_assets`). 연결·분류(`addIf`, Reason, 사업 연결 저장 로직)는 **무변경**.
- **라벨 형식**: 「제품명 · 모델 (분류)」(분류는 기존 `ProductCategoryLabel` 재사용), 여러 개면 「첫 개 외 n」. 정기점검은 `product_type` 그대로(KLAS 등). 자산 연결이 없는 AS·자산 없는 행정/지원은 **비워 둔다**.
- **화면**: `_weekly_unassigned.html` 의 미연결·행 없는 사업 업무 목록 5곳에 `KindLabel · BucketLabel` 옆 배지(`data-product-label`)로 표시. 없으면 아무것도 안 보인다. `data-kind`·`data-id`·「사업 연결」 링크·모달은 그대로.
- 스키마·DB 변경 없음.

## 5. 한계·남은 것
1. AS 는 자산이 연결된 건만 제품이 보인다(운영 사본 기준 20~40%). 나머지는 증상 문구 추정 없이 비워 둔다. 접수 때 자산을 고르게 하면 비율이 오른다.
2. 행정/지원은 연결 자산이 거의 없어 대부분 라벨이 없다(사본 0건).
3. 점검 대상(`maintenance_visit_targets`)은 사본에 0건이라 실데이터로는 확인하지 못했고 시험 데이터로만 확인했다.
4. 이 화면 밖(엑셀·HWPX 보고서 본문)에는 제품 라벨을 넣지 않았다.
