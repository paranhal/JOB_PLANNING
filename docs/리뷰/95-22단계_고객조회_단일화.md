# 95-22 고객 조회 단일화 · 사이트 목록 누락

작성: 2026-10-24. 지시서 v2(D-163). 95-2F §1을 대체한다. 고객 org_id·계층 데이터는 코드로 바꾸지 않았다. 고객현황 UI·AS 접수 동작(초성 검색)은 유지하고 옵션 출처만 Lookup 으로 맞췄다.

## 원인

| 화면 | 이전 조회 | 빠진 이유 |
|---|---|---|
| 정기점검 방문 추가 | `customerRepo.List` (검색어 없으면 최상위만, 2000건 상한) | 하위 기관(학교) 누락 |
| 일일 업무 등록(예전) | `ListAllInOrg(org)` | 타 조직 소속 고객 누락(95-2E 전사 공용 위배) |
| 업무 관리 새 모달 | `ListAllInOrg` 복사 | 위와 같음 |
| 정기점검 번호 후보 | 고객 `org_id` 로 방문 필터 | 계획 조직과 다른 고객이 붙은 방문 누락 |
| AS 사례·검색 | `ListAllInOrg` | 타 조직 고객 누락 |
| AS 접수 | `ListForReceipt` | 빠지지 않음(기준) |

## Scope

| Scope | 대상 | 사용 |
|---|---|---|
| `site` | 활성 `party_kind=customer` | AS·정기점검·일일업무·작업·자산·연락처·점검 사이트 |
| `party` | customer+partner+vendor+own | 발주처·계약상대·제조사·공급사. `own` 포함은 기존 `ListAll`/`SearchJSON` 이 party_kind 를 가리지 않은 것과 같게 맞춤 |

가등록은 AS 접수와 같이 활성 customer 이면 포함한다.

## 허용 목록

선택 목록이 아닌 조회: 고객현황 `CustomerRepo.List`, 백업 `ListAll`, 임포트·마이그레이션, `lookup_cache` ID→이름. 핸들러 가드: `customer.go`·`backup.go`·`as.go`(초성)·`work.go`.

`<select name=customer_id>` 후속: 영업·사업·연락처·자산·관계·공간·관리업무 폼/필터. 이번 단계 필수는 콤보로 바꿈.

## 판단 기록

- 정기점검 후보: 92단계 격리에 따라 **계획 조직**. 고객 조직으로 거르면 전사 공용 고객이 계획에 있어도 빠진다.
- `ScopeParty`에 `own`: 기존 제조사/공급사 검색과 동일 집합.
- AS 접수는 옵션 출처만 Lookup. 초성 UI는 지시서 「AS 접수 동작 변경 금지」.

## 브라우저 (TEST, `:8081` + 임시 DB)

로컬 `:8080`(jp-server)은 구버전이라 건드리지 않았다. `PORT=8081 DB_PATH=/tmp/jp-95-22.db` 에 상위/하위/타조직 3건을 넣고 admin으로 확인.

- `GET /lookup/customers?scope=site&q=공주생명` → `C-GONG`, label `공주생명과학고등학교 (충남교육청 · 공주시)`
- `GET /maintenance/sites/customer-search?q=충남` → 충남교육청 `registered=true` + `edit_href`, 공주생명과학고는 미등록
- 점검 사이트 등록 콤보: 「이미 점검 사이트로 등록됨」·수정 링크·하위 기관 동시 표시(접근성 스냅샷). 스크린샷 도구는 타임아웃되어 파일로 남기지 못함

운영 복사본의 공주생명과학고등학교는 이 세션에서 `data/app.db` 조회가 비어 확인하지 않음(데이터 미변경).
