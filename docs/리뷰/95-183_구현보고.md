## 변경 내용
### A. 하부 업무(2단계) — 설계 권한자(`CanEditPhase`)만
- **수정 접힘 하나로 통합**(「수정 · 이름·유형·일자·배지·다음 할 일」): 이름(100자, 같은 단위 업무 안에서 정규화 기준 중복 금지·비활성 포함), 유형, 예정·마감·실제 시작, 배지, 연장 사유, 다음 할 일(300자, 보고 문장 「완료 후 계획」 안내 문구). 이름을 바꿔도 이미 저장된 작업명은 바뀌지 않는다는 안내.
- **유형 변경**: 계획·사이트·실적(수량 기록 포함)이 있으면 막고 건수를 안내(예: 「계획 1개·사이트 4곳이 있어 유형을 바꿀 수 없습니다」).
- **순서 ↑↓**(같은 단위 업무 안, 비활성 제외, 맨 위·아래는 변화 없음).
- **상태** 진행·완료·보류·자동(되돌리기). 완료는 사람이 누르고 `done_at/by` 기록, 자동으로 되돌리면 지움. 끝나지 않은 사이트(수량만은 못 채운 수량)가 있으면 확인 패널을 한 번 거친 뒤 확정(막지 않음).
- **삭제**: 실적이 없으면 삭제(마일스톤·직접 등록 사이트·일 스냅샷 함께 삭제, 일자 변경 이력은 보존), 연결 작업·계획·계획에 묶인 사이트·진행/완료 사이트·일 이벤트(수량 기록)가 있으면 **비활성**. 비활성은 단위 업무 아래 「비활성 하부 업무 N개」 접힘에서 **되돌리기**.
- 저장 뒤 **같은 줄로 돌아온다**: 행에 `id="phase-…"`·`package-…`·`plan-…` 앵커 추가, 리다이렉트가 앵커로 이동, 오류 때는 해당 수정 접힘이 열린 채 돌아옴. 성공·실패 문구는 수행 구조 위에 표시.

### B. 작업 계획(3단계)
- 「계획 수정」에 **진행 기준(사이트/수량)·수량 단위** 추가. 수량 기준으로 바꾸려면 제외되지 않은 사이트 전부에 목표 수량 필요(미입력 N곳 안내).
- 새 화면 `계획 사이트·수량`(`/projects/:id/plans/:planID/sites`, 계획 줄의 「사이트·수량 관리」 링크; 계획 권한이 없으면 「사이트 보기」로 읽기만):
  - 이 계획의 사이트 목록과 사이트별 **목표 수량** 직접 입력·저장, 선택한 사이트에 **같은 수량 적용**.
  - **제외**(사유 필수, 완료 사이트는 확인 체크), 제외한 사이트 목록.
  - **담기·옮기기**: 하부 업무에 등록된 사이트(95-179B) 중 이 계획이 아닌 곳만 후보. 이름·초성·지역 검색, 결과 전체 선택, 100곳씩 쪽 이동. 다른 계획에 있으면 현재 계획이 표시되고 옮겨진다. 완료 사이트는 선택 불가. 수량 기준 계획이면 목표 수량 입력을 같이 받고, 비면 전부 취소.
  - 서버에서도 하부 업무에 등록되지 않은 사이트는 거절한다.
- 계획 삭제 규칙(실적 있으면 비활성)은 그대로 두고, 삭제 버튼에 이유(확인창·툴팁)를 붙였다.

### C. 화면 구성
- 1단계 수정 폼을 **접힘**(「단계 수정」)으로 바꾸고 위에 읽기 줄(이름·상태·지연·기간)을 둬서 하부 업무 줄이 묻히지 않게 했다. 1·2·3단계 모두 「읽기 줄 + 수정 접힘 + 버튼」 모양이다.

### C-2. 변경 내용 저장 막대
- 1단계·하부 업무·계획 폼에서 값이 바뀌면 그 폼에 윤곽선과 「수정됨」 표시, 원래 값으로 돌리면 사라진다(연장 사유는 변경으로 세지 않음).
- 화면 아래 고정 막대: 「N곳 수정됨 · 변경 내용 저장 · 취소(원래대로)」(안전 영역 포함, 막대가 마지막 내용을 가리지 않게 아래 여백). 권한이 있는 사용자에게만 렌더.
- 서버 `POST /projects/:id/structure/batch`(JSON): 항목마다 권한 재검사(1단계·하부 업무는 설계 권한자, 계획은 계획 권한자), **한 트랜잭션**(하나라도 실패하면 전부 취소, 실패 위치와 이유 반환). 일자 변경 이력도 같은 트랜잭션, 감사 로그는 커밋 뒤 항목별로 남김.
- 실패 시 입력값·열린 접힘 유지, 해당 폼 아래에 이유 표시. 성공 시 「N곳을 저장했습니다」, 열려 있던 접힘·스크롤 위치 복원. 저장 중 버튼 비활성(이중 클릭 요청 1회), 저장하지 않은 수정이 있으면 이동 확인(`beforeunload`), `role="status"`.
- 개별 「저장」은 그대로. 다른 곳에 수정이 남아 있으면 개별 저장 때도 이동 확인이 뜬다.

## 한계·남은 것 (질문 후보)
1. **제외한 사이트를 계획으로 되돌리는 입구는 없다**(제외된 사이트는 후보에 안 나온다). 하부 업무 사이트 화면에서 다시 등록해야 한다.
2. 「선택 유지」: 후보 목록의 쪽 이동 사이에 선택한 체크는 유지되지 않는다(쪽마다 담기). 한 쪽 100곳 + 결과 전체 선택으로 대부분 처리된다.
3. **보류 상태**는 표시·완료 후보 억제까지만 반영(기본안). 작업 등록의 계획 선택, 대시보드·주간 보고서·업무 회의 진행 줄(`lightTrees`)은 하부 업무 상태를 여전히 무시한다(0단계 §8-2·3). 필요하면 별도 작업.
4. 일괄 저장의 **감사 로그는 커밋 뒤** 항목별로 남는다(실패해도 변경은 유지되는 기존 방식). 같은 트랜잭션에 넣으려면 `audit.InsertTx` 로 옮기면 된다.
5. 사업 목록·읽기 전용에서 「사이트 등록·관리」 링크가 보이는 것은 기존 그대로.
6. 조직 O02 조직관리자의 타 조직 사업 `GET` 이 200 이던 관찰(0단계)은 이번에 건드리지 않았다.
7. 배포 시 `VERSION` 라벨을 올려야 한다(이번 변경에 포함하지 않음).
