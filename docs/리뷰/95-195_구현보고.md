# 95-195 구현 보고 — 사업 등록 관리: 계약 정보 없는 직접 등록 사업 표시

작성: 2026-11-15. 푸시·배포·VERSION 변경 없음. 작업지시서 파일(95-195)은 찾지 못해 붙여 주신 지시문과 확인한 기본안으로 진행했다(§3·§4·§6 원문은 못 봤다). 지시서와 다른 점이 있으면 알려 주세요.

## 0. 확인 결과 (변경 전, 읽기 전용)
- `Registry`([project.go](server/internal/handler/project.go))가 `ListContracts(OrgAll, …, false)` 를 불러 `ContractedSQL`(계약금액>0 · 계약번호 있음 · 영업 계약 종결 중 하나)에 맞는 사업만 보였다. 계약 정보 없는 직접 등록 사업은 등록 관리에서 숨었다.
- 상태 필터는 「전체·진행·완료·보관」(취소 옵션 없음). 「전체」는 상태 조건이 없어 보관·취소도 나온다. 배지는 「유관」·「파이프라인」/「직접 등록」, 같은 이름 안내(`DupNames`)에 합치기 링크는 없었다.
- DB 복사본(현재 운영보다 오래됨)에서 숨은 사업은 비시험 58개 중 7개(WPSEED02·03·05·06, WP-006·007·008). 전부 O01·진행·계약금액·번호·영업 연결 없음. WPSEED03 은 업무 81·점검 76·AS 28 이 붙어 있는데 등록 관리에 안 보였다.

## 1. 재현 (수정 전)
임시 DB 에 계약 정보 없이 직접 등록한 사업을 만들고 비전관리자로 `/projects/registry` 를 열면 **그 사업이 없다**. 재현 시험이 수정 전 실패하고 수정 후 통과한다.

## 2. 변경 (등록 관리만)
- `Registry` 가 `ListContracts(…, includeAll=true)` 를 부른다. **`ContractedSQL` 과 다른 화면의 목록(`includeAll=false`)은 그대로** — 시험으로 고정.
- 「계약 구분」 필터(전체·계약됨·계약 미등록, `?contract=none|contracted`)와 초기화 링크 조건 포함.
- 계약 정보가 없는 사업(`IsContracted` 가 아닌 사업) 이름 옆 「계약 미등록」 배지(`data-uncontracted`, 계약금액·번호 없음·영업 계약 종결 아님을 설명하는 툴팁).
- 「이름이 같은 사업이 N건」 안내에 **비전관리자에게만** 「합치기」 링크(`/projects/{첫 ID}/merge`, 2건이면 `?drop_id=` 로 상대 사업을 미리 지정). 숨겨져 있던 사업이 이제 목록에 들어와 같은 이름 쌍(시드·승격 사업)이 이 안내에 잡힌다.
- 스키마·DB 변경 없음.

## 3. 변경 파일
- 수정: `server/internal/handler/project.go`, `server/web/templates/project/registry.html`
- 신규: `server/internal/handler/project_registry_95_195_{http,browser}_test.go`, `server/web/static/js/95_195_registry_browser.mjs`

## 5. 한계·남은 것
1. 등록 관리 목록이 길어진다(복사본 기준 +7건). 시드 사업(WPSEED*)은 「계약 미등록」 배지로 구분되지만, 영업 계약과 합칠 사업(WPSEED02 ← WP-011 등)은 사업 합치기를 실제로 실행해야 정리된다(이번엔 링크만).
2. 상태 필터에 「취소」 옵션은 없다(지시 범위 밖). 「전체」로 보면 취소 사업이 나온다.
3. 합치기 링크는 같은 이름 안내에만 있고 행마다 있지는 않다.
