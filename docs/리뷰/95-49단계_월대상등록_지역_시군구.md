# 95-49단계 — 월 점검 대상 등록 지역 단위를 시·군·구까지 확대

기준: `커서_작업지시서_95-49_정기점검_월대상등록_지역_시군구_확대.md`  
선행: 95-45 month target, 95-14 지역 담당. 실행일: 2026-10-25.  
운영·개발 DB를 코드로 바꾸지 않음. 배포 이미지는 요청 시에만.

## 무엇이 바뀌었나

정기점검 > 관리 > 「월 점검 대상 등록」의 「지역 단위」가 `cfg.Region`(시·도 축약: 충남·세종)만 묶어 **충남 798곳**처럼 한 덩어리였다. `customers.addr_sigungu` 는 이미 로드되고 있었다.

이제 시·도 행을 펼치면 시·군·구 칩이 나오고, 시·도 전체 체크와 시·군·구 일부 체크(indeterminate)를 구분한다. **`cfg.Region` 은 그대로**라서 지역 담당·캘린더·95-15A 일괄 지정은 시·도 기준을 유지한다.

## 키 규칙 (`model/region_key.go`)

| 의미 | 키 | 라벨 |
|------|----|------|
| 시·도 전체 | `충남` | 충남 |
| 시·군·구 | `충남\|홍성군` | 충남 홍성군 |
| 시·도는 있고 시·군·구 없음 | `충남\|` | 충남 (시·군·구 미지정) |
| 시·도도 없음 | `지역 미지정` | 지역 미지정 |

`충남` 과 `충남|홍성군` 을 같이 내면 `CollapseMonthTargetRegionKeys` 가 시·도만 남긴다. 등록 비교는 `MatchRegionKey`. `shortRegionName` 은 `model.ShortRegionName` 위임.

## 화면·API

- `GET /maintenance/:id/month-targets?month=&q=&sido=&sigungu=` — `regions[].Key`·`Children`, `sites[].Sigungu`·`RegionLabel`. 통계는 필터와 무관, 사이트 표만 시·도/시·군·구·검색 적용.
- 세종처럼 **모든 사이트의 시·군·구가 비면 하위 칩 없음**.
- 시·도 접힘 기본, 「선택 n곳」, `textContent`/`createElement`(innerHTML 없음).
- `POST` 지역 없음 → JSON `{ok:false, message:"등록할 지역을 선택하세요"}`. 성공 메시지 예: `충남 홍성군·예산군 — 57곳 등록 / 3곳 건너뜀`.

| addr_sido | addr_sigungu | 건수 |
|-----------|--------------|------|

| 충청남도 | 천안시 동남구 | 6 |

이상값: 시·군·구에 시·도명·숫자가 들어간 행 0. 두 단어 시·군·구 10곳(전부 `천안시 동남구` / `천안시 서북구`) — **한 칩으로 두고 상위 「천안시」 합치기는 안 함**. `school_master_import` 는 `AddrSigungu = ir.Region` 인데, 현재 점검 사이트 시·군·구는 시·도명이 아니라 시·군·구 형태. 세종 30곳은 시·군·구가 비어 있어 화면에서도 시·도 칩만 나온다. cfg.Region 은 `충남` 37 / `세종` 30.

데이터 보정은 이번 단계에서 하지 않음. 후속 후보: 세종 시·군·구 채우기, `천안시 *` 상위 합치기, 지역 담당을 시·군·구로 세분화.
