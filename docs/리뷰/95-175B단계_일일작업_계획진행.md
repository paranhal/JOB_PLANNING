## 변경

- 통합: `mergeProjectPhases` 가 같은 이름 단계를 지우기 전에 하부 업무를 대상 단계로 옮긴다. 같은 이름(공백·괄호를 뺀 이름)은 계획·사이트·연결 작업을 한 하부 업무로 합친다. 자식이 남으면 단계 행을 남긴다. 계획이 없는 경우의 되돌리기 payload 는 `project_merge_moves` 의 `package_plans` / `*` 에 들어간다.
- 110: `package_events`, `package_progress_daily`.
- `UpsertSiteCheck` 는 한 트랜잭션이다. 같은 상태·같은 수량을 다시 저장하면 이벤트는 늘지 않는다. 이미 완료인 사이트를 다른 작업에서 다시 완료해도 계획 건수는 1이다.
- 작업 등록: 계획을 고르면 「오늘 처리할 사이트」가 그 계획의 미완료 사이트만 보여 준다. 이어서(진행)가 위, 검색·초성·지역, 선택은 유지, 한 번에 100곳. 그 작업일에 이미 배정된 사이트는 「○○ 배정됨」(막지 않음). 미리보기 문장은 서버가 준 완료·대상 수에 선택 건수를 더해 만든다.
- 조치·작업 화면: 칩 「{계획명} {하부 업무명} · 현재 N/M (%)」. 머리의 달성률도 같은 N/M 의 퍼센트다. 처리 수량 칸이 있다. 사이트가 모두 완료면 「계획을 완료 확정할까요?」와, 계획 권한이 있는 사람에게 「완료 확정」. 계획에서 빠진 사이트는 「계획에서 빠짐」.

## 코드 확인 중 생긴 질문

설계서 §10 의 7건과 120P 에서 받은 네 가지(기본 단계명, 구조 수정 권한, 유지보수 접기, 단계 담당자 없음)는 다시 묻지 않는다. A 보고서의 「계획 없는 통합에서 하부 업무가 떨어진다」는 이번에 고쳤다.

1. 한 작업만 보는 `TaskSiteCheckRate` 는 그 작업의 체크만 센다. 화면의 달성률과 칩, 그리고 이번 시험의 「95-119 합계」는 계획에 묶인 체크를 모두 모아 `package_sites` 와 같게 맞춘다.
2. 빠른 실적 입력(95-121 §2-D, 일일 업무 없이 `source=manual`)과 설치·검수 제안 목록(§2-E)은 이번 단계에 없다. 실적의 입구는 기존 사이트 체크 저장이다.
3. 일 스냅샷은 이벤트를 날짜순으로 다시 재생한다. 사이트가 나중에 추가되면 과거 행의 분모도 현재 범위로 다시 써진다. 과거 분모를 얼리는 일은 95-122 로 남긴다.
4. 페이스 칩은 일 실적 일수가 아직 `PlanPace` 에 들어가지 않아 「판정 전」이다. 영업일·임계값은 C 단계다.
5. 해당없음은 기존 95-119 셀렉트에 사유 칸이 없어, 풀의 제외 사유를 「해당없음」으로 채운다.
6. 이월(95-80)은 같은 업무의 날짜만 바꾼다. 사이트 행을 다른 업무로 복사하지 않으므로, 완료되지 않은 사이트는 다음 날 풀에 남는다.
