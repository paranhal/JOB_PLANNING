# 95-197 구현 보고 — 주간업무보고서: 활동 분류 블록 · 연결된 업무의 사업·활동 변경

작성: 2026-11-15. 푸시·배포·VERSION 변경 없음. 지시서 파일은 없고 대화에서 정한 안(업무 활동 분류 컬럼 추가)으로 진행했다.

## 0. 확인 결과 (변경 전)
- 활동 행 종류는 `asset`·`tech`·`mnt_as`·`unlinked` 4가지, 보고서 행(`weekly_report_rows`)을 조직별로 「행 관리」에서 직접 추가하는 구조였다.
- 업무(`work_tasks`)는 사업(`project_id`)에만 연결됐고 활동에 직접 연결하는 필드가 없었다. 사업이 없는 업무는 「사업 미연결」 행에 통째로 모였다.
- 값이 없는 활동 행도 카드로 보였다.

## 1. 변경
- **활동 7종** (`model/weekly_activity.go`): 경영지원 mgmt · 기술영업 tech · 전략및혁신 strategy · 자산관리 asset · 업무지원 biz_support · 고객서비스 service · 역량강화 growth.
- **DB**: `work_tasks.activity_kind TEXT` 컬럼 추가(기존 행은 비어 있음).
- **집계**: 분류된 업무를 같은 활동 블록에 모은다(`company_weekly_activity_tag.go`). 보고서 행이 없는 활동은 이 주에 분류 업무가 있을 때만 가상 행(`ACT-<종류>`)으로 만든다. 기존 tech·asset 행은 기존 줄 + 분류 업무.
- **표시**: 값 없는 활동 블록은 숨김(사업 행은 그대로). 사업 블록이 먼저, 활동 블록은 뒤. 활동에 연결된 업무는 「사업이 연결되지 않은 업무」에서 빠진다. 엑셀·HWPX는 원래 값 없는 카드를 제외하므로 같은 규칙이 이어진다.
- **연결**: 사업과 활동은 하나만. `SetTaskProject`는 활동 분류를 해제하고, 새 `SetTaskActivity`는 사업 연결을 해제한다. `POST /stats/company-weekly/tasks/project` 가 `activity_kind` 를 받는다(일반 업무만, 권한·조직 검사는 기존과 같음, 감사 로그·업무 이력 기록).
- **수정 화면**: 「연결된 업무 N건 · 사업·활동 변경」 구역(`data-weekly-linked`)과 「연결 변경」 버튼. 연결 창은 `_weekly_link_modal.html` 로 분리해 한 곳에서 쓰고, 활동 7종 선택을 추가했다(사업/활동 상호 배타).

## 4. 한계·남은 것
1. 업무를 만들거나 수정하는 화면에는 활동 분류 입력칸이 없다. 지금은 주간 보고서의 연결 창에서만 지정한다.
2. AS·정기점검은 활동에 연결할 수 없다(사업 연결만).
3. 숨긴 활동 블록은 편집 모드에서도 보이지 않아, 빈 활동에 직접 줄을 적을 수 없다(값이 생기면 나타남).
4. 운영 배포 시 컬럼 1개 추가(`activity_kind`). 백업 후 배포 권장.
