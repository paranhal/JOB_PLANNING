# 95-117 진단: 새 업무 등록 · 지원 업무 사업명 목록·검색

작성: 2026-11-04. 코드 미수정. 운영 DB·push·이미지 없음. 이 문서는 커밋하지 않는다.

## 결론 (원인 하나)

**사업 옵션 데이터는 폼에 넘어간다. 목록 `<ul class="combobox-list">` 가 `position:absolute` 인데 피커 루트 `.pp` 에 `relative` 가 없어, 드롭다운이 모달 입력칸 아래가 아니라 페이지 하단(모달 밖)에 그려진다.** 입력칸을 눌러도 모달 안에서는 목록이 안 보이고, 글자를 쳐도 필터 결과는 같은 잘못된 위치에만 생긴다. 「▼ 타 부서 사업 보기 (N건)」은 문서 흐름이라 모달 안에 그대로 보인다.

검색은 **서버 요청이 아니라** 내 부서 `Own` 배열만 클라이언트 필터한다. 타 부서 N건은 접기 버튼을 눌러야 `GET /workboard/projects/picker-other` 로 불러온다.

## 3. 검색 동작 · 브라우저 재현

- **클릭 시 목록**: `@focus="open=true"` → `filtered` getter가 `items`(Own) 반환. **fetch 없음**.
- **2글자 입력**: `x-model="q"` 로 Own 이름 `indexOf`. **네트워크 없음**.
- **타 부서**: `toggleOther()` → `GET /workboard/projects/picker-other?q=...`

조직관리자 브라우저 (`/workboard/board` → +업무등록 → 행정/지원 → 지원업무):

| 확인 | 결과 |
|------|------|
| `typeof projectPicker` | `function` (보드 `base.html` 스크립트) |
| Alpine `$data(피커).items.length` | 14, 초기화됨 |
| 클릭 후 `open` | true, `filtered` 14. 콘솔 `onerror` 없음 |
| 「도서관」 2글자+ | `filtered` 9건 (부여공공도서관, 꿀벌도서관, …). **추가 요청 없음** |
| 목록 위치 | `ul` `position:absolute`, 높이 240. `getBoundingClientRect().top≈828` 인데 입력칸은 모달 안 `top≈786`. **모달 밖 페이지 하단에 목록이 그려짐** (스크린샷: 모달 아래 「— 선택 (해당 시) —」와 사업명) |
| `ulInView` | false |

`.pp` 에 relative 없음. `.combobox` 클래스도 안 씀. `input.css` 의 `.combobox { relative }` 는 이 피커에 적용되지 않음.

## 5. 수정안 후보 (아직 적용하지 않음)

1. **원인 수정 (권장)** `_partials/project_picker.html` 루트에 `relative`(또는 `combobox` 클래스)를 넣어 absolute 목록이 입력칸 기준이 되게. 영향: `project_picker` 를 쓰는 모든 화면(새 업무·일정표 모달·task_show·점검 등). 모달 `overflow-hidden` 과 맞물리면 여전히 잘릴 수 있어, 목록을 absolute 대신 흐름(static)으로 두거나 위쪽으로 flip 하는 편이 안전.
2. 검색 UX: `q` 입력 시 Own + (권한 있으면) `picker-other?q=` 를 같이 보여 주기. 영향: 95-113 「타 부서는 접기」 설계. 일반(tech)은 타 부서 검색을 열면 안 됨.
3. 운영 DB에서 Own=0·Other=37이면 그건 주관/유관 데이터 문제. 목록이 모달 안에만 나와도 「등록된 사업이 없습니다」+타 부서 37건이 됨. 데이터 보정은 별건.
