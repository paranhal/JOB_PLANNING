작성: 2026-11-13. 푸시·배포·운영 DB 접근 없음. `VERSION`은 올리지 않았다.
참고: 지시서 파일 「커서_작업지시서_95-186_…」은 `Claude outputs`에서 찾지 못해, 붙여넣은 지시문과 인수인계 문서 §2 기준으로 진행했다. 지시서와 다른 점이 있으면 알려 주세요.

## 0. 확인 결과 (변경 전)
- 단계 추가 폼은 `_phases.html`의 `{{if .CanEditPhase}}`(권한 있을 때만) 안, 구조 복사·템플릿 박스 아래, 화면 맨 아래쪽에 있었다.
- `PhaseCreate`는 서버에서도 `canEditProjectPhase`를 확인(403)하고, 오류를 `?err=`에 `err.Error()` 그대로(인코딩 없이) 붙여 돌려줬다.

## 1. 변경
- **박스 이동**: 「수행 구조」 제목·변경내역 줄 아래, 성공·오류 문구 바로 아래에 「1단계 사업 만들기」 박스(`data-phase-create`)를 둔다. 기존 맨 아래 폼은 삭제했다(단계명 입력은 화면에 1개).
  - 권한 조건은 그대로 `.CanEditPhase`. 단계명(100자)·예정 시작·예정 종료 입력은 같고, 버튼은 `btn-primary`로 바꿨다. 항상 펼쳐 있다.
  - 단계가 하나도 없을 때도 같은 박스가 맨 위에 나온다.
- **오류 처리**: `PhaseCreate`의 `?err=`를 `url.QueryEscape`로 인코딩했다. 오류 문구는 박스 위에 나온다. 입력값은 돌려주지 않는다(기본안).
- **성공 문구**: `ok=phase`일 때 「단계를 저장했습니다.」를 수행 구조 위에 표시한다(기존에는 문구가 없었다. 단계 수정 성공에도 같은 문구가 쓰인다).
- 스키마·DB·지표 변경 없음.
