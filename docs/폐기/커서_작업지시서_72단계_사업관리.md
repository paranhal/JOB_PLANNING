# Cursor 작업 지시서 — 72단계: 사업관리 시스템 (실데이터 전환)

기준 문서: `claude/project-management-spec.md`(설계서 v0.1), `claude/decisions-log.md`(D-51~D-58), 71단계 결재 엔진.
저장소: JOB_PLANNING. 마이그레이션 번호는 착수 시점 최신(현재 059)에 이어 붙인다(설계서의 060~066은 예시 순서).

## 공통 규칙 (모든 하위 단계)
1. **단계마다 별도 커밋**. 새 실패 0건: `go test ./...` 결과가 단계 시작 전보다 나빠지면 안 된다(기존 실패 목록은 `docs/리뷰/` 기록과 비교).
2. 템플릿에 Tailwind 유틸리티를 추가하면 같은 커밋에서 `npm run build:css`로 `vendor/tailwind.css` 재생성(손편집 금지). `ui_lint` 래칫 위반 0.
3. 마이그레이션은 **멱등**, 운영 DB 적용 금지(스키마 생성만). 데이터 정리(백필·병합)는 **드라이런 리포트 → 사용자 승인 → 실행** 순서이며 이번 지시에서 운영 실행은 하지 않는다.
4. 폐쇄망: CDN·외부 호출 금지. 첨부는 로컬 저장.
5. 각 단계 끝에 **작업 보고**: 변경 파일, 마이그레이션 번호, 추가한 테스트 이름, `go test ./...` 전후 실패 수, 확인한 화면 URL.
6. 결재는 71 엔진 재사용(작성 → 승인, 검토 없음). 읽기 전용/view-as 계정은 쓰기·결재 불가 유지.
7. 의문점은 임의 결정하지 말고 보고서의 「질문」 항목에 적는다.

## 72-A. 정리 (선행 필수)
1. 미커밋 변경을 **주제별로 분리 커밋**: 사업관리 mock / mailer / role / leave / approval / analysis / tailwind. `deploy/server-app.tar` 등 배포 산출물은 커밋 제외(.gitignore 확인). 빈 폴더 `x` 삭제 여부는 사용자 확인.
2. `SHOW_PROJECTS_SECTOR` 동작 변경: 플래그는 **사이드바 메뉴 노출 여부만** 제어한다. `/projects` 가 mock(`sampleWorkMgmt`)로 실제 목록을 대체하지 않게 하고, 플래그가 켜져 있어도 `/projects`는 **실제 목록**을 렌더링한다. mock 화면(dashboard/docs/diary)은 72-I에서 교체되기 전까지 화면 상단에 「예시 데이터」 배지를 유지.
3. 운영 compose 값(`SHOW_PROJECTS_SECTOR=0`)은 변경하지 않는다.
4. 테스트: 플래그 on/off 각각에서 `/projects`가 실제 `work_projects` 행을 보여 주는지, 메뉴 노출만 달라지는지.

## 72-B. 사업 코어 (마이그레이션 060)
설계서 §9 060 구현. 추가 작업:
- 모델/리포지토리/서비스: `project_type`, `exec_status`, `pm_user_id`, `project_members`, `project_phases`, 단계 템플릿 시드(준비/수행/검수/종료, 유형 무관 공통).
- 사업 생성/수정 폼: 유형·상태·PM·구성원·계약일 입력. PM/구성원은 활성 사용자만(소프트 삭제 제외).
- 사업 상세 `/projects/:id`에 PM·구성원·단계 표시(단계 추가/삭제/순서/완료 처리).
- 유형/상태 코드는 상수 + 라벨 매핑(표시용), DB CHECK 없음.
- 테스트: 마이그레이션 2회 실행 무오류, 구성원 중복 방지, 단계 완료 처리 권한(PM·관리자), 삭제된 사용자 PM 지정 거부.

## 72-C. 영업 → 사업관리 이관 (마이그레이션 061)
설계서 §3. 구현:
- 서비스 `TransferSalesProject(ctx, salesProjectID, actor)`: 트랜잭션, 계약 완료 상태 검증, 이미 이관됨/`sales_project_id` 연결 존재 시 `linked_existing`, 스냅샷 JSON 저장, 멱등.
- 영업 상세에 「사업관리로 이관」 확인 화면(복사될 값 미리보기 → 확정). 이관 후 영업 사업은 읽기 전용 + 사업관리 링크, 금액 변경 차단.
- 관리자 「이관 취소」(사유 필수, 연결 데이터 있으면 차단, `data_change_logs`).
- 이관 직후 PM 미지정이면 관리자 업무 영역에 알림 표시.
- `uq_projects_sales` 생성 전 **중복 sales_project_id 점검 쿼리**를 실행해 결과를 보고(중복 있으면 인덱스를 만들지 말고 질문).
- 테스트: 정상 이관, 이중 이관(멱등), 미계약 상태 거부, 기존 연결 건 `linked_existing`, 이관 후 영업 금액 수정 차단, 권한(영업 본인/관리자만), 취소 규칙.

## 72-D. 하위 업무 연결 (마이그레이션 062)
설계서 §4. 구현:
- 조직별 시스템 사업 「내부업무(비사업)」 멱등 생성(`is_system=1`, 목록·통계에서 구분 표시, 삭제/병합 불가).
- 서비스 계층 검증: AS 접수·일일업무·주간보고·점검·자산 신규 입력은 `project_id` 필수. 자동 제안 규칙(고객의 활성 사업 1개면 선택, 여러 개면 선택 필수, 없으면 내부업무).
- **미분류 큐** 관리 화면: 자식 테이블별 `project_id IS NULL` 건수/목록, 다건 선택 후 사업 일괄 지정, 로그 기록.
- **자동 연결 드라이런 CLI/화면**: 「고객 + 활성 사업 정확히 1개」 건만 후보로 리포트(실행 버튼은 만들되 이번 단계에서 운영 실행 금지).
- 린트 테스트: 신규 입력 핸들러가 `project_id` 검증을 우회하지 않는지(핸들러 목록 기반).
- 테스트: 필수 검증, 자동 제안 3경우, 큐 일괄 지정, 병합 사업의 자식 이동 일관성, 권한.

## 72-E. 발주처 정리 (마이그레이션 063)
설계서 §5. 구현:
- `customers.name_normalized` 컬럼·정규화 함수(공백, (주)/㈜/주식회사, 대소문자) + 저장/수정 시 갱신, 기존 행 채우기는 별도 보정 명령.
- 사업 폼의 발주처를 **고객 선택(자동완성)만** 허용, 신규 등록 팝업. 텍스트 직접 입력 제거. `ordering_party_snapshot`은 저장 시 자동.
- **드라이런 리포트**: 정확 일치 / 유사 / 불일치 3분류, 조직별. 정확 일치 자동 채움은 실행 버튼만 제공(운영 실행 금지).
- 고객 병합 화면: 하위 참조(사업, AS, 자산, 영업 사업) 이동 + 이력.
- 테스트: 정규화 함수 표 기반 테스트(한글 법인표기 변형 10종 이상), 중복 경고, 병합 시 참조 이동 누락 없음.

## 72-F. 일일업무 = 일지 (마이그레이션 064)
설계서 §7 권고안 A.
- 일일업무 등록/수정 폼과 목록 행을 `[사업] [유형] [내용] [결과/메모] [투입]` 형태로 정리. 별도 일지 입력 화면 만들지 않음.
- `effort`(공수: 0.25 단위 선택) 입력은 선택. 같은 사용자·날짜 합계 1.0 초과 시 **경고만**.
- 조직 설정 `time_tracking`(off/optional/required, 기본 off). on이면 시작/종료 입력 가능, 공수는 시간에서 자동 계산(8시간=1.0). 설정 화면은 관리자.
- `project_day_notes`(사업·날짜별 일일 메모) CRUD.
- 사업 일지 뷰 `/projects/:id/diary`: `work_tasks`를 날짜·사업으로 집계 + 일 메모. 「한 줄 추가」는 사업이 고정된 일일업무 폼을 연다.
- D-49(미배정 AS 표출) 동작이 바뀌지 않는지 회귀 테스트.
- 테스트: 투입 합계 경고, time_tracking 모드별 필드 노출/검증, 공수 자동 계산 경계값(0분, 480분, 자정 넘김 거부), 집계 정확성, 권한.

## 72-G. 서류 (마이그레이션 065)
설계서 §6.
- 수작업형(`mode=adhoc`) **먼저** 완성: 사업 상세 「서류」 탭에서 제목·종류·본문(여러 줄)·첨부 업로드, 상태(작성중/결재중/승인/반려/보관).
- 템플릿형: `project_doc_templates` CRUD 관리 화면(이름·종류·적용 유형·`schema_json` 단순 필드 목록: 텍스트/숫자/날짜/선택/여러 줄). 템플릿 선택 시 폼 자동 생성, 제출 시 템플릿 버전 고정. **시드 템플릿 없음**(현업 자료 후 등록).
- 결재: 71 엔진에 `project_doc` 유형 등록, 작성 → 승인(팀장), 서류별 「결재 불필요」 허용, 제출 시 `content_json` 스냅샷 보존, 반려 후 수정은 revision 증가.
- 첨부: 로컬 저장, 크기 한도·확장자 화이트리스트(설정값), sha256 기록.
- 테스트: 수작업형 전체 흐름, 템플릿형 생성·버전 고정, 결재 연동(승인/반려/자기 결재), 첨부 한도/확장자, 읽기 전용 계정 거부.

## 72-H. 진행률 확장점 (마이그레이션 066)
설계서 §8.
- `ProgressCalculator` 인터페이스·레지스트리, 구현체 `manual`, `phase_ratio`(weight 있으면 가중, 없으면 단순 비율).

- 테스트: 계산기 표 기반 테스트(단계 0개, 전부 완료, 가중치 합 0 처리), 방식 변경 시 스냅샷, 미등록 방식 폴백.
