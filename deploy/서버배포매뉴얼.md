# 고객지원시스템(업무일지) — 우분투 서버 배포 매뉴얼

작성 기준: 개발 PC Docker 배포본(`deploy/`) → 우분투 서버, 호스트 포트 **8888**  
앱 구성: **별도 웹서버/WAS 없음** — Go(Echo) 앱이 Docker 컨테이너에서 HTTP 직접 제공

---

## 1. 준비물

### 개발 PC
- 경로: `C:\Users\테크센터\PROJECT\JOB_PLANNING\deploy`
- 필수 파일:
  - `server-app.tar` — Docker 이미지
  - `docker-compose.yml` — 실행 설정 (기본 `8888:8080`)
  - `data/app.db` — SQLite DB (운영 데이터)
  - `data/uploads/` — 첨부 파일(있을 경우)
  - `start.sh` / `stop.sh` — Linux 시작·중지

### 우분투 서버
- Docker Engine + Compose plugin 설치
- SSH 접속 가능 (보통 포트 22)
- 공인 IP 1개, 앱 포트 **8888** 방화벽/공유기 개방
- 배포 권장 경로: `/home/sys2/deploy`

> **버전:** 개발 PC Docker Desktop과 서버 Docker CE 버전을 동일하게 맞출 필요 없음. 공식 저장소 최신 안정판이면 충분.

## 2. 서버에 Docker 설치 (최초 1회, root)

현재 디렉터리와 무관하게 실행 가능합니다.

```bash
apt-get update
apt-get install -y ca-certificates curl gnupg

install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg

. /etc/os-release
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu ${VERSION_CODENAME} stable" > /etc/apt/sources.list.d/docker.list

apt-get update
apt-get install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

systemctl enable --now docker
docker version
docker compose version
```

## 3. 파일 전송 (WinSCP / SFTP)

| 항목 | 값 |
|------|-----|
| 프로토콜 | SFTP |
| 호스트 | 서버 공인 IP |
| 포트 | 22 (앱 8888과 별개) |
| 방향 | **양방향** (업로드·다운로드 가능) |

1. WinSCP 접속
2. **왼쪽** = PC, **오른쪽** = 서버 (혼동 주의)
3. 왼쪽: `C:\Users\테크센터\PROJECT\JOB_PLANNING\deploy`
4. 오른쪽: `/home/sys2/`
5. `deploy` 폴더 전체를 오른쪽으로 드래그 업로드

업로드 후 서버에 있어야 할 구조:

```text
/home/sys2/deploy/
  server-app.tar
  docker-compose.yml
  start.sh
  stop.sh
  data/
    app.db
    uploads/   (선택)
```

### 포트 확인 (`docker-compose.yml`)

```yaml
ports:
  - "8888:8080"
```

- `8888` = 서버(호스트)에서 여는 포트  
- `8080` = 컨테이너 안 앱 포트 (변경하지 않음)

## 4. 서버에서 기동 (SSH)

일반 사용자로 올린 뒤 `su -`로 root가 되었다면, 홈이 `/root`로 바뀌므로 **deploy 절대 경로**로 이동합니다.

```bash
cd /home/sys2/deploy
pwd
ls -la
```

Windows에서 올린 스크립트는 줄바꿈(CRLF) 때문에 실행이 실패할 수 있습니다.

```bash
sed -i 's/\r$//' start.sh stop.sh
chmod +x start.sh stop.sh
./start.sh
```

`./start.sh`가 하는 일:
1. `docker load -i server-app.tar` (이미지 로드)
2. `data/` 확인
3. `docker compose down` 후 `docker compose up -d` (최신 이미지로 기동)

접속:

```text
http://공인IP:8888
```

로그인: 기존 DB를 올렸다면 **기존 계정**, 초기 DB면 `admin` / `admin` (변경 권장)

**배포 후 확인:**

```bash
curl -s http://lib.visionit.co.kr/version
```

`built`가 방금 빌드한 시각인지, `started`가 방금인지 본다. **둘 다 맞아야 배포가 끝난 것이다.** `built`만 새것이고 `started`가 옛날이면 이미지는 올라갔는데 컨테이너를 안 바꾼 것이다.

### 수동 기동 (스크립트 대신)

```bash
cd /home/sys2/deploy
docker load -i server-app.tar
docker compose up -d
docker compose ps
```

## 5. 중지 / 재시작

### 권장 중지 (`deploy` 폴더에서)

```bash
cd /home/sys2/deploy
./stop.sh
```

또는:

```bash
cd /home/sys2/deploy
docker compose stop          # 컨테이너만 중지 (이미지·데이터 유지)
# 또는
docker compose down          # 컨테이너 제거 (data/ 볼륨·폴더는 유지)
```

### 다시 시작

```bash
cd /home/sys2/deploy
docker compose start         # stop 했을 때
# 또는
docker compose up -d         # down 했거나 최초 기동
# 또는
./start.sh                   # 이미지 재로드까지 포함
```

### 컨테이너만 stop 한 경우

```bash
docker start server-app-1
# 또는
cd /home/sys2/deploy && docker compose start
```

> **주의:** `docker stop` / `compose stop`은 앱만 멈춥니다. `data/app.db`는 삭제되지 않습니다.

## 7. 개발 PC에서 deploy 다시 만들기

서버에 올린 내용이 오래되었거나 `deploy`를 지웠을 때 (개발 PC PowerShell/터미널):

```powershell
cd C:\Users\테크센터\PROJECT\JOB_PLANNING
docker compose -f server/docker-compose.yml stop
python -c "import sqlite3; c=sqlite3.connect(r'server/data/app.db'); c.execute('PRAGMA wal_checkpoint(TRUNCATE)'); c.close()"
.\deploy\build.ps1
# data 복사
New-Item -ItemType Directory -Force -Path deploy\data | Out-Null
Copy-Item server\data\app.db deploy\data\app.db -Force
if (Test-Path server\data\uploads) { Copy-Item server\data\uploads deploy\data\uploads -Recurse -Force }
docker compose -f server/docker-compose.yml start
```

이후 WinSCP로 `deploy` 전체를 서버에 **덮어쓰기** 업로드 → 서버에서 `./start.sh`.

> 운영 DB가 이미 서버에 있으면 `deploy/data`는 **올리지 마세요.** 아래 7-1을 쓰면 됩니다.

### 7-1. 앱만 교체 (운영 데이터 그대로)

개발 PC — 이미지만 새로 만듭니다.

```powershell
cd C:\Users\테크센터\PROJECT\JOB_PLANNING
.\deploy\build.ps1
```

WinSCP로 **`data/`는 올리지 말고** 아래만 `~/deploy`에 덮어씁니다.

- `server-app.tar` (필수)
- `docker-compose.yml` (`stop_grace_period: 30s` — 없으면 이것도)
- `update.sh` (없으면 이것도)

서버에서:

```bash
cd ~/deploy
touch .env
sed -i 's/\r$//' update.sh
chmod +x update.sh
./update.sh
curl -s localhost:8888/version
```

`.env`가 없으면 compose가 기동을 거부한다. 공휴일 API·연동 키가 필요하면 그 파일에만 넣고, 소스·compose에는 적지 않는다. `data/`는 올리지 않는다.

`version`이 **44-G**이고 `built`가 방금, `started`가 방금이어야 끝난 것입니다.

- `data/app.db`는 볼륨으로 붙어 있어 이미지 교체와 무관합니다.
- 표(컬럼) 추가 같은 스키마 변경은 앱이 **기동할 때 자동 반영**합니다.
- 컨테이너를 내리지 않고 이미지를 바꿀 수는 없습니다. 교체 중 1~2분 접속이 끊깁니다.

### 7-2. 서버(운영) 데이터로 개발·확인하기

SQLite는 파일 DB라 개발 PC에서 서버 DB에 **직접 접속할 수 없습니다.** 사본을 내려받아 씁니다.

서버 — 쓰기를 멈추고 사본을 만듭니다(WAL 잔여분까지 안전하게).

```bash
cd ~/deploy
docker compose stop app
tar czf ~/app-db-$(date +%F).tar.gz data/app.db data/uploads
docker compose start app
```

WinSCP로 `~/app-db-날짜.tar.gz`를 내려받아 푼 뒤, 개발 PC에서:

```powershell
cd C:\Users\테크센터\PROJECT\JOB_PLANNING\server
docker compose stop
Copy-Item data\app.db "data\app.db.bak-$(Get-Date -Format yyyyMMdd-HHmmss)" -Force
Remove-Item data\app.db-wal, data\app.db-shm -ErrorAction SilentlyContinue
# 내려받은 app.db 를 data\app.db 로 덮어쓰기
docker compose start
```

주의사항:

- 운영 DB에는 고객 정보가 들어 있습니다. 사내 PC에서만 쓰고 확인이 끝나면 지우세요.
- 개발 PC에서 고친 내용은 **서버에 반영되지 않습니다.** 반대로 올리려면 운영 DB를 덮어써야 하므로, 그동안 서버에서 입력된 자료가 사라집니다. 되도록 하지 마세요.
- 네트워크 드라이브로 서버의 `app.db`를 직접 물리면 파일 잠금이 깨져 DB가 손상됩니다. 금지.
- 여러 PC가 같은 자료를 실시간으로 보려면 PostgreSQL 전환이 필요합니다(`docker-compose.yml`에 준비된 주석 참고).

## 8. 문제 해결

### `./start.sh: cannot execute: required file not found`
Windows 줄바꿈(CRLF) 문제.

```bash
sed -i 's/\r$//' start.sh stop.sh
bash start.sh
```

### `getwd: no such file or directory`
현재 셸이 **이미 삭제된 폴더**에 남아 있음.

```bash
cd /home/sys2
ls -la
# deploy 다시 업로드 후
cd /home/sys2/deploy
```

### WinSCP에는 보이는데 터미널 `ls`에 안 보임
- WinSCP **왼쪽 = PC**, **오른쪽 = 서버**
- 오른쪽 경로가 `/home/sys2/deploy` 인지 확인
- 터미널:

```bash
cd /home/sys2
ls -la
ls -la /home/sys2/deploy
```

### 포트 충돌
```bash
ss -lntp | grep 8888
```

### Docker 연결 안 됨
```bash
systemctl start docker
docker info
```
